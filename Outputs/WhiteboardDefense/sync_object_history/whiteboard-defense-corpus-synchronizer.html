sync-object-history.sh — v3 Corpus Synchronizer

bash · rsync · ssh read-only pull no-git internal tooling  |  Source: sync-object-history.sh

1 · High-Level Architecture & Mental Model

One-liner: A thin Bash wrapper that drives two sequential rsync -avz pulls over SSH — one for the v3 corpus tree, one (optional) for intent markdown artefacts — then prints a summary from INDEX.txt.

┌─ Operator CLI ──────────────────────────────────────────────────┐ │ bash sync-object-history.sh [--host H] [--user U] │ │ [--remote P] [--local P] │ │ [--intent] [--dry-run] │ └──────────────────────────┬──────────────────────────────────────┘ │ argument parse (shift/case loop) ▼ ┌─ Phase 1 — Corpus Sync ─────────────────────────────────────────┐ │ rsync -avz --compress-level=9 -e ssh --progress │ │ szuraski@sockeni07:"/home/szuraski/BobOutput/Object History/v3/" │ → ./Object-History-v3/ │ │ │ │ Transferred tree: │ │ INDEX.txt │ │ <ClassName>/commits.txt │ │ <ClassName>/blame.txt │ │ <ClassName>/functions.txt │ │ <ClassName>/diffs/<sha>.diff │ └──────────────────────────┬──────────────────────────────────────┘ │ if --intent ▼ ┌─ Phase 2 — Intent Sync (optional) ──────────────────────────────┐ │ rsync -avz --compress-level=9 -e ssh --progress │ │ --include="*-intent.md" --exclude="*" │ │ szuraski@sockeni07:"/home/szuraski/BobOutput/Object History/"│ │ → ./Object-History-intent/ │ │ │ │ Glob: any *-intent.md at the root of Object History/ │ └──────────────────────────┬──────────────────────────────────────┘ │ ▼ ┌─ Summary ───────────────────────────────────────────────────────┐ │ cat INDEX.txt (or warn if absent) │ │ count of *-intent.md synced (if --intent) │ └─────────────────────────────────────────────────────────────────┘

Key Invariants

  • Script is pull-only — it never writes to the remote.
  • set -euo pipefail aborts on any unhandled error, unset variable, or broken pipe.
  • mkdir -p ensures local destinations exist before rsync runs.
  • The --dry-run flag is propagated verbatim to both rsync invocations via RSYNC_EXTRA.
  • Intent destination is hardcoded to ./Object-History-intent (not overridable via CLI).
  • Intent source root is hardcoded to /home/szuraski/BobOutput/Object History regardless of --remote.

2 · Architectural Decisions & Trade-offs

DecisionAlternative ConsideredReason Chosen
rsync over SSH, not git git clone / git pull Corpus is produced by a BobOutput pipeline, not a git repo. rsync transfers arbitrary directory trees without requiring a versioned repository on the remote.
-avz --compress-level=9 -a alone or lower compression -a = archive (preserves perms/times/symlinks/owner/group). -z + level 9 = maximum zlib compression in-transit — suited for text-heavy diff corpora. Delta-transfer algorithm skips unchanged files/blocks.
Separate --intent flag / sync phase Bundle intent files into corpus root Intent artefacts live one directory level above v3/ in the remote tree. Separating them keeps corpus and intent directories independent locally; operators can pull one without the other.
--include="*-intent.md" --exclude="*" Sync full Object History/ directory The parent directory contains the v3/ subdirectory and possibly other data. Glob filtering limits the pull to exactly the *-intent.md artefacts — no over-fetching.
Hardcoded intent destination (./Object-History-intent) A --intent-local CLI flag Simplicity — intent is a secondary, optional artefact. The two output dirs have symmetric, memorable names: Object-History-v3/ and Object-History-intent/.
SSH transport (-e ssh) rsync daemon (port 873), NFS mount No special daemon config needed on remote. Leverages existing SSH key infrastructure. Encrypted channel for corpus data.
RSYNC_EXTRA array with parameter expansion guard String concatenation or global var "${RSYNC_EXTRA[@]+"${RSYNC_EXTRA[@]}"}" correctly handles an empty array under set -u without triggering "unbound variable" — a precise Bash idiom.
set -euo pipefail No error handling / manual || chains Fail-fast: any rsync failure, SSH failure, or mkdir failure aborts the script immediately with a non-zero exit. No silent partial syncs.
No post-sync validation beyond INDEX.txt cat Checksum verification, file count diff Script's purpose is pull-and-inspect, not production data integrity. INDEX.txt serves as a human-readable manifest printed at the end.

3 · Data Structures, Algorithms & Invariants

Remote Corpus Layout

/home/szuraski/BobOutput/Object History/
├── v3/                          ← REMOTE_CORPUS (Phase 1 source)
│   ├── INDEX.txt                ← manifest of all classes
│   └── <ClassName>/
│       ├── commits.txt          ← git log output per class
│       ├── blame.txt            ← git blame output
│       ├── functions.txt        ← extracted function signatures
│       └── diffs/
│           └── <sha>.diff      ← per-commit unified diff
└── <ClassName>-intent.md       ← Phase 2 source (flat, root-level)

Local Output Layout

./Object-History-v3/             ← mirrors remote v3/ tree exactly
./Object-History-intent/         ← flat dir, only *-intent.md files

rsync Delta-Transfer Algorithm

How rsync decides what to transfer
  • Default comparison: file size + modification timestamp. Files that match both are skipped.
  • -z applies zlib compression to the byte stream in transit (not stored compressed locally).
  • --compress-level=9: maximum deflate effort — higher CPU on both ends, lower bytes-on-wire. Appropriate for text corpora with high redundancy (diffs, blame output).
  • Block-level delta: rsync uses its rolling-checksum / MD4 block-hash algorithm to transfer only changed blocks within a file when the file already exists locally and differs.
  • --progress: streams per-file transfer progress to stdout — useful for large diff trees but noisy in CI.
  • -a (archive mode) = -rlptgoD: recursive, preserve symlinks, permissions, timestamps, group, owner, devices.

Invariant: Unknown flags hit the *) catch in the case block → echo ... >&2; exit 1. No silent flag ignoring.

Critical Bash Idiom

"${RSYNC_EXTRA[@]+"${RSYNC_EXTRA[@]}"}"

Under set -u, expanding an empty array ${RSYNC_EXTRA[@]} would be an unbound variable error. The +word form only expands if the variable is set and non-empty, correctly passing no extra args when the array is empty.

Quick Smoke Test

# 1. Dry-run first — see what WOULD transfer
bash sync-object-history.sh --dry-run

# 2. Live pull
bash sync-object-history.sh

# 3. Verify corpus structure
ls Object-History-v3/
cat Object-History-v3/INDEX.txt

# 4. With intent artefacts
bash sync-object-history.sh --intent
ls Object-History-intent/

# 5. Alternate host/user (e.g., testing on staging)
bash sync-object-history.sh --host stagingbox --user devuser --dry-run
Pro tip: Run --dry-run first on a fresh machine to confirm SSH connectivity and enumerate what will be transferred before committing to a potentially large pull.
Watch for: rsync --compress-level=9 is CPU-intensive on both ends. On a slow remote or loaded host, this may throttle transfer speed more than network bandwidth warrants. Consider dropping to --compress-level=6 if transfer rate stalls on CPU rather than bandwidth.
No lock file / no rollback: If the script is killed mid-transfer (Ctrl-C, SIGTERM), the local directory is left in a partially-synced state. A re-run will recover via rsync's delta logic, but verify INDEX.txt is complete after any interrupted run.

7 · Design Constraints & Known Limitations

ConstraintImpact
Intent local destination not overridable via CLI Always writes to ./Object-History-intent; workaround: run from desired parent dir or patch script
Intent source root is hardcoded, not derived from --remote Passing a custom --remote does not shift the intent source path; the two are independent
No parallelism between Phase 1 and Phase 2 Intent sync runs only after full corpus sync completes; total time = Phase1 + Phase2
RSYNC_EXTRA only supports --dry-run Other rsync flags (e.g., --checksum, --delete) cannot be injected via CLI; script must be patched
No --delete flag on rsync Files removed from remote are NOT removed locally. Local corpus can accumulate stale artefacts across runs.
SSH key setup is an implicit external dependency No documentation or check in-script for SSH key availability; auth failures manifest as rsync error 255
