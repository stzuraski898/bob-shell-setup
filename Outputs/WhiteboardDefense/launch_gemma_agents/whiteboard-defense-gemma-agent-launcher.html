1 · High-Level Architecture & Mental Model

System Overview

Three execution modes, one core agent (generate_tests.py), one decision: local RAM is scarce → offload to a 503 GB RAM server.

Execution Modes Side-by-Side

ModeScriptConcurrencyModelTarget ResolutionOutput Location
Local Interactive launch-gemma-agents.sh 1–N Tilix tabs (capped by --agents) gemma4:latest (12b, ~9.6 GB) Flat text file: Inputs/gemma-instructions Caller-defined per-entry
Remote Serial launch-gemma-remote.sh Serial (1 at a time on remote) gemma4:27b or gemma4:31b (~17-20 GB) Hardcoded assoc-array: 5 Ceph mgr classes LOCAL_CEPH/src/test/mgr/ (rsync pull)
Local Serial Fallback run-remaining.sh Serial (no concurrency) Default Ollama model Hardcoded: ServiceMap, MgrClient, DaemonServer ~/Projects/ceph/src/test/mgr/

Core Agent Loop (generate_tests.py)

[1] Read source (.cc file)         → raw string
[2] Load system prompt             → file OR built-in default
[3] POST /api/chat (ollama SDK)    → Gemma generates initial gtest file
[4] extract_code_block()           → strip ```cpp fence (3 fallback cases)
[5] Write output file              → os.makedirs + open("w")
[6] if --no-feedback → exit 0
[7] loop up to --max-iterations:
      run_pytest(output_path)      → subprocess pytest -v --tb=short
      if pass  → exit 0
      truncate output to 8000 chars
      fix_tests(source, test, build_output) → Gemma rewrites test
      write updated file
[8] Exhausted → exit 1, last attempt left on disk

Feedback Loop Prompt Construction

Each fix iteration sends a 3-part user message with no conversation history threading — each call is a fresh stateless client.chat():

  • System role: Hard-coded C++ test engineer persona for fix calls; custom .md file (or default) for initial generation.
  • User role: source_code + test_code + build_output (truncated at 8,000 chars).
  • No multi-turn history — each request is independent. Context accumulation happens via prompt construction, not conversation state.

2 · Architectural Decisions & Trade-offs

DecisionWhat was chosenWhy / trade-off
Default concurrency = 1 MAX_AGENTS=1 hardcoded in launcher; requires explicit --agents N Gemma4:latest is ~9.6 GB; the laptop has ~16 GB free. Two instances compete for RAM → swap → both slow down. Fail-safe default avoids accidental OOM. User must consciously opt in.
Tilix for local parallelism One tilix --action=app-new-window + N app-new-session calls Visual parallelism: each tab is independently observable and survives shell exit. No need for a process manager; Tilix is already the dev terminal. Trade-off: requires Tilix installed, not portable to non-GTK environments.
Remote server offload for larger model sockeni07 (503 GB RAM) runs gemma4:27b/31b The 27b/31b model won't fit in laptop RAM at all. sockeni07 is an idle server with no GPU required — pure CPU inference. The larger model produces noticeably better C++ test output at the cost of serial execution and SSH round-trip latency.
Serial execution on remote Targets run one at a time via a sequential for loop CPU inference saturates cores on a single model invocation. Parallel remote runs would compete for the same CPU pool with no VRAM to distribute across. Serial is faster wall-clock than two thrashing simultaneous runs.
rsync over scp for file sync rsync -az --info=progress2 Incremental delta sync — re-running the script after a partial failure only transfers changed bytes. Idempotent by nature. Progress reporting keeps the operator informed during large source-tree uploads.
Ollama 127.0.0.1:11434 only Local loopback; no firewall rules, no port forwarding Security: Ollama has no auth. Binding to loopback means only local processes (or SSH-tunneled sessions) can reach it. The remote launcher issues commands via ssh … bash -s — the remote Ollama never needs to be network-accessible.
Stateless per-call LLM requests Each client.chat() call is independent; no session/thread ID Simplicity — no state management, no conversation expiry. Each fix iteration reconstructs the full context from scratch. Downside: the model cannot learn from prior iterations' reasoning; each fix is "cold".
Prompt file override (--prompt-file) Caller-supplied .md/.txt replaces built-in system prompt Allows per-class contract annotations (e.g., DaemonKey.md) to be injected as context for the model without modifying generate_tests.py. The prompt directory defaults to Inputs/prompts/ and is resolved by basename-without-extension matching.
set -euo pipefail in all scripts Strict error propagation in every launcher Any unexpected non-zero exit (bad rsync, SSH failure, missing file) halts the entire script immediately. Prevents silent partial-state failures where some targets ran and others silently didn't.
Feedback loop uses pytest (Python only) run_pytest() uses subprocess pytest The generator was originally designed for Python source. For C++ gtest output, pytest does not compile the file — so the feedback loop is a no-op for C++ targets unless the user manually pipes build errors back. Acknowledged in code comments; --no-feedback is the default in run-remaining.sh.
num_ctx=32768, num_predict=16384 Fixed token limits in generate_tests.py 32k context fits comfortably in 30 GB RAM on local hardware. 16k predict is enough for even large gtest files. Going higher risks OOM; going lower risks truncated code. Not configurable via CLI — tuned for the hardware profile.
Parallel arrays vs. assoc arrays for target mapping Local launcher: parallel source_file[]/output_file[] arrays parsed from file. Remote launcher: two declare -A assoc-arrays hardcoded. Local launcher reads a user-editable flat file — parallel arrays are the natural parse target for paired lines. Remote launcher has a fixed known set of 5 Ceph mgr targets — assoc-arrays keyed by class name are more readable and trivially extensible.

3 · Data Structures, Algorithms & Invariants

Key Data Structures

StructureLocationPurpose & Shape
source_file[] / output_file[] launch-gemma-agents.sh Parallel bash arrays, indexed 0…N-1. Populated by parsing the instructions file: blank-line delimited pairs, first non-blank line → source, second → output. Always same length by construction.
SOURCE_FILE[ClassName] / OUTPUT_FILE[ClassName] launch-gemma-remote.sh Bash associative arrays keyed by class name (e.g. DaemonKey). 5 entries. TARGETS[] is a plain array of keys to iterate — set to all 5 by default or filtered to one via --target.
SYNC_FILES[] launch-gemma-remote.sh Plain array accumulating all .cc + optional .h paths needed. Deduplicated via sort -u before rsyncing — prevents duplicate transfers when multiple targets share a header.
Chat message list generate_tests.py Python list of {"role": …, "content": …} dicts passed to ollama.chat(). Always exactly 2 entries (system + user). No persistent history between calls.
Pytest output string generate_tests.py Plain string, stdout+stderr concatenated. Hard-truncated at 8,000 chars before inclusion in the fix prompt to stay within num_ctx budget.

Algorithms

AlgorithmLocationDetail
Instructions file parser launch-gemma-agents.sh:99–109 Two-state FSM: src="" = waiting for source; src≠"" = waiting for output. Blank line resets to waiting. Processes last entry via || [[ -n "$line" ]] guard to handle files without a trailing newline.
extract_code_block() generate_tests.py:42–62 3-tier regex fallback: (1) properly closed ``` fence → capture group; (2) opening fence, no close (truncated response) → take everything after opening; (3) no fence → raw stripped text. Handles partial LLM responses gracefully.
Feedback loop generate_tests.py:250–285 Bounded retry with hard exit: iterate 1…max_iterations. On pass → exit 0. On last iteration → print warning, exit 1. On intermediate failure → call fix_tests(), overwrite file, continue. O(max_iterations) LLM calls worst case.
Prompt file resolution launch-gemma-agents.sh:130–142 basename(src) strip extension → try .md then .txt in PROMPT_DIR. First hit wins. No-op if neither exists — falls back to built-in system prompt.
Ollama readiness probe setup-gemma-remote.sh:89–96 Polling loop: up to 30 iterations × 1s sleep. Calls curl -sf http://127.0.0.1:11434/api/tags. Exits 1 with log pointer if not ready in 30s.

Invariants

  • INV-1: source_file[] and output_file[] are always the same length — the parser only appends to both in the same branch.
  • INV-2: AGENT_COUNT ≤ MAX_AGENTS — the local launcher hard-caps the number of spawned tabs before entering the loop.
  • INV-3: The output file always exists on disk after generate_tests() returns — write_tests() is called before any feedback loop iteration.
  • INV-4: Remote Ollama is probed alive before each target SSH invocation (inline check + auto-restart inside the remote heredoc).
  • INV-5: LLM context budget is bounded: num_ctx=32768, pytest output truncated at 8,000 chars — the fix prompt cannot overflow context by construction.
  • INV-6: All launchers use set -euo pipefail — partial execution (some targets ran, some didn't) is not a valid terminal state; the script aborts.

4 · Threat Model & Adversarial Handling

Scope: This is a local developer tooling system with no public network surface. Threat model focuses on misuse, credential leakage, malicious model output, and accidental data destruction.
User passes --agents 3 on a 16 GB laptop with Gemma4:latest (9.6 GB)
ThreatAttack VectorActual ExposureMitigation / Gap
Malicious model output written to codebase Gemma generates test file with injected shell commands, destructive #includes, or data exfiltration via build system macros MEDIUM Output is written directly to src/test/mgr/ with no content inspection Generated files are .cc files requiring explicit compilation — no auto-execution. Developer reviews before merging. No mitigation in script. Gap: no diff/review step before write.
Ollama running with no auth on loopback Any local process or SSH-forwarded connection can send arbitrary prompts to the Ollama API MEDIUM Ollama binds to 127.0.0.1 only — external network cannot reach it Loopback binding is the only access control. Any local user on sockeni07 can use the API. Acceptable for an internal dev server; unacceptable in a shared prod environment.
Hardcoded SSH username/host REMOTE_HOST="szuraski@sockeni07" in scripts — wrong if hostname/user changes LOW Scripts accept --host override; no credential is hardcoded, only host alias SSH key auth assumed (no password in script). If ~/.ssh/config has the host defined, the alias works transparently. Not a security risk, but an operational brittleness.
Prompt injection via source file content A crafted comment in a .cc source file could attempt to override the system prompt or instruct the model to produce harmful output MEDIUM The entire source file is embedded verbatim in the user message No sanitization. Gemma 4 is not an agentic model with tool access — worst case is poor/malicious test code, which still requires compilation and human review before use.
Disk exhaustion from repeated test file overwrites Feedback loop runs 5 iterations × potentially large test files LOW Each iteration overwrites the same output file path — no accumulation File is overwritten in place. No temp files accumulate. Disk risk is bounded by one file per target.
OOM / swap thrashing from >1 concurrent agents HIGH Two instances alone may saturate all RAM Default cap is 1. Warning printed when AGENT_COUNT > MAX_AGENTS. No enforcement beyond the cap — user can set --agents 99 and the script will attempt to spawn 99 Tilix sessions.
Curl-pipe installer on remote curl -fsSL https://ollama.com/install.sh | sh executed on sockeni07 MEDIUM Downloads and executes an arbitrary shell script from the internet with sudo This is the official Ollama install method. Idempotency guard (command -v ollama) means it only runs once. Acceptable risk for a controlled internal server; would need review for stricter environments.
SSH heredoc variable injection Variables like ${MODEL}, ${REMOTE_WORK} are interpolated into heredoc commands sent over SSH MEDIUM If a model name or path contains shell metacharacters, they would execute on the remote Values come from the operator (CLI args or hardcoded defaults). User-controlled paths in --target are validated against the assoc-array keyset before use. Not a significant risk in practice given the controlled operator context.

5 · Failure Modes, Edge Cases & Blast Radius

FailureTriggerBlast RadiusRecovery
Ollama not running (local) curl -sf http://127.0.0.1:11434/api/tags fails at launch Script exits 1 immediately. No agents spawned. No side effects. ollama serve in another terminal; re-run launcher.
Ollama not running (remote, pre-flight) SSH probe fails before any sync Script exits 1. No files transferred or modified. ./setup-gemma-remote.sh to restart service.
Ollama dies mid-target (remote) Ollama crashes during SSH inference run Current target's SSH session fails → set -e aborts the launcher. Remaining targets do not run. Already-completed targets' output was already rsynced back. Check /tmp/ollama-serve.log on remote. Re-run with --target <ClassName> for the failed target. Inline auto-restart in heredoc adds resilience (nohup restart + 5s sleep).
Model not pulled on remote ollama list | grep -c returns 0 for model name prefix Script exits 1 before any sync. No files changed. Run ./setup-gemma-remote.sh --model <MODEL>.
Instructions file missing / empty File not found or no valid pairs parsed Script exits 1 with clear error. Nothing spawned. Create/fix the instructions file and re-run.
Source file not found (Python agent) os.path.isfile(args.source) returns False That agent's process exits 1. Other Tilix tabs unaffected (independent processes). Fix the source path in the instructions file.
Truncated LLM response (no closing fence) Model hits num_predict limit mid-generation extract_code_block() catches Case 2 — returns everything after the opening fence. Output file is written but may be syntactically incomplete C++. Increase _NUM_PREDICT in generate_tests.py or simplify the prompt. Feedback loop will attempt to fix on next iteration.
Feedback loop exhausted (max iterations) pytest still failing after N attempts Script exits 1. Last generated test file is left on disk (not rolled back). Prior correct file (if any) is overwritten. Manually inspect the last output file and pytest errors. Use --no-feedback and edit manually or increase --max-iterations.
rsync pull fails after remote generation succeeds Network drop between remote run and rsync … back step Local file is not updated. Remote output file exists on sockeni07. set -e aborts; remaining targets do not run. Re-run with --target <ClassName> for the affected target — rsync is idempotent, remote file still exists.
Tilix not installed tilix command not found on PATH set -e exits immediately after the first tilix call. No agents run. Install Tilix, or use run-remaining.sh / launch-gemma-remote.sh which don't require it.
OOM during local inference RAM pressure when running ≥2 agents on 16 GB laptop OS kills Ollama or Python process. Affected tab exits non-zero. Other tabs may also be impacted by swap pressure. Reduce --agents to 1. Check ollama ps for live memory usage.
Ceph source file has no matching .h header [[ -f "${base}.h" ]] check is false in remote sync step Only the .cc file is synced. The model will not have the interface declaration in scope. Generated tests may be lower quality but the run proceeds normally. Expected for some Ceph mgr classes. Not a failure — the guard is intentionally soft (&& not checked by set -e).

Blast Radius Summary

Contained failures: Each generate_tests.py process is independent — a Tilix tab crash does not affect other tabs. The remote launcher runs targets serially, so a mid-run failure leaves already-completed targets' output intact on disk.
Unguarded: If the feedback loop exhausts its iterations, the last (potentially broken) test file overwrites any previously correct version. There is no backup/rollback mechanism.
