1 · High-Level Architecture & Mental Model

One Python script. One input. One output. The entire explorer — data, UI, logic — ships as a single file.

Build-time (Python) dataset.json ─────────────► json.load() ──► json.dumps() ──► str.replace("%%DATA_JSON%%", json_str) │ ▼ HTML_TEMPLATE (raw string literal, ~1340 lines, inlined in source) │ ▼ Outputs/ceph-mgr-intents-assessment.html (single file, full JS + CSS + DATA embedded) Run-time (Browser) Browser loads .html │ ├─► CSS vars parsed → dark-theme layout applied ├─► DATA (const) = JSON.parse(inlined blob) ← already parsed by JS engine ├─► DOMContentLoaded fires │ ├─ renderSidebar() → sidebar list from DATA[] │ ├─ renderHomeStats() → header badge counts (reduce over DATA[]) │ ├─ renderHomeView() → metrics grid + objects table │ └─ handleRoute() → reads window.location.hash for deep-link │ ├─► User navigates → navToObject() / navToFunction() │ └─ innerHTML replaced on 3 static div slots: #view-home, #view-object, #view-function │ ├─► Filter/Search → DOM display:none toggling (no re-fetch, no re-parse) │ └─► Split pane drag → mousemove % calc → leftPane.style.width splitRatio persisted to localStorage

2 · Architectural Decisions & Trade-offs

DecisionWhat was chosenWhy not the alternative
Data transport JSON blob inlined via str.replace("%%DATA_JSON%%", ...) No server, no fetch(), no CORS. The file is fully self-contained and opens from the filesystem (file://). A separate .json fetch would require a web server even for local use.
Template mechanism Single sentinel token %%DATA_JSON%% replaced with str.replace() No Jinja2, no Mako, no templating library. Zero dependencies on the build side — only stdlib (os, glob, re, json). A templating engine would add installation overhead for a one-token substitution.
Client-side rendering DOM innerHTML rebuilt from JS functions per navigation event No React/Vue/Svelte. No virtual DOM. The dataset is read-only at runtime; full re-renders on each nav are cheap and keep the code straightforward. Framework weight would dwarf the actual payload value.
Routing URL hash routing (window.location.hash) with hashchange listener Hash routing works on file:// URLs. history.pushState requires an HTTP origin and would break local file browsing.
Filtering DOM display:none toggling on rendered cards/rows Re-rendering the full list on every keystroke would flash. CSS hide/show is instant and requires no state diff. Works because dataset fits in memory.
Pane splitter persistence localStorage key ceph_mgr_split_ratio No backend session needed. Persists across reloads of the same file origin. Cheap and zero-friction.
XSS defence escapeHtml() for all data-derived strings inserted via innerHTML textContent would be safe but can't mix markup. Using innerHTML + explicit escaping is a deliberate choice; pre-rendered fn.html / d.overview_html are trusted (build-time generated HTML, not user input).
Split pane constraint Clamped 20%–80% Prevents either pane from collapsing below min-width: 250px, avoiding broken layout with narrow viewports.
Scroll-to-line setTimeout(..., 100ms) before scrollIntoView The code container is populated via innerHTML; the 100ms delay lets the browser paint before scrolling. Without it, the target element may not yet be in the layout tree.

4 · Threat Model & Adversarial Handling

The output is a read-only explorer distributed to internal team members. There is no user login, no server, no writable API.

Actor / ScenarioAttack SurfaceActual RiskMitigation
Malicious dataset.json input at build time json.load() → json.dumps() → raw injection into <script> HIGH — a crafted string in any field could break out of the JS string literal and execute arbitrary JS at browser load time ⚠️ No sanitisation at build time. The json.dumps() output is inserted verbatim. Mitigation relies entirely on dataset.json being build-system generated (not user-supplied). If dataset origin is untrusted, the output HTML would be unsafe.
XSS via function/object names in rendered HTML renderSidebar(), renderObjectView() — string interpolation into innerHTML MEDIUM — d.object and fn.title are used both escaped (escapeHtml(fn.title)) and unescaped (d.object in onclick attribute strings) escapeHtml() is applied to fn.title in card titles and breadcrumbs. d.object in onclick="navToObject('${d.object}')" is not escaped — a single-quote in an object name would break the attribute. Mitigated by dataset being build-generated.
Malicious overview_html / fn.html content Injected directly as innerHTML (trusted path) MEDIUM — these fields are treated as trusted, pre-rendered HTML. If the pipeline that generates them is compromised, arbitrary HTML/JS executes in the browser. Design decision: these fields are build-time generated from Markdown → HTML conversion (not user input). No runtime sanitisation. Documented trust boundary.
localStorage tampering splitRatioLeft loaded from localStorage LOW — only affects CSS width percentage. parseFloat() returns NaN on garbage; NaN || '50' falls back to default. Implicit: parseFloat(localStorage.getItem(...) || '50') — bad values yield NaN, clamp logic prevents layout break.
Hash injection in URL handleRoute() reads window.location.hash LOW — unknown hash values fall through to navToHome(). Route segments are matched only against known DATA keys. DATA.find() returns undefined on unknown values; all branches have else navToHome() fallback.
Missing / malformed source file content renderSourceCodeLines(sourceText, ...) LOW — missing content renders a placeholder message. Early return: if (!sourceText) return <placeholder div>.

5 · Failure Modes, Edge Cases & Blast Radius

FailureTriggerBlast RadiusObserved Behaviour
Missing dataset.json generate_html() called without input file present Build fails entirely — Python FileNotFoundError raised. No HTML produced. Unhandled exception. No fallback. Script must be run with dataset.json present.
Invalid JSON in dataset.json Malformed JSON Build fails — json.JSONDecodeError. No HTML produced. Unhandled exception. No partial output written.
Output directory does not exist Outputs/ not present Build fails — FileNotFoundError on open(output_path, "w"). No os.makedirs() call. The script assumes Outputs/ exists.
Very large dataset.json Many objects × large source files embedded verbatim in sources HTML file grows unbounded. Browsers struggle past ~50–100 MB. Memory spike in JS engine on const DATA = ... parse. No size guard at build time. File size is printed post-generation but not validated.
%%DATA_JSON%% token absent from template Template accidentally edited Silent failure — str.replace returns template unchanged; JSON blob dropped silently. str.replace with a missing needle is a no-op, no exception. Output HTML renders with const DATA = %%DATA_JSON%%; which throws a JS syntax error at runtime.
Object name contains single quote d.object = "O'Brien" Broken onclick attribute in sidebar/table cells → JS syntax error, navigation breaks for that item. No encoding applied to d.object in template literals that emit onclick="navToObject('${d.object}')".
Function id contains URL-unsafe characters fn.id with /, #, ? Hash routing breaks — parts = hash.split('/') produces wrong segments. fn.id is used raw in updateUrl(${obj.object}/${fn.id}). No encodeURIComponent.
Split pane drag on mobile / touch Touch events Splitter is non-functional on touch devices — only mousedown/mousemove/mouseup listeners are attached. No touchstart/touchmove handling. Panes display correctly but cannot be resized.
concern_lines key resolution failure File path mismatch between concern_lines key and d.sources key format Concern line highlighting silently absent — no error, no crash. The code renders but annotations are missing. getConcernRangesForFile does kClean === activeBase comparison. Subtle path format divergence (trailing slash, different prefix depth) causes missed match.
