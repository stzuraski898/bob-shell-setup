📄 scripts/query_ceph_tracker.sh 🔧 Shell wrapper + inline Python 🌐 Redmine REST API (tracker.ceph.com) 🎯 One-shot issue search tool

1 · High-Level Architecture & Mental Model

What it does in one sentence

A self-contained Bash script that URL-encodes a search term, fires a single Redmine REST API call to tracker.ceph.com, and pretty-prints all matching issues (up to 25) using an inline heredoc Python script piped over stdin.

Component inventory

ComponentRoleInvocation
bash (shebang: /usr/bin/env bash) Orchestrator — arg parsing, variable assignment, pipeline glue Process entry point
python3 (inline -c) URL-encode SEARCH_TERM via urllib.parse.quote() Subprocess — stdout captured to ENCODED
curl -sf HTTP GET to Redmine JSON API; -s silent, -f fail on HTTP error Subprocess — stdout captured to RESPONSE
python3 -c (total count) Parses RESPONSE JSON; prints total_count Subprocess — RESPONSE piped via stdin
python3 heredoc (PYEOF) Full issue formatter — iterates issues[], prints structured lines Subprocess — RESPONSE piped via stdin

Argument forwarding mechanic

The script uses positional default substitution, not "$@" forwarding:

SEARCH_TERM="${1:-life_expectancy}"    # only $1 is consumed; all other positional args are silently dropped
  • $1 — the search string (optional; defaults to life_expectancy)
  • $2 and beyond — ignored; no error, no forwarding
  • The value is then shell-interpolated into a Python -c one-liner for URL encoding (see security §4)

Python interpreter resolution

#!/usr/bin/env bash          # bash from PATH
python3 -c "..."             # python3 from PATH — no version pin, no venv
  • env lookup used for both bash and python3 — relies entirely on the user's $PATH
  • No PYTHONPATH manipulation, no virtual-environment activation — only stdlib (urllib.parse, json, sys)
  • Stdlib-only import set means any Python 3.x installation works without dependency installation

2 · Architectural Decisions & Trade-offs

DecisionWhy this, not thatTrade-off accepted
Bash + inline Python (not pure Bash or pure Python) Bash excels at orchestrating subprocesses and pipelines; Python handles URL-encoding and JSON parsing — both without third-party deps Two runtimes required; no single-binary distribution
Heredoc inline script (<<'PYEOF') instead of a separate .py file Keeps the tool as a single deployable file; zero auxiliary file management Larger script, harder to unit-test the Python logic in isolation
curl -sf instead of wget or requests curl is ubiquitous on Linux/macOS; -f maps HTTP ≥400 to a non-zero exit, which set -e then catches HTTPS certificate validation is on by default (secure); no progress noise (-s)
Redmine subject=~{term} query (not full-text search) Redmine's ~ operator does substring match on the subject field — simple, predictable, no auth required Only matches issue titles, not descriptions or comments; misses body-only mentions
Hard limit of 25 results per request Redmine's documented maximum per page; prevents unbounded response size Silent truncation if total_count > 25; no pagination
No authentication header tracker.ceph.com exposes read-only issue data publicly; no API key needed for this query Cannot access private/restricted projects; no per-user rate-limit token
set -euo pipefail Fail-fast on any unset variable or non-zero exit in the pipeline — prevents silent data corruption from partial failures Any unexpected non-zero (e.g. curl HTTP 4xx, network timeout) aborts with no user-friendly message
Default term life_expectancy Domain-specific: tool was authored for investigating Ceph OSD device life-expectancy validation bugs Default is useful for the original author; may confuse reuse in other contexts

3 · Data Structures, Algorithms & Invariants

Redmine JSON response shape

{
  "issues": [
    {
      "id":         <int>,
      "subject":    <str>,
      "status":     {"name": <str>},
      "priority":   {"name": <str>},
      "tracker":    {"name": <str>},
      "updated_on": "YYYY-MM-DDTHH:MM:SSZ"
    },
    ...
  ],
  "total_count": <int>,
  "offset": 0,
  "limit":  25
}
  • Nested objects for status, priority, tracker — Python accesses via .get("name", "?") with sentinel fallback
  • updated_on sliced to [:10] — truncates ISO-8601 to YYYY-MM-DD without datetime parsing

Shell variable set

VariableTypeSource
BASE_URLString (constant)Hardcoded
SEARCH_TERMString$1 or default
ENCODEDStringpython3 stdout
RESPONSEString (JSON blob)curl stdout
TOTALString (int-like)python3 stdout

All variables are plain shell strings. No arrays, no associative maps.

Key invariants

  • INV-1: RESPONSE is parsed twice — once for total_count, once for the issue list. Both parses receive the same immutable string; no mutation between reads.
  • INV-2: The heredoc delimiter is 'PYEOF' (single-quoted) — Bash performs no variable expansion inside the Python block; the Python code is passed verbatim.
  • INV-3: set -u guarantees ENCODED, RESPONSE, and TOTAL are assigned before use; any failed subprocess assignment aborts the script.
  • INV-4: curl -f maps HTTP ≥400 → exit 22; combined with set -e this means a 404 or 503 aborts before Python ever sees a non-JSON payload.
  • INV-5: Result count is bounded at 25 per the limit=25 query parameter. total_count may exceed 25 — only the first page is displayed.

4 · Threat Model & Adversarial Handling

Attack VectorSeverityWhat happensMitigation / Gap
Shell injection via $1 HIGH SEARCH_TERM is embedded into a python3 -c "..." string with double-quotes. An input like "); import os; os.system('id' would break out of the Python string literal and execute arbitrary code in a subprocess. No sanitization. Mitigated only by the fact this is a local developer tool, not a server-side script. A malicious caller controlling $1 can achieve arbitrary command execution.
Malicious/malformed API response (JSON injection) MEDIUM Python's json.load() raises ValueError on malformed JSON. With set -e, this aborts the script. A crafted response with extremely large payloads could exhaust memory. json.load() is safe against injection into Python logic. Memory exhaustion is theoretical — Redmine's own API paginates at 25.
Malicious Redmine server / MITM MEDIUM curl uses system CA bundle for TLS verification by default. A compromised CA or MITM could serve forged data. curl validates certificates by default (--insecure is not used). No --cacert pinning, so relies on system trust store.
Unquoted URL construction MEDIUM The curl URL is built via Bash string interpolation of ${ENCODED}. If URL-encoding fails and ENCODED contains spaces or special chars, the URL could be malformed. URL-encoding is the purpose of the Python step — output should be percent-encoded and safe. But if python3 itself errors, set -e catches it before curl runs.
PATH manipulation (malicious python3/curl) LOW Script uses env lookup for bash and bare python3/curl names. A compromised $PATH entry could shadow these binaries. Standard risk for any env-based script. Acceptable for a local dev tool; unacceptable for a CI/CD or privileged context.
Denial of service via slow API LOW No --max-time or --connect-timeout set on curl. A stalled connection blocks the shell indefinitely. No timeout guard. Terminal interrupt (Ctrl+C) is the only escape.

Critical shell injection illustration

# Dangerous: $SEARCH_TERM is interpolated into a double-quoted Python -c string
ENCODED=$(python3 -c "import urllib.parse; print(urllib.parse.quote('${SEARCH_TERM}'))")
#                                                                      ^^^^^^^^^^^^^^^^
#  An attacker-controlled value breaks the Python string and injects code.

# Safe alternative:
ENCODED=$(python3 -c "import urllib.parse, sys; print(urllib.parse.quote(sys.argv[1]))" -- "$SEARCH_TERM")

Passing the term as sys.argv[1] isolates it from the Python interpreter's eval surface entirely.

5 · Failure Modes, Edge Cases & Blast Radius

FailureTriggerBehaviourBlast Radius
python3 not found Python not in $PATH set -e fires at URL-encoding step; script exits with error from bash 🟡 Script aborts early; no network call made
curl not found curl not installed set -e fires; aborts after URL-encoding 🟡 Script aborts; no data fetched
Network unreachable No internet / DNS failure curl returns non-zero; set -e aborts; RESPONSE unset 🟡 Clean abort; no partial output
HTTP 4xx/5xx from Redmine API down, rate-limited, endpoint changed curl -f exits 22; set -e kills script before Python sees empty body 🟡 Clean abort; user sees no output and no error message (silent fail)
Zero results Search term matches nothing Python heredoc prints "No issues found." and sys.exit(0) 🟢 Handled gracefully; exit 0
Result count > 25 Popular search term Only first 25 issues shown; total_count is printed so user knows truncation occurred 🟡 Silent truncation of results; no pagination
Missing JSON fields in response API schema change / partial response .get("name", "?") fallback returns "?" sentinel; script continues 🟢 Degraded output, not crash
Malformed JSON in RESPONSE API returns HTML error page, partial body json.load() raises ValueError; Python exits non-zero; set -e kills Bash 🟡 Aborts with Python traceback on stderr — reveals script internals
Special chars in search term User passes "life & death" URL-encoding handles it correctly — but the shell injection risk (§4) is triggered first 🔴 Potential code execution for adversarial input
No timeout on curl Slow/stalled connection Script hangs indefinitely; no watchdog 🟡 Process hangs; user must Ctrl+C

6 · Observability & Triage Playbook

What the script emits (all to stdout)

=== Searching tracker.ceph.com for: 'life_expectancy' ===

Total matching issues: 7
---
  #63274  [Resolved    ] [Normal  ] ceph osd set-life-expectancy truncates to 0
           Type: Bug  |  Updated: 2024-03-11
           URL : https://tracker.ceph.com/issues/63274

  ...
  • No structured logging — all output is human-readable text to stdout
  • Errors (Python exceptions, curl non-zero) go to stderr implicitly
  • No log file, no timestamps, no exit-code documentation

Triage: script exits immediately with no output

  • Run with bash -x to trace each step
  • Check python3 --version and curl --version
  • Run the curl command manually with -v to inspect HTTP status
  • Check network connectivity: curl -v https://tracker.ceph.com

Triage: "Total: 0" but issues should exist

  • The subject=~ filter only matches issue titles — try a broader/shorter term
  • Verify the Redmine endpoint directly in a browser: tracker.ceph.com/issues.json?subject=~life_expectancy&limit=25&status_id=*
  • Check if the API endpoint or Redmine version changed (path format shift)

Triage: Python ValueError / JSON decode error

  • Redmine may be returning an HTML error page — check raw curl output
  • Rate limiting may return a non-JSON body
  • Workaround: remove -s from curl to see headers + body

Triage: only 25 results but need more

  • Script shows total_count so you know truncation occurred
  • Add &offset=25 to the curl URL manually for page 2
  • No built-in pagination — must extend script or use Redmine web UI

One-page recall — key facts for whiteboard defense

  • Pattern: Shell orchestrator + inline Python for encoding/parsing
  • Networking: Single curl -sf GET; HTTPS; no auth; no timeout
  • Arg handling: ${1:-life_expectancy} — only $1 consumed, no "$@"
  • Python resolve: python3 from $PATH; stdlib-only
  • Heredoc: <<'PYEOF' single-quoted — no Bash expansion inside
  • Hard limit: 25 results (Redmine max); silent truncation
  • Safety net: set -euo pipefail + curl -f = fail-fast
  • Biggest risk: Shell injection via $1 interpolated into python3 -c "..."
  • Missing: No pagination, no curl timeout, no error messages to user
  • Scope: Local developer tool — not suitable for CI/CD or untrusted input
