Whiteboard Defense — get-object-history.sh

Role: On-demand lazy consumer of pre-collected git history corpus Transport: SSH/SCP (remote) or filesystem passthrough (local) Shell: Bash · set -euo pipefail Dependencies: bash, scp, awk, ssh · optionally rsync for --all

1. High-Level Architecture & Mental Model

One-sentence purpose: Given a class name (and optionally a method name or flag), locate pre-collected git history flat files — from a remote SSH host or a local directory — and render structured commit metadata to stdout.

Critical framing: This script is a consumer only. It never runs git. All data was produced upstream by collect-object-history-v4.sh and stored as a flat-file corpus under a well-known directory tree. This script is purely a fetcher + formatter.

┌─────────────────────────────────────────────────────────────────────────────┐ │ get-object-history.sh │ │ │ │ ① TRANSPORT DECISION (startup, before any arg parsing) │ │ ───────────────────────────────────────────────────── │ │ HISTORY_RAW_DIR is a local dir? │ │ YES ──► WORK_DIR = HISTORY_RAW_DIR (no SSH, no trap) │ │ NO ──► TMPDIR_CREATED=$(mktemp -d) │ │ trap 'rm -rf TMPDIR_CREATED' EXIT │ │ WORK_DIR = TMPDIR_CREATED │ │ │ │ ② ARGUMENT DISPATCH │ │ ────────────────── │ │ --list ─► fetch_file("INDEX.txt") ──► cat │ │ --all ─► rsync (or scp -r) entire tree ──► exit (no WORK_DIR writes) │ │ CLASS ─► fetch_class(CLASS) [scp -r, guarded by 00-HEADER.txt] │ │ │ │ │ ├─ (no 2nd arg) ─► list methods + SHAs from 09-… │ │ ├─ --signals ─► filter signal:yes across all SHAs │ │ └─ <method> ─► per-SHA detail from 10-… or 02-… │ │ │ │ ③ CLEANUP │ │ EXIT trap ─► rm -rf TMPDIR_CREATED (no-op in local mode) │ └─────────────────────────────────────────────────────────────────────────────┘ Remote corpus layout (mirrored into WORK_DIR on demand): ────────────────────────────────────────────────────── HISTORY_RAW_DIR/ INDEX.txt ← class list; only --list ever fetches this <ClassName>/ 00-HEADER.txt ← head_sha, collected_at, source_cc [SENTINEL] 09-function-commits.txt ← per-method SHA lists (### sections) 10-commits-detail.txt ← per-SHA full detail (=== sections, signal: field) 02-messages.txt ← fallback if 10 is absent; fewer fields

Core Invariants

I-1: Transport is opaque to all modes. All code after the startup branch reads WORK_DIR. Whether that path is /tmp/tmp.XYZ or a live local directory is invisible to the fetching and rendering logic.
I-2: Lazy fetch — fetch only what the current query needs. fetch_file and fetch_class are both no-ops if the target already exists locally. No unnecessary network round-trips.
I-3: Sentinel-guarded class fetch. fetch_class uses 00-HEADER.txt (not directory existence) as the "fully fetched" signal — mkdir -p creates the empty directory before SCP runs, so a bare -d check would be insufficient.
I-4: Single cleanup path. trap … EXIT fires on normal exit, exit N, and unhandled signals. No exit point needs its own cleanup call. (Exception: SIGKILL is untrappable — see §5.)

2. Architectural Decisions & Trade-offs

Decision (X) Rejected Alternative (Y) Justification & Trade-off
Transport decided at startup, before arg parsing Decide inside each mode handler Centralises the local/remote fork into one place; all modes share a single WORK_DIR abstraction. Trade-off: a --list call allocates a temp dir even though it only needs one file. Acceptable: one INDEX.txt fetch is cheap.
Lazy fetch_file / fetch_class with idempotency guards Eager download of all remote files at startup Only files needed for the current query are transferred. A single-method query fetches one class directory (KB-range); --all is the explicit bulk path. Trade-off: each new class opens a fresh SCP connection — no SSH multiplexing or connection reuse across separate invocations.
fetch_class sentinel = 00-HEADER.txt Directory existence (-d) or a synthetic .fetched marker mkdir -p creates the directory before SCP runs (so SCP can write into it). A plain -d check would see the empty placeholder and skip the fetch. 00-HEADER.txt only exists after a successful transfer. Trade-off: A partial fetch that happens to include 00-HEADER.txt before other files would pass the guard; full integrity is not verified.
scp -r per class; rsync only for --all rsync per class; or always rsync SCP has zero additional runtime dependency. rsync gives delta/compression benefits for bulk sync (--all) and has a graceful fallback to scp -r if absent. Per-class SCP avoids mirroring the entire tree for a single query. Trade-off: No delta on subsequent fetches; re-fetching a class re-transfers everything unless the sentinel is present.
trap … EXIT for temp dir cleanup Explicit rm -rf at each exit point Bash EXIT fires on normal exit, exit N, and uncaught signals — one registration covers every code path. No risk of a future code branch forgetting cleanup. Trade-off: SIGKILL bypasses all traps (see §5).
--signals filters inline from 10-commits-detail.txt Pre-built signal index as a separate corpus file No extra file format to maintain in the corpus. The signal: field already lives in each === sha block. Trade-off: O(SHAs × detail_file_lines) scanning per invocation. Acceptable at current corpus scale (~27 classes, <500 SHAs each); would not scale to millions of commits.
Method name stripped of ClassName:: prefix at call-site Require bare method names only from callers SEARCH_NAME="${METHOD##*::}" bridges C++ convention (Class::method) and the index's bare-name storage. Ergonomic for the primary audience. Trade-off: Two different methods with identical base names across classes would both match — but this is a single-class query so the index file is already scoped to one class.
print_sha_detail falls back from file 10 → file 02 Hard fail if 10-commits-detail.txt is absent Graceful degradation for older corpus snapshots. A reduced view from 02-messages.txt is more useful than crashing. Trade-off: Caller may not realise they're seeing the reduced format; signal: and diff fields will be absent without warning.
set -euo pipefail as the global failure strategy Manual || true everywhere Fail-fast is correct for a query tool — partial output is worse than no output. The only deliberate softenings are scp … 2>/dev/null || { echo ERROR; return 1 } (user-readable message before aborting) and grep -c "." || true (handles the zero-match case for SHA_COUNT without aborting).

3. Data Structures, Algorithms & Invariants

Corpus File Schema

FileFormat / DelimitersRole in this script
INDEX.txt Plain text, one class name per line --list only; fetched as a single file via fetch_file
00-HEADER.txt YAML-like key: value pairs (head_sha:, collected_at:, source_cc:) Fetch sentinel; fields extracted with grep | head -1 and printed as the output header
09-function-commits.txt Sections delimited by ### <method>; SHAs indented (40-char hex, one per line); # none if no commits Source of truth for "which commits touched this method"; drives all non---list modes; parsed by get_shas_for_method
10-commits-detail.txt Blocks delimited by === <sha> …; fields within blocks include signal: yes/no Full detail source for print_sha_detail; mandatory for --signals mode
02-messages.txt Same === <sha> block structure; fewer fields; no signal: key Fallback when 10-commits-detail.txt is absent; output capped at 80 lines/block vs 120

get_shas_for_method — section-scoped SHA extraction

awk -v method="${method}" '
  /^### / { in_section = ($0 ~ method) }
  in_section && /^[[:space:]]+[0-9a-f]{40}/ {
    gsub(/^[[:space:]]+/, "")
    gsub(/[[:space:]].*$/, "")
    print
  }
' "${file}"
  • in_section is set to 1 only on the matching ### method header; reset to 0 on any other ### line. SHA lines are only emitted while in_section=1.
  • SHA regex: /^[[:space:]]+[0-9a-f]{40}/ — indentation + exactly 40 lowercase hex chars. Defensive: any annotation after the SHA (spaces, comments) is stripped by the second gsub.
  • Uses regex match ($0 ~ method) not equality — a method search string is a substring match against the section header. Works for both bare names and partial names.
  • Invariant: Returns only SHAs from within the matching section; other methods' SHAs are never emitted.

print_sha_detail — block extraction from === sha delimiters

awk -v sha="${sha}" '
  /^=== / { in_block = ($0 ~ sha) }
  in_block { print }
  /^=== / && !($0 ~ sha) && in_block { exit }
' "${detail}" | head -120
  • Rule order matters: awk evaluates all three rules on each line. On a non-matching === line, rule 1 sets in_block=0 first; by the time rule 3 evaluates, in_block is already 0 — so the exit in rule 3 is never reached.
  • In practice this means the block boundary is enforced by rule 1 (sets in_block=0 stopping rule 2 from printing) rather than the exit. The script still works correctly — rule 1 stops output at the block boundary — but the exit optimisation is dead code.
  • The real upper-bound terminator is head -120 (or head -80 for the fallback file). This prevents terminal flooding from a pathologically large diff block.
  • No dynamic path construction: The sha variable is passed to awk as a literal value pattern, not interpolated into a shell command — no injection risk.

--signals mode — deduplication + cross-reference algorithm

ALL_SHAS=$(awk '/^[[:space:]]+[0-9a-f]{40}/ { gsub(…); print }' "${INDEX}" | sort -u)

while IFS= read -r sha; do
  sig=$(awk -v sha="${sha}" '/^=== / {in_block=($0~sha)} in_block && /^signal:/ {print $2; exit}' "${DETAIL}")
  if [[ "${sig}" == "yes" ]]; then
    # back-reference: scan INDEX again for all methods containing this SHA
    methods_list=$(awk -v sha="${sha}" '/^### / {cur=substr($0,5)} $0~sha {print "  " cur}' "${INDEX}" | sort -u)
    print_sha_detail …
  fi
done <<< "${ALL_SHAS}"
  • sort -u deduplicates SHAs that appear under multiple method sections — each signal commit is printed exactly once.
  • Cross-reference (which methods reference this SHA) re-scans 09-function-commits.txt for lines containing the SHA, collecting the preceding ### section names.
  • Complexity: O(unique_SHAs × detail_file_lines) for signal extraction. Linear scans; no indexing. Bounded by corpus size.
  • SHA_COUNT=$(echo "${SHAS}" | grep -c "." || true) — the || true handles the case where SHAS is empty (grep exits non-zero with zero matches); without it, set -e would abort.

4. Threat Model & Adversarial Handling

Threat / Actor Attack Vector Handling & Residual Risk
MEDUnsanitised CLASS argument Pass CLASS="../../../etc/passwd" (path traversal) CLASS is directly interpolated into "${WORK_DIR}/${CLASS}" and "${HISTORY_RAW_DIR}/${class}" without sanitisation. A crafted class name could request arbitrary remote paths via SCP and write outside WORK_DIR. In practice, WORK_DIR is a mktemp -d path, limiting host-local damage. No input validation exists on class name.
MEDMalicious remote corpus content Attacker controls HISTORY_HOST; returns crafted file contents with shell metacharacters File contents are only passed to awk, cat, grep, and printed to stdout. Contents are never eval'd or interpolated into a shell command. No code execution path from file content. Risk is data integrity (misleading output), not code execution.
MEDSSH host key change / MITM Intercept the SCP connection; return forged corpus data SCP inherits SSH host-key verification. A changed key causes SCP to fail with non-zero exit → set -e aborts with an error message. Forged content that passes key checks is rendered to stdout but never executed. Risk is data integrity.
LOWSpaces in HISTORY_RAW_DIR Default path is /home/…/Object History/raw — contains a space All scp remote-path arguments are double-quoted: "${HISTORY_HOST}:${HISTORY_RAW_DIR}/…". Bash passes the full string (including the space) as one argument to scp. The script comment explicitly confirms this was tested. Correctly handled.
LOWRace condition on temp dir Symlink placed at mktemp -d path between creation and first write mktemp -d creates the directory atomically on Linux. No symlink race is possible post-creation. The rm -rf in the trap will follow symlinks inside the temp dir but not a symlink replacing the dir itself.
LOWTemp dir leak on SIGKILL Process killed with kill -9 during remote fetch SIGKILL bypasses all traps. Temp dir (/tmp/tmp.XXXXXXXX) is left on the local filesystem. It contains only corpus text files — no credentials, no sensitive data. Cleaned on next OS reboot or manual /tmp sweep.
LOWLarge commit block floods terminal Malformed or unusually large diff in 10-commits-detail.txt head -120 (detail file) / head -80 (messages fallback) caps output per SHA block. Terminal flood is unconditionally bounded.

Diagnostic Q&A

Q: "Exited immediately / printed nothing."

  • Check exit code: echo $? — non-zero means set -e triggered.
  • Trace execution: bash -x get-object-history.sh … shows exactly which command failed.
  • Most likely cause: SCP failed silently (2>/dev/null). Verify manually: scp -v "${HISTORY_HOST}:${HISTORY_RAW_DIR}/INDEX.txt" /tmp/probe

Q: "Method query returns 'not found'."

  • List all methods: bash get-object-history.sh ClassName (no second arg).
  • Verify prefix stripping: echo "${method##*::}" — does it match what's in the index?
  • Inspect index directly: grep "^### " "${WORK_DIR}/ClassName/09-function-commits.txt"

Q: "--signals shows nothing even though commits exist."

  • Check signal distribution: grep "^signal:" "${WORK_DIR}/ClassName/10-commits-detail.txt" | sort | uniq -c
  • If all read signal: no: corpus was collected without signal classification — re-run collect-object-history-v4.sh.
  • If 10-commits-detail.txt is absent entirely: the script will die with a clear message.

Q: "Output is truncated at 120 lines."

  • By design: head -120 cap in print_sha_detail.
  • To see the full block without the cap:
    awk -v sha="<SHA>" '/^=== /{in_block=($0~sha)} in_block{print}' "${WORK_DIR}/ClassName/10-commits-detail.txt"

Q: "I want to work offline / avoid SSH every call."

  • Bulk download once: bash get-object-history.sh --all ./local-corpus
  • Then use locally: HISTORY_RAW_DIR="./local-corpus" bash get-object-history.sh ClassName method
  • The if [[ -d "${HISTORY_RAW_DIR}" ]] startup check fires — no SSH, no mktemp, no trap registered.

Q: "A class was partially fetched and now the sentinel check passes but files are missing."

  • Identify the stale cache: ls -la "${WORK_DIR}/ClassName/" — look for missing 09- or 10- files.
  • Fix: delete the partial directory: rm -rf "${WORK_DIR}/ClassName" and re-run. The sentinel guard will re-fetch.
