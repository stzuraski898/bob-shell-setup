1 — High-Level Architecture & Mental Model

One-liner: For each of 27 Ceph mgr C++ classes, resolve the file's entire rename history, build a SHA→historicPath map, then write commits, blame, function index, scoped diffs, and a commit→function map — all in parallel background subshells.

ENTRY cd ${CEPH_ROOT} · capture HEAD_SHA, RUN_TS iterate CLASS_FILES[27] sorted alphabetically │ │ for each class, launch & (background subshell) ▼ PHASE 1 — RENAME RESOLUTION resolve_rename_chain(SRC_CC) ──▶ chain_cc.tmp segments: path sha_new sha_old resolve_rename_chain(SRC_H) ──▶ chain_h.tmp └── git log --follow --name-status --format='COMMIT:%H' -- {path} piped into awk state machine (segment tracker) │ PHASE 2 — SHA→PATH MAP build_sha_to_path_map(chain_cc) ──▶ map_cc.tmp sha path (one per commit) build_sha_to_path_map(chain_h) ──▶ map_h.tmp └── per segment: git log ${seg_old}~1..${seg_new} + git log -1 ${seg_old} │ PHASE 3 — ARTIFACT GENERATION commits.txt union SHAs(map_cc ∪ map_h) → git log --no-walk --stdin blame.txt git blame -w -M -C on current .cc / .h functions.txt ctags --language-force=C++ --c++-kinds=f+p rename_chain.txt cat chain_cc + chain_h (human readable) diffs/{sha}.diff git show {sha} -- {hist_cc} [{hist_h}] ← historically-correct path │ PHASE 4 — COMMIT→FUNCTION MAP commit_function_map.txt └── for each diff: parse @@ hunk headers, extract func context, match against functions.txt names (full Class::method + bare) │ PHASE 5 — CLEANUP + INDEX rm chain_cc/h.tmp map_cc/h.tmp func_names.tmp wait all 27 background jobs → collect FAILED count write INDEX.txt (class | commits | functions | diffs)

Filesystem Output Layout

${OUTPUT_DIR}/
├── INDEX.txt                          # summary table: class | commits | funcs | diffs
└── <ClassName>/                       # one dir per class (27 total)
    ├── commits.txt                    # SHA date author | subject  (rename-aware, newest-first*)
    ├── blame.txt                      # git blame -w -M -C  (.cc + .h)
    ├── functions.txt                  # ctags: "qualified_name | file:line"
    ├── rename_chain.txt               # "path sha_new sha_old" per segment
    ├── commit_function_map.txt        # "SHA | func1 func2 …"  (or "(no functions)")
    └── diffs/
        └── <40-char-sha>.diff        # git show scoped to historic path  [idempotent]

* sort order from git --no-walk --stdin, not guaranteed strictly chronological

Concurrency Model

  • 27 workers spawned simultaneously via & — no work queue, no semaphore.
  • Each worker owns its own ${OUTPUT_DIR}/${CLASS}/ subtree — zero shared mutable state.
  • Stderr serialized with flock on a per-run lockfile /tmp/collect-v4-$$.lock.
  • Main process harvests exit codes via wait ${job}; accumulates FAILED counter.

2 — Architectural Decisions & Trade-offs

"Why did you do X instead of Y?"

DecisionChosen ApproachRejected AlternativeRationale
Rename tracking git log --follow --name-status per file, parsed by awk into path segments; each segment's diffs use its historically-correct path v3 approach: always call git show <sha> -- <current_path> v3 produces spurious "new file mode" diffs for any commit predating a rename. The segment map eliminates this contamination entirely.
SHA→path mapping Two-pass: seg_old~1..seg_new range + separate -1 seg_old catch-up Single seg_old..seg_new range (inclusive both ends) Git range A..B excludes A. The two-pass approach is explicit about the boundary commit rather than relying on a half-open range that silently drops it.
Function extraction ctags on current working tree files; kinds f+p (function definition + prototype) Parse function names from diffs/source manually ctags provides structured, language-aware extraction. Regex parsing of C++ headers is fragile against templates and macros.
Commit→function linkage Parse @@ … @@ context from git unified diff hunk headers; match against ctags names Map line numbers from diff to function ranges from ctags Line numbers shift across the entire rename history. Git's nearest-enclosing-function annotation in @@ is derived from diff content and works correctly across all historical commits.
Parallelism Bash & with one subshell per class; main waits with wait Sequential processing; xargs -P; GNU parallel 27 classes is a bounded, known-small set. Simple & requires no external tools, no job-queue logic, and bash natively provides exit-code harvesting via wait.
Diff idempotency [[ -f "${diff_file}" ]] && continue skips existing diffs Always regenerate diffs; delete output dir on each run Diffs are immutable (content-addressed by SHA). Skipping avoids redundant git show calls on re-runs, enabling safe incremental execution.
Class registry Bash associative array CLASS_FILES[ClassName]="cc_path:h_path" External config file (JSON/YAML/CSV); auto-discovery by grep Keeps the script self-contained and deployable with a single scp. Auto-discovery would pick up unrelated files; explicit registry is auditable.
Merge commits --no-merges flag on all git log calls in the map and commits list Include merge commits Merge commit diffs are noisy (they combine all changes from a branch). The meaningful history lives on the non-merge commits.
Blame flags git blame -w -M -C (ignore whitespace, detect moved/copied lines within and across files) Plain git blame Whitespace-only reformats and internal refactors would incorrectly attribute lines to reformatting commits rather than the original author.
Logging flock-guarded echo to stderr; graceful fallback to unfenced echo if flock absent Named pipe logger; logger process Minimizes dependencies. Partial interleaving of log lines is acceptable; full log corruption (torn lines) is prevented cheaply.

3 — Data Structures, Algorithms & Invariants

Primary Data Structures

StructureTypeKeyValueWhere
CLASS_FILES Bash assoc array ClassName (string) "cc_path:h_path" colon-separated Global config
chain_cc.tmp / chain_h.tmp Newline-delimited text — path sha_new sha_old per line (newest segment first) Per-class temp; deleted after use
map_cc.tmp / map_h.tmp Newline-delimited text — sha40 path per line Per-class temp; deleted after use
awk known[] awk assoc array function name (string) 1 (presence set) commit_function_map inline awk; per-commit
awk funcs_seen[] awk assoc array function name (string) 1 (presence set) commit_function_map inline awk; per-commit

rename chain awk state machine (resolve_rename_chain)

State variables: cur_path seg_new seg_old Input stream from git log --follow --name-status: COMMIT:<sha> → if seg_new=="" set seg_new=sha; always set seg_old=sha R<N> old new → emit "cur_path seg_new seg_old" cur_path = old (rename source) seg_new = seg_old ← new segment starts at rename commit M/A/blank → ignored (path tracking handled by R lines only) END → if seg_new!="" emit final segment
Invariant I1: Segments are non-overlapping and collectively cover every commit reachable via --follow. No SHA appears in two segments for the same file.
Invariant I2: Segment order is newest-first. seg_new is always chronologically ≥ seg_old within a segment.
Invariant I3: For each commit SHA in map_cc.tmp, the stored path is the path that was active when that commit was authored — not the current path.
Invariant I4: diffs/{sha}.diff is content-addressed and immutable. Regenerating with the same SHA always yields identical content (git objects are immutable). Idempotent skip is safe.
Invariant I5: Workers share no mutable state. Each writes exclusively under ${OUTPUT_DIR}/${CLASS}/. No locking needed for file I/O.

Boundary Off-by-One in build_sha_to_path_map

git log ${seg_old}~1..${seg_new} -- ${path}   # range: (seg_old, seg_new]  ← EXCLUDES seg_old
git log -1 ${seg_old}            -- ${path}   # catch-up: add seg_old explicitly

If seg_old is the repository's initial commit, seg_old~1 does not exist. The first call silently returns nothing. The second -1 call still captures it. Net result: correct.

commit_function_map Algorithm

  1. Load ctags function names into awk set known[] from func_names.tmp.
  2. Scan each .diff for /^@@ / lines.
  3. Strip @@ -a,b +c,d @@ prefix; strip argument list (…); trim whitespace → ctx.
  4. Test both ctx (full Class::method) and bare (post-:: suffix) against known[].
  5. Accumulate matches into funcs_seen[]; emit space-separated list or (no functions).

Limitation: git's nearest-enclosing-function heuristic is language-aware but not perfect for C++ templates, lambdas, or functions in anonymous namespaces.

"What if an actor behaves maliciously or unexpectedly?"

Note: This is an offline corpus-collection tool run by a developer in a trusted ceph worktree. There is no network-facing surface or user input. The threat model centers on malformed git objects, hostile repository content, and filesystem misuse.

Huge repository / unbounded parallelism Running script in a repo with thousands of commits and 27 simultaneous workers OOM, fd exhaustion, git pack contention 27 workers is bounded and fixed. Each worker runs ~4 serial git processes. Git's object store uses file locks internally (pack-refs); concurrent reads are safe. Triage Checklist

Symptom: 0 commits for a class
  • Check rename_chain.txt — is the chain populated? Empty chain = git couldn't find the file at all.
  • Verify SRC_CC path in CLASS_FILES matches actual repo path (case-sensitive on Linux).
  • Run manually: git log --follow --name-status -- src/mgr/ClassName.cc | head -40
Symptom: diffs contain "new file mode" or show full file content
  • Indicates historic path lookup failed — check map_cc.tmp was populated (it's deleted post-run; re-run with rm -f diffs/*.diff and add a debug cat map_cc.tmp line).
  • Fallback path (SRC_CC) was used; rename chain likely missed that commit's segment.
Symptom: functions.txt is empty (beyond header comment)
  • Check CTAGS_BIN: run command -v universal-ctags ctags on the target machine.
  • Verify ctags version supports --c++-kinds and --fields=+nk (universal-ctags ≥ 5.x).
  • Inspect raw ctags output: ctags --language-force=C++ --c++-kinds=f+p --fields=+nk -f - src/mgr/ClassName.cc | head
Symptom: commit_function_map.txt has only "(no functions)" entries
  • First verify functions.txt is populated — if empty, all lookups will miss.
  • Check if diff hunk headers actually contain function context: grep "^@@" diffs/<sha>.diff | head
  • C++ files that lack context (e.g., all code inside anonymous namespaces) will produce no matches. Expected for some files.
Symptom: script exits immediately with error
  • set -euo pipefail is active on the main script. Check: is git rev-parse --show-toplevel succeeding? (CEPH_ROOT fallback is . only if it fails).
  • Bash ≥ 4.0 required for declare -A. Check: bash --version.
  • If subshells fail, main script still continues (subshell errors don't propagate to the main shell's set -e).
