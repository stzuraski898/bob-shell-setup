ceph-tracker-issues.sh — Redmine + GitHub open-issue fetcher & HTML reporter

1 · High-Level Architecture & Mental Model

One-sentence summary: A Bash script that authenticates to tracker.ceph.com (Redmine REST API) and GitHub's public API, paginates all open issues assigned to the current user, enriches each with PR metadata and journal timestamps, computes "new since last run" deltas via a persisted timestamp file, emits a self-contained dark-mode HTML report, and optionally spawns Chrome tabs for every linked PR.

2 · Architectural Decisions & Trade-offs

DecisionWhy thisWhy not thatCost / Risk
API key preferred over basic auth Redmine API key never touches password rotation logic; stateless and revocable without changing account password Basic auth is a plaintext credential in the curl process list (-u user:pass) on older systems Medium Basic auth fallback still exists; password leaks via ps on Linux < 5.x
TLS 1.2 enforced via --tlsv1.2 Prevents downgrade to TLS 1.0/1.1; satisfies IBM security floor. Every curl call in the script carries this flag --tlsv1.3 would be stronger but not universally supported on older curl/OpenSSL combos Low TLS 1.2 is still secure; TLS 1.3 preferred where available
Bash-native pagination (accumulate in-memory string) Simple; no temp files for page results; jq -s '.[0] + .[1].issues' merges cleanly Could stream to a temp file per page and use jq --slurpfile; would lower peak RAM Medium Large issue counts (>~500) risk huge bash strings; unlikely in practice
Per-issue detail fetch (N+1 API calls) Redmine bulk list endpoint doesn't include journal entries; a separate GET /issues/:id?include=journals is the only way to get last comment timestamp Could skip last-comment timestamps entirely and use only updated_on from list payload — would eliminate N calls High O(N) HTTP calls per run; 50 issues = 100 extra requests (Redmine + GitHub)
GitHub API unauthenticated PR updated_at from public GitHub endpoint requires no token; reduces credential surface Authenticated GitHub API has 5 000 req/hr vs 60 req/hr unauthenticated High 60 req/hr rate-limit; 60 PRs = entire hourly quota
ISO-8601 string comparison for "newer than last run" Bash string comparison [[ "$ts" > "$LAST_RUN_TS" ]] is correct for well-formed ISO-8601 UTC strings (lexicographic order = chronological order) Converting to Unix epoch via date +%s is more explicit but adds a date subprocess per comparison Medium Breaks silently if any timestamp has mixed timezone offsets (e.g. +05:30 vs Z)
Enriched data staged in a temp file ($ENRICHED_TMP) Bash can't hold complex structured data natively; temp file + jq '. += [...]' accumulation is reliable and inspectable Could use a bash associative array or named pipe; far more complex for structured JSON Low trap 'rm -f ...' EXIT ensures cleanup on all exit paths
PR URL custom field hardcoded as ID 21 The "Pull request ID" field on tracker.ceph.com is field ID 21 — a stable upstream convention Could search by .name == "Pull request ID" dynamically; more resilient to field ID changes Medium If tracker admin ever renumbers the field, PRs silently disappear from report
Self-contained HTML (no CDN dependencies) Report is fully offline-readable; no external CSS/JS fetch required; CSS variables give the dark theme Could import Tailwind or Bootstrap from CDN for faster authoring Low Larger HTML file; but it works in air-gapped environments
Chrome binary auto-detection Handles google-chrome, google-chrome-stable, chromium, chromium-browser — covers Fedora/Debian/Ubuntu naming differences Could require a single explicit env var BROWSER Low No Firefox/Safari support; exits with error if none found

3 · Data Structures, Algorithms & Invariants

Core Data Structures

VariableTypeShape / ContentsInvariant
AUTH_CURL_OPTS Bash indexed array (-H "X-Redmine-API-Key: ...") or (-u "user:pass") Always set before any curl call; splatted as "${AUTH_CURL_OPTS[@]}" to preserve tokens with spaces
ISSUES_JSON Bash string (JSON array) [{id, subject, updated_on, custom_fields:[...]}, ...] Starts as "[]"; each page appended with jq -s '.[0] + .[1].issues'; never written to disk
$ENRICHED_TMP Temp file (JSON array) Array of enriched objects (see schema below); one element per open issue Written atomically: jq > .next && mv .next current; trap EXIT removes both files
$PR_URL_FILE Temp file (plain text) One GitHub PR URL per line, in issue-iteration order Populated only when PR_NUM matches ^[0-9]+$; read into bash array via mapfile -t
LAST_RUN_TS Bash string (ISO-8601 UTC) 2025-06-01T14:32:00Z Empty string on first run; read from .last_run_ts; is_newer_than_last_run returns false when empty
SORTED_ISSUES Bash string (JSON array) Same enriched objects, descending latest_ts Derived from $ENRICHED_TMP via jq 'sort_by(.latest_ts) | reverse'; read-only after creation

Enriched Issue Object Schema

{
  "id":               "12345",          // Redmine issue ID (string)
  "title":            "Fix RGW crash",  // subject from Redmine
  "url":              "https://tracker.ceph.com/issues/12345",
  "updated_on":       "2025-06-01T10:00:00Z",  // Redmine field
  "updated_on_fmt":   "June 1  10:00 AM UTC",
  "last_comment":     "2025-06-02T08:15:00Z",  // max journal.created_on where notes != ""
  "last_comment_fmt": "June 2  8:15 AM UTC",
  "pr_num":           "56789",          // custom_field id=21, empty if absent
  "pr_url":           "https://github.com/ceph/ceph/pull/56789",
  "pr_ts":            "2025-06-03T07:00:00Z",  // GitHub PR updated_at
  "pr_ts_fmt":        "June 3  7:00 AM UTC",
  "latest_ts":        "2025-06-03T07:00:00Z",  // max(updated_on, last_comment, pr_ts)
  "tracker_is_new":   true,             // updated_on or last_comment > LAST_RUN_TS
  "pr_is_new":        true,             // pr_ts > LAST_RUN_TS
  "any_is_new":       true              // tracker_is_new || pr_is_new
}

Key Algorithms

Pagination accumulator
ISSUES_JSON=$(echo "$ISSUES_JSON $PAGE" | jq -s '.[0] + .[1].issues')
  • Reads current accumulator + new page together via jq -s (slurp = parse two JSON docs)
  • Terminates when PAGE_COUNT < LIMIT — assumes Redmine never sends a partial page mid-set unless it's the final page
  • No deduplication: assumes no issue appears on two pages (offset-based, stable sort on Redmine side)
"latest_ts" computation (bash lexicographic max)
LATEST_TS="$UPDATED_ON"
[[ "$LAST_COMMENT" > "$LATEST_TS" ]] && LATEST_TS="$LAST_COMMENT"
[[ "$PR_TS"       > "$LATEST_TS" ]] && LATEST_TS="$PR_TS"
  • Relies on ISO-8601 UTC (Z suffix) lexicographic ordering matching chronological ordering
  • Empty string sorts before any real timestamp in bash — safe: empty timestamps don't "win"
Last-comment extraction (jq pipeline)
jq -r '
  [ .issue.journals[]?
    | select((.notes // "") != "")
    | .created_on ]
  | sort | last // ""'
  • journals[]? — tolerates missing journals key without error
  • select((.notes // "") != "") — filters out status-only journal entries (no text comment)
  • sort | last — lexicographic max of ISO-8601 timestamps; // "" returns empty if no comments
Atomic temp-file update pattern
jq ... "$ENRICHED_TMP" > "${ENRICHED_TMP}.next" && mv "${ENRICHED_TMP}.next" "$ENRICHED_TMP"
  • Prevents partial writes: if jq fails, .next is never promoted and && short-circuits
  • trap 'rm -f "$PR_URL_FILE" "$ENRICHED_TMP"' EXIT covers all exit paths including set -e triggers

HTML Rendering Safety

  • escape_html() escapes & < > " ' in strict order (ampersand first to avoid double-escaping)
  • Applied to: USERNAME, TITLE, all *_FMT display strings
  • URLs (ISSUE_URL, PR_URL) are not escaped — they go into href attributes constructed by the script, not injected from untrusted sources

4 · Threat Model & Adversarial Handling

Trust boundary: The script trusts Redmine and GitHub responses entirely. It is designed for a single authenticated developer running on their own workstation — not a multi-tenant service.
ThreatVectorCurrent HandlingResidual Risk
Credential exposure via process list Basic auth fallback passes user:pass as curl -u argument; visible in ps aux briefly API key preferred; basic auth is a documented fallback; env vars never echoed Medium — Use API key to eliminate entirely
API key leaked in shell history / env dump CEPH_TRACKER_API_KEY as env var; printenv or shell history exposes it Script reads from env only; never prints the key; header value never echoed Medium — Operator must manage env hygiene; no vault integration
TLS downgrade MITM forces TLS < 1.2 Every curl call uses --tlsv1.2; curl rejects connection if server can't meet minimum Low — Effectively mitigated
Malicious issue title containing HTML Attacker creates a Redmine issue with <script>alert(1)</script> in title escape_html() converts all five special chars; script tags rendered as literal text Low — XSS mitigated for title/comment fields
Malicious PR URL (open redirect / URL injection) Custom field 21 contains javascript:alert(1) or a non-numeric value PR_NUM validated against ^[0-9]+$ regex before use; non-numeric values → PR skipped Low — URL constructed from validated integer only
Malicious .last_run_ts file File on disk modified to future date → all issues appear stale; or to epoch → all appear new File content only used for string comparison; no eval or command substitution on its value Low — Worst case: incorrect NEW badges, no code execution
GitHub API rate-limit exhaustion 60 unauthenticated req/hr; >60 PRs in one run returns HTTP 403 curl -sf: -s silent, -f fails on HTTP 4xx/5xx → returns "{}" via || echo "{}"; PR timestamp silently empty High — PR timestamps missing; no user-visible warning
Redmine returns malformed JSON Network interruption, proxy injection, server error body curl -sf fails fast on non-2xx; jq exits non-zero on invalid JSON; set -e propagates to script exit Low — Script aborts cleanly; partial HTML file not committed (write happens after all enrichment)
Path traversal via USERNAME Redmine returns .user.login = "../../etc/passwd" Username used in output file path: ${OUTPUT_DIR}/${USERNAME}-Open-Issues.html; no sanitization applied Medium — Attacker-controlled Redmine server could write to arbitrary path; mitigated by trusted-server assumption
Chrome binary substitution PATH poisoned with a fake google-chrome Script finds first matching binary in $PATH; no hash verification Medium — Requires local PATH compromise; outside script's threat model

5 · Failure Modes, Edge Cases & Blast Radius

FailureTriggerBehaviorBlast Radius
Auth failure on identity probe Wrong API key / wrong creds / network down curl -sf exits non-zero → explicit echo ERROR + exit 1 Contained — no output written; clean abort
Pagination fetch failure mid-loop Network drop between pages curl ... || { echo ERROR; exit 1; } — script exits; accumulated ISSUES_JSON is lost (in-memory) Contained — no partial HTML written; no state corruption; re-run safe
Per-issue detail fetch failure Network blip mid-enrich loop get_last_comment_ts uses || echo "{}" — returns empty last_comment silently Partial — issue appears in report without last-comment timestamp; no crash
GitHub rate-limit (60 req/hr) >60 linked PRs, or multiple rapid runs get_pr_ts: curl -sf ... 2>/dev/null | jq -r '.updated_at // ""' → returns empty string on 403 Partial — PR shown in report, timestamp blank, not flagged as NEW even if updated
Zero issues All issues closed or none assigned Enrich loop body skipped (if (( TOTAL > 0 ))); HTML renders "No open issues found." empty state Safe — clean output, no errors
First run (no .last_run_ts) File absent LAST_RUN_TS=""; is_newer_than_last_run returns false for all items; no ***NEW*** badges Safe — all issues appear stale on first run (correct: no prior baseline)
Missing curl or jq Bare system without tools Dep-check loop at line 37 exits with explicit message before any I/O Contained
Output dir not writable mkdir -p $OUTPUT_DIR fails set -e causes immediate exit; no HTML written Contained
Disk full during HTML write Write to OUTPUT_FILE fails mid-stream Script exits (set -e); partial HTML file left on disk — no atomic write protection on the output file Partial write — re-run overwrites; old report if prior run existed is gone
Chrome not found (--open-prs) None of the 4 binary names exist in $PATH Explicit error message + exit 1 after report is already written Contained — HTML report already complete before Chrome launch
Timestamps with non-UTC timezone offsets Redmine/GitHub returns 2025-06-01T12:00:00+05:30 Bash string comparison breaks — +05:30 < Z lexicographically but could be chronologically later Silent wrong sort — issues sorted incorrectly; NEW detection may misfire
Concurrent runs Two instances run simultaneously Both write to same $ENRICHED_TMP path (different mktemp values) and same OUTPUT_FILE; no locking on OUTPUT_FILE or TIMESTAMP_FILE Race — last writer wins for timestamp; report may be incomplete

Quick Health Check (Manual)

# Verify auth
curl -sf --tlsv1.2 \
  -H "X-Redmine-API-Key: $CEPH_TRACKER_API_KEY" \
  https://tracker.ceph.com/users/current.json | jq '.user.login'

# Check GitHub rate limit
curl -si https://api.github.com/rate_limit \
  | grep -E "X-RateLimit-(Limit|Remaining|Reset)"

# Inspect last run timestamp
cat ./ceph-tracker/.last_run_ts

# Run with debug output
bash -x ./ceph-tracker-issues.sh 2>&1 | head -60

Known Gaps & Improvement Signals

  • No curl timeout — add --max-time 30 --connect-timeout 10 to all curl calls
  • No GitHub rate-limit warning — add check of X-RateLimit-Remaining response header
  • PR field ID hardcoded — extract dynamically via select(.name == "Pull request ID")
  • No output file atomic write — write to .tmp then mv to protect against partial writes
  • Performance — O(2N) API calls; cache PR timestamps between runs to skip unchanged issues
