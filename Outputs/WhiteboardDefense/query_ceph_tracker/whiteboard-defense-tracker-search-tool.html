Whiteboard Defense: Ceph Tracker Search Tool

Source: scripts/query_ceph_tracker.py HTTP Client Read-Only HTML Generator Output: Outputs/TrackerSearch/ Runtime: Python 3, stdlib only

1. High-Level Architecture & Mental Model

One-liner: CLI tool that queries the public Ceph Redmine REST API, deduplicates issues across multiple queries, hydrates full issue descriptions, and renders a static offline HTML investigation dashboard.

Mental model: A batch ETL pipeline over an external read API — Extract (HTTP search), Transform (dedupe + Textile→HTML sanitization), Load (static file emit). Zero state, zero daemon, zero external dependencies, zero credentials.

2. Architectural Decisions & Trade-offs (“Why X instead of Y?”)

Chose (X)Rejected (Y)Defense
Stdlib only: urllib, json, html, re, os, sys, argparse, datetime requests + textile + jinja2 Zero-dependency requirement: runs immediately in minimal developer boxes, air-gapped workstations, or pristine CI containers without pip install, virtual environments, or dependency supply-chain risks. Hand-rolled Textile handles the subset used in Ceph tracker issues.
Sequential HTTP requests: per search and per unique issue asyncio / concurrent.futures.ThreadPoolExecutor Respects community-hosted upstream infrastructure (tracker.ceph.com) to prevent 429 rate-limiting, IP bans, or DoS. Predictable request sequencing; bounded execution time given default limits.
Static HTML output: self-contained files in Outputs/TrackerSearch/ Live web server (Flask/FastAPI) or terminal scrollback only Zero runtime daemon overhead. Creates portable, permanent, shareable, git add-able triage dossiers readable offline without local ports or background services.
Two-Stage Hydration: search query → individual /issues/{id}.json Rely solely on search query results Redmine's /issues.json search endpoint omits full issue descriptions and key custom fields. Hydrating unique IDs guarantees complete backtraces and reproduction steps in the offline report.
Pre-escape Sanitization: html.escape() before regex formatting in redmine_to_html() Post-escape or raw unescaped regex replacement Guarantees elimination of Stored XSS vectors from untrusted tracker content before converting Markdown/Textile syntax into safe DOM elements. Untrusted markup cannot bypass sanitization.
Mutual Exclusion: argparse.add_mutually_exclusive_group() for --issue vs --search Manual branching on parsed arguments Enforces mutual exclusion at CLI parse time, providing standard error formatting and failing fast before any network requests are dispatched.

Algorithms

  • URL Construction & Query Encoding [L100]: urllib.parse.quote(term) applied to search term; interpolated into Redmine query syntax: /issues.json?subject=~{encoded}&status_id={status}&limit={limit}&sort=updated_on:desc.
  • Textile Transpilation Pipeline (redmine_to_html) [L150]:
    1. html.escape(text) — neutralizes <, >, &, ".
    2. <pre>(.*?)</pre> → <pre><code>\1</code></pre> (preserves formatting).
    3. @([^@\n]+)@ → <code>\1</code> (inline code).
    4. \*([^*\n]+)\* → <strong>\1</strong> (bold text).
    5. _([^_\n]+)_ → <em>\1</em> (italic text).
    6. (https?://[^\s<>"']+) → <a href="\1" target="_blank">\1</a> (safe URL linkification).
    7. Double newlines \n{2,} → </p><p>; single newlines \n → <br>.
  • Static Artifact Emission [L522]: Creates target directory via os.makedirs(out_dir, exist_ok=True), writes per-issue detail pages issue_{iid}.html, and renders aggregated index.html with embedded CSS.

4. Threat Model & Adversarial Handling (“What if an actor behaves maliciously?”)

Threat / ActorAttack VectorDefensive Countermeasure
Malicious tracker content (Stored XSS) Attacker submits Redmine issue containing <script>, <img onerror=...>, or event handlers in subject or description. Strict pre-escape architecture: html.escape() neutralizes all HTML entities before formatting regexes run [L156]. Linkification is constrained strictly to https?:// protocols [L172].
Upstream API hang / Slow-Loris tracker.ceph.com stalls TCP connection or delays response packets indefinitely. Hard socket timeout of timeout=15 enforced on all urllib.request.urlopen() calls [L96]. Socket timeout propagates to local exception handlers.
Upstream HTTP 429 / 5xx Errors Upstream server returns rate limits, gateway errors, or temporary 503 outages. Per-request try...except blocks catch Exception, log error details to stderr, and continue processing subsequent searches or issue detail fetches without crashing [L561, L620].
Parameter Injection via CLI User inputs query containing URI control characters (e.g. term&status_id=*&limit=9999). All search terms are passed through urllib.parse.quote() before URL string interpolation [L101]. --status is restricted by argparse.choices [L593].
Path Traversal via Issue IDs Upstream returns malicious ID (e.g., ../../etc/passwd) to escape output directory. Issue IDs from Redmine API are integers; file path construction uses f"issue_{iid}.html" where iid is integer-keyed [L557]. Output root is pinned to constant Outputs/TrackerSearch.
Security Footprint: Zero-credential architecture. The tool uses no API keys, tokens, or basic auth headers. It operates strictly as a read-only client against public endpoints.

5. Failure Modes, Edge Cases & Blast Radius (“Where does this fail?”)

Failure Modes & Edge Cases

Failure Mode / Edge CaseCode LocationBehavior & Recovery
Network / DNS failure fetch_json() [L96] urllib.error.URLError caught in main search loop. Error printed to stderr; empty result appended; pipeline continues to next term.
Individual issue 404 / 403 on detail fetch fetch_issue() in write_html_output() [L553] Caught by try...except Exception. Error logged to stderr; issue detail HTML write is skipped; issue remains present as card in index.html.
Schema drift (missing fields in JSON) Template builders [L200, L245, L387] Defensive .get() lookups fall back to "?", "unassigned", or "—". Prevents KeyError exceptions.
Malformed date strings fmt_date() [L119] try...except catches parsing failures and falls back to string slicing (iso[:10]) or "?".
Zero matching issues across all searches build_index() [L433] Renders valid index.html containing <p class="no-results">No matching issues found.</p> under each search section.
Disk write permission / storage exhaustion write_html_output() [L558, L573] Raises standard OSError/IOError. Process terminates with non-zero status.

6. Observability & Triage Playbook

Diagnostic Signals

ChannelSignal Content & Purpose
stdout Live execution telemetry: active search terms, match counts, deduplication summary, detail hydration progress, and emitted file paths.
stderr Diagnostic logs for failed HTTP operations and parsing anomalies without polluting standard pipeline output.
HTML Metadata UTC generation timestamp (generated_at) embedded into page headers and footers for cache/staleness verification.

Triage Checklist

  1. Upstream Throttling / 429 Errors: If stderr reports HTTP 429 or connection rejections, verify community tracker availability via curl -Is "https://tracker.ceph.com/issues.json?limit=1". Reduce search terms or --limit parameter.
  2. Missing Issue Detail Page: If an issue is listed on index.html but its link gives 404, check stderr for hydration failures. Issues restricted by ACL permissions on Redmine return 403 upon detail lookup.
  3. Empty Results Unexpectedly: Check --status filter flag. By default, --status all is used; if set to open, resolved issues will be omitted.
  4. Connection Timeouts: Long search queues on slow connections may hit the 15-second socket timeout. Isolate queries using --search "specific term" to pinpoint failing endpoints.
