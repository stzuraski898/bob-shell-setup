1. High-Level Architecture & Mental Model

One-line summary: Reads every Outputs/Intents/*-intent.md file, parses its structured Markdown to extract function-level records with severity classifications and line-range citations, augments each record with raw source file text from ../ceph/src/mgr/, and serialises the whole corpus to dataset.json.

ENTRY POINT build_dataset() │ ├── load_source_files() ← runs ONCE, eager │ ../ceph/src/mgr/* ──glob──► sources: Dict[basename → content] │ (flat dict, key = filename without path, e.g. "Gil.cc") │ ├── glob("Outputs/Intents/*-intent.md") sorted alphabetically │ │ │ └── for each intent file # one object == one file │ │ │ ├── METADATA PASS │ │ re.search HEAD SHA, date, commits_count │ │ fallback: count lines in v4/{obj}/commits.txt │ │ │ ├── SOURCE-FILE RESOLUTION │ │ v4/{obj}/functions.txt ──pipe-split──► src_files[] │ │ fallback: check sources dict for {obj}.cc / {obj}.h │ │ │ ├── CANDIDATE HEADING SCAN (per-line, O(n) on intent text) │ │ ## headings → h2_c[] (filtered by non_func_titles set) │ │ ### headings → h3_c[] (filtered by sub-section blocklist) │ │ choose set: whichever is larger AND non-empty │ │ │ ├── OVERVIEW EXTRACTION │ │ lines[0 : first_candidate_heading] → overview_html (markdown→HTML) │ │ │ └── FUNCTION RECORD BUILD for each candidate heading │ section text = lines[start:next_heading] │ tag scan → c_div / c_ung / c_over / c_other counts │ status → DIVERGED > UNGROUNDED > OVERCAUTIOUS > CONCERN > CLEAN │ loc_match → first 400 chars, file:line anchors │ critique_text → Implementation critique block (or full text) │ parse_line_ranges() → concern_lines: Dict[file → [[s,e]…]] │ markdown → fn_html │ ├── SOURCE ATTACHMENT │ for each src_file: lookup basename in sources{} │ obj_sources: Dict[full-path → content] │ └── SERIALISE results[] → dataset.json (json.dump)

2. Architectural Decisions & Trade-offs

DecisionAlternative ConsideredWhy This ChoiceCost / Risk
Eager full source load into RAM
load_source_files() reads every ../ceph/src/mgr/* file up-front into a single dict		 Lazy per-object load inside the loop Avoids redundant disk I/O — multiple objects share the same source file (e.g. Gil.cc). One dict lookup vs repeated open() Entire src/mgr tree held in memory simultaneously. If the tree is large, RAM spike. In practice the Ceph mgr dir is <50 files; acceptable trade.
Heading-level auto-selection (H2 vs H3)
Pick whichever candidate set is larger		 Always use H2, or always use H3, or user-supplied schema Intent files are not schema-locked. Some objects use H2 per function, others use H3. The heuristic picks the denser level and degrades gracefully. If H2 and H3 counts are equal, H2 wins (tie-break). Could silently omit functions if two levels have equal density but represent different logical scopes.
Blocklist-based heading filter
non_func_titles set + inline sub-section list		 Allowlist (only accept known function patterns) Function names are unbounded. Blocklisting known structural headings (corpus, summary, inventory, etc.) is more stable than maintaining a regex for every valid function name pattern. Blocklist maintenance burden. New section headings in intent templates will silently appear as "functions" until added to the blocklist.
Regex-based line-range extraction from free text
parse_line_ranges() with 4 regex patterns		 Structured annotation schema in intent files (e.g. YAML front-matter) Intent files were written in free-form prose by LLM agents. Retrofitting a strict schema would require regeneration. Regex covers the empirical citation formats actually used. Brittle to novel citation styles. False positives possible (e.g. section numbers matching "Line 1").
Priority-ordered status roll-up
DIVERGED > UNGROUNDED > OVERCAUTIOUS > CONCERN > CLEAN		 Multi-label, or highest-count wins Single status is simpler for UI triage. Priority order reflects defect severity: a DIVERGED finding always overshadows cosmetic OVERCAUTIOUS findings. A function with 10 OVERCAUTIOUS tags but 1 DIVERGED is labelled DIVERGED — the count detail is still available in counts{}.
Basename key in sources dict
e.g. "Gil.cc" not "src/mgr/Gil.cc"		 Full-path key The glob enumerates a flat directory. Basename is unambiguous within src/mgr/ (no sub-directories loaded) and matches the functions.txt parts[1] value after splitting off the path component. If the same filename existed in sub-directories of src/mgr/, only one would survive (last writer wins in the load loop).
Optional markdown dependency
try: import markdown		 Hard dependency; always render HTML Dataset is consumed in two modes: raw JSON (test harness, inspection) and HTML-rendered (browser viewer). Graceful absence means the builder still produces valid JSON without the library installed. html fields are empty strings when markdown is absent. Downstream consumers must handle "" as valid.
Critique-section scoping for line extraction
Prefer Implementation critique block over full function text		 Always run regex over full function section text Intent documents contain commit SHAs, PR numbers, and section reference numbers that superficially look like line references. Scoping to the critique block reduces false positives. If no critique block is found, falls back to full text — false positive risk returns.

3. Data Structures, Algorithms & Invariants

Core Data Structures

StructureTypeKey / ShapeInvariants
sources Dict[str, str] basename → full file text Populated once; read-only after return from load_source_files(). Keys are bare filenames ("Gil.cc", not paths). Missing if ../ceph/src/mgr is absent.
non_func_titles Set[str] (literal constant) lowercase section name strings Used for startswith and equality checks. Checked before candidate is appended. Adding a new structural section type requires explicit set update.
candidates List[Tuple[int, int, str, str]] (level, line_idx, raw_line, clean_title) Ordered by line_idx (ascending, since we iterate lines sequentially). Never reordered. Level is 2 (H2) or 3 (H3).
findings_map Dict[str, List[List[int, int]]] filename → [[start, end], …] Built inside parse_line_ranges(). Ranges are not deduplicated or sorted. Same range can appear twice if matched by both pattern branches.
Function record Dict (inline schema) See schema below id is always {obj}_fn_{1-based-index}. status is always one of 5 enum strings. counts subkeys are always ints ≥ 0.
results List[Dict] One entry per intent file Order mirrors sorted(glob(...)) — alphabetical by object name. No deduplication.

Function Record Schema

{
  "id":            "{obj}_fn_{N}",           // N is 1-based loop index
  "title":         "clean_title",            // stripped of ` * # chars
  "status":        "CLEAN|DIVERGED|UNGROUNDED|OVERCAUTIOUS|CONCERN",
  "counts": {
    "diverged":    int,                      // DIVERGED + DEFECT + HAZARD tags
    "ungrounded":  int,                      // UNGROUNDED tags
    "overcautious":int,                      // OVERCAUTIOUS tags
    "concern":     int                       // CONCERN + GAP + RISK + MISSING tags
  },
  "locs":          ["src/mgr/Gil.cc:28", …], // raw re.findall hits, first 400 chars
  "primary_file":  "src/mgr/Gil.cc",         // first locs entry with valid int line
  "primary_line":  28,                       // 0 if none found
  "concern_lines": { "Gil.cc": [[28,50]], … },// parse_line_ranges output
  "raw_markdown":  "...",                    // full section text
  "html":          "..."                     // rendered HTML or "" if no markdown lib
}

Object Record Schema

{
  "object":         "Gil",
  "head_sha":       "8681fa6e…",             // default hardcoded; overridden by regex
  "date":           "2026-09-11T21:40:59Z",
  "commits":        14,
  "source_files":   ["src/mgr/Gil.cc", "src/mgr/Gil.h"],
  "sources":        { "src/mgr/Gil.cc": "…full text…" },
  "overview_html":  "…",
  "function_count": 10,
  "functions":      [ /* function records */ ],
  "totals": {
    "diverged": int, "ungrounded": int, "overcautious": int, "concern": int,
    "clean": int,    "with_concerns": int
  }
}

Line-Range Extraction Algorithm

Two regex passes, both applied to critique_text (or full fn_text fallback):

  • Pattern 1 — file-anchored: (?:src/mgr/)?([A-Za-z0-9_]+\.(?:cc|h))|…(cc|h) followed by :\d+(-\d+)?
    Matches: Gil.cc:28–50, src/mgr/Gil.cc:48, .cc:131
    Normalises bare extensions (cc, h) to {default_file_base}.{ext}
  • Pattern 2 — generic: \bLines?\s+\d+(-\d+)?
    Matches: Lines 239–242, blame lines 167–169
    Attributed to default_file (or literal "default" if none)

Unicode dash normalisation: Both patterns accept -, – (en-dash U+2013), — (em-dash U+2014) as range separators.

Output: findings_map — keys are filenames, values are unsorted, non-deduplicated [[start, end], …] lists.

Status Roll-Up Algorithm

if   c_div  > 0  → "DIVERGED"      # DIVERGED, DEFECT, HAZARD tags + **Divergence:** field
elif c_ung  > 0  → "UNGROUNDED"
elif c_over > 0  → "OVERCAUTIOUS"
elif c_other > 0 → "CONCERN"        # CONCERN, GAP, RISK, MISSING tags
else             → "CLEAN"
Note: **Divergence:** field match contributes +1 to c_div independently of bold-tag scanning — so a function can reach DIVERGED from either path.

Heading Candidate Selection Invariant

chosen = h2_c  if  len(h2_c) >= len(h3_c)  AND  len(h2_c) > 0
       else h3_c
if chosen is empty: chosen = all candidates (h2 + h3 mixed)
  • The tie-break favours H2 — matching the majority of intent file schemas.
  • If all candidates are filtered out, the function list is empty but the object record is still emitted (with function_count: 0).

4. Threat Model & Adversarial Handling

Actor / InputAttack / AnomalyWhat HappensVerdict
Malformed intent file Missing or corrupt heading structure candidates is empty → chosen_candidates = [] → functions = [] → object record emitted with function_count: 0. No crash. SILENT MISS
Malformed intent file Infinite em-dashes or unicode in heading lines re.sub(r"[`*]", "", title) only strips backticks and asterisks. Em-dashes pass through to clean_title. No crash; title is slightly dirtier. BENIGN
functions.txt format change Missing | separator (single-column line) len(parts) >= 2 guard skips the line. src_files may be empty → falls back to checking sources dict for {obj}.cc / {obj}.h. DEGRADED
Source code directory absent ../ceph/src/mgr does not exist os.path.exists(base_dir) → skips load. sources = {}. All obj_sources dicts are empty {}. Dataset still builds; source text fields are empty. DEGRADED
Source file unreadable Permission error on a source file Caught by bare except Exception as e; prints error to stdout; file silently absent from sources. HANDLED
Crafted intent file Thousands of heading-level sections (DoS via memory) Each section's full text is stored in raw_markdown and html in the function record. RAM usage is proportional to total intent file size × 2 (raw + HTML). No limit enforced. UNBOUNDED
Crafted critique text Pathological regex input (ReDoS) Both regexes in parse_line_ranges are linear — no nested quantifiers. Not vulnerable to ReDoS. SAFE
Crafted intent file Inject **DIVERGED** tags into structural sections to inflate severity Tags in sections filtered by non_func_titles are never scanned (those sections never enter chosen_candidates). However, a new section name not on the blocklist would be accepted as a function and its tags counted. PARTIAL
Two objects with same basename source file e.g., two objects sharing Gil.cc sources uses basename key — last writer wins at load time. Both objects successfully look up the content; only one copy stored (correct). SAFE
Hardcoded default SHA Intent file has no HEAD SHA header Falls back to hardcoded "8681fa6ebac230f86eb445bf57095c63e7f1abcc". Dataset is still valid but the SHA field is misleading for objects that genuinely lack the metadata. MISLEADING
output path collision dataset.json already open by another process Python's open(..., "w") will truncate and overwrite. No file locking. On Windows, this raises PermissionError; on Linux, silently races. RACE

5. Failure Modes, Edge Cases & Blast Radius

FailureTriggerBlast RadiusDetection
Wrong heading level selected Intent file has equal number of H2 and H3 candidate sections, but they represent different logical scopes Some functions silently dropped or structural sections treated as functions. Affects one object in the dataset. Other objects unaffected. Check: function_count unexpectedly low; function titles contain structural keywords not in blocklist.
False-positive line ranges Critique text contains commit SHA offsets, section numbers, or PR IDs matching line-range patterns (e.g. "commit 28–50") concern_lines contains spurious entries. Does not crash or affect status classification. Misleads downstream source-highlighting features. Inspect concern_lines for unrealistically high line numbers or entries keyed to "default".
Phantom "default" key in concern_lines Generic "Lines N" match found but primary_file is "" AND default_file arg defaults to obj + ".cc" concern_lines has key like "Gil.cc" with ranges that may not correspond to that file. Downstream must treat this as approximate. Key name matches object default but ranges originate from generic pattern — ambiguous without cross-referencing source.
Empty overview First candidate heading is line 0 (heading at top of file) overview_text = ""; overview_html = "". Record valid but no preamble context. Only affects the overview field. overview_html == "" when markdown is installed.
Duplicate line ranges in concern_lines Same citation appears in both file-anchored and generic patterns Range list has duplicate [s, e] entries. Downstream must deduplicate. No crash. Check for repeated entries in concern_lines[file].
commits.txt count wrong File contains blank lines or header comments commits_count is accurate — the fallback uses l.strip() filter before counting. Not a failure. N/A — correctly handled.
Markdown not installed pip environment without markdown package All html and overview_html fields are "". Raw markdown is still present. Dataset structurally valid. Downstream HTML views render nothing. dataset.json has "html": "" universally.
intent file unreadable Permission denied on Outputs/Intents/X-intent.md Uncaught PermissionError → entire script aborts mid-run. dataset.json is not written (write happens after the loop). Previously valid JSON file is NOT overwritten. Data loss is zero but run is incomplete. Exception traceback to stderr; dataset.json timestamp unchanged.
Bottleneck: source file load Large ../ceph/src/mgr/ tree All source files loaded into RAM before processing begins. With a large mgr directory (~100+ files, each 1000+ lines), peak RAM could be significant. Time is I/O-bound at startup. Profile with time python build_dataset.py; memory via /usr/bin/time -v.
Bottleneck: markdown rendering Large intent files with complex tables markdown.markdown() called twice per function (once for overview, once for fn_text across all functions). For a large object with 30 functions × 2KB each = 60 renders. CPU-bound; linear. Profile per-object timing; consider caching or batch render if latency matters.

concern_lines has absurd line numbers (e.g. 50000) Search critique text for the number — likely a commit SHA fragment or PR number Generic "Lines N" pattern matched a non-line context Add a range sanity check in parse_line_ranges (e.g. reject > 10000)

Dataset build is slow Profile: time per object, total markdown renders Many large intent files + markdown rendering overhead Defer markdown rendering to a separate pass; or cache rendered HTML on disk
