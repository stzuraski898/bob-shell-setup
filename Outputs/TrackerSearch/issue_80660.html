mgr: missing validation for inverted life expectancy ranges in DeviceState and CLI command handlers

Description

DeviceState tracks predicted disk failure windows via lifeexpectancy (makepair(from, to)). Neither DeviceState::setlifeexpectancy() nor DeviceState::set_metadata() validates that from <= to. Furthermore, upstream callers, including the ceph device set-life-expectancy CLI handler in DaemonServer.cc and persistent store loader in Mgr.cc contain zero validation checks to ensure the lower bound does not exceed the upper bound.

As a result, inverted ranges (where from > to or lifeexpectancymin > lifeexpectancymax) are accepted, persisted to the monitor store, and cause incorrect formatting and underflow risks during duration math in getlifeexpectancy_str().

Found via unit test: 



TESTF(DeviceStateTest, LatentBugsetlifeexpectancy_InvertedRange) {

  utime_t now(1000, 0);

  utime_t from(3000, 0); // min is 3000

  utime_t to(2000, 0);   // max is 2000 (inverted: from > to)

  

  device->setlifeexpectancy(from, to, now);



  // Range should either be rejected or normalized, not stored as from > to

  EXPECTLE(device->lifeexpectancy.first, device->life_expectancy.second);

}


Impact:

1. Illogical / Backwards User Output:
In DeviceState::getlifeexpectancy_str() (src/mgr/DaemonState.cc:109-128): 


string a = timespanstr(maketimespan(min));

string b = timespanstr(maketimespan(max));

return a + " to " + b;


2. Underflow Risk in Duration Math If to < now < from, now >= life_expectancy.first is false, leading to: 


utimet max = lifeexpectancy.second - now; // Underflow: subtracting larger unsigned time from smaller

utimet uses unsigned components (uint32t sec()), subtracting now when now > to results in large unsigned wraparound values when converted via make_timespan(max).

Resolution
The problem should either be resolved at the CLI level or within setlifeexpectancy and set_metadata, ensuring that from <= to
