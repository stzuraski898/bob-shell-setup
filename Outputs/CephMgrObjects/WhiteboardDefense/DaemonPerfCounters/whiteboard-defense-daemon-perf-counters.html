1 — High-Level Architecture & Mental Model

Role in the Manager

  • One DaemonPerfCounters object lives inside each DaemonState — it is the per-daemon counter store for the manager.
  • It receives incoming MMgrReport messages (one per daemon heartbeat) and keeps a rolling time-series of recent counter values.
  • It does not handle locking, persistence, or serialisation — all of that is the caller's responsibility (DaemonStateIndex).

Data Flow

Daemon (osd/mon/mds/rgw…) ──── MMgrReport (packed binary + declare_types + undeclare_types) ────▶ MgrServer.handle_report()
│ locks DaemonState
▼
DaemonPerfCounters::update(report)
│
├─ load declare_types → shared PerfCounterTypes& types
├─ track per-session membership → MgrSession::declared_types (set<string>)
├─ erase undeclare_types from session set
└─ DECODE packed binary, for each path in session set:
├─ lazy-insert instances[path] if absent
├─ LONGRUNAVG → push_avg(now, val, avgcount)
└─ else → push(now, val)
DaemonServer::handle_open() ──── on new session ────▶ DaemonPerfCounters::clear() ── wipes instances only

2 — Architectural Decisions & Trade-offs

Decision Alternative Rationale (commit-grounded) Cost / Trade-off
Shared PerfCounterTypes& (global registry) Per-daemon type map Avoids duplicating type metadata for every daemon instance. Type paths are identical across all OSDs/MDSs; sharing is correct. Any caller can pollute the shared map. Duplicate declare silently no-ops (std::map::insert semantics). No eviction.
declared_types lives in MgrSession, not here Owned set<string> in this class dc415f1ae09a (tracker #21197): Multiple RGW daemons share a name; their sessions opened concurrently. One session's declared set was bleeding into another's decode loop, causing wrong types to be decoded. update() must retrieve the session from the connection on every call via get_priv(). Creates a static_cast coupling to MgrSession.
Lazy instance creation in decode loop Eager insert on declaration (1164ef2f32d8) 5b6037aeb43a (tracker #36244): Eager insert caused crash when a concurrent session called clear() between declaration and decode, making instances.at() throw out_of_range. Slightly more branching per decode iteration. Correct guard comment preserved in code.
Ring buffer (boost::circular_buffer<DataPoint>(20)) per instance Single current value 9501bfdd7114: "store some counter history." Manager needs time-series to answer rate/sparkline queries; a single scalar discards history. Fixed 20-slot window. Old history silently evicted. No configurable depth.
clear() wipes only instances Also clearing declared_types Pre-dc415f1ae09a, clear() cleared both. After migration, declared_types belongs to MgrSession and its lifetime follows the session, not the counter store. If a caller calls clear() and then reads without a new update(), instances is empty but the new session will lazily recreate them on the next report.
const MMgrReport& (pass-by-ref) Raw pointer MMgrReport* 9b6aa95ff401: Semantic cleanup — the function never modifies the report. Pointer signature implied ownership or nullability neither of which is true. None; purely a correctness improvement.
Out-of-line ctor/dtor (header forward-declares PerfCounterType) Inline in header d2d4c7d3f865 / 35f6dd06dd0b: Moving MMgrReport.h include to the .cc file required the full PerfCounterType definition to be unavailable in the header. Out-of-line dtor prevents incomplete-type instantiation of the map. Slightly more verbosity; enables faster recompilation by breaking include chains.

3 — Data Structures, Algorithms & Invariants

instances — std::map<string, PerfCounterInstance>

  • Key: counter path string (e.g. "osd.op_r")
  • Value: PerfCounterInstance — wraps two ring buffers:
    • buffer: circular_buffer<DataPoint>(20) — for plain counters/gauges
    • avg_buffer: circular_buffer<AvgDataPoint> — for LONGRUNAVG
  • Created lazily on first decode for the path (not at declaration time)
  • Wiped entirely by clear()

types — PerfCounterTypes& (std::map<string, PerfCounterType>)

  • Shared reference into DaemonStateIndex
  • Populated by update() via types.insert(make_pair(t.path, t))
  • Duplicate insert is a silent no-op — first writer wins
  • Types are never removed from this map, even on undeclare
  • Used in decode loop: types.at(t_path) — safe because t_path ∈ session→declared_types ⊆ types

Counter vs. Gauge vs. LONGRUNAVG Semantics

Type flagWire encodingStorage callBuffer used
PERFCOUNTER_COUNTER val (u64) push(now, val) DataPoint ring buffer (size 20)
PERFCOUNTER_GAUGE val (u64) push(now, val) DataPoint ring buffer (size 20)
PERFCOUNTER_LONGRUNAVG val, avgcount, avgcount2 (3× u64) push_avg(now, val, avgcount) AvgDataPoint ring buffer
⚠ UNGROUNDED: avgcount2
Decoded from the wire at line 74 (since ac30e6cee2b2, 2016-06-30) but never passed to push_avg or stored. 1164ef2f32d8 added push_avg and removed the TODO comment, but did not pass avgcount2. The variable exists solely to advance the buffer pointer — its semantic purpose is undocumented and unimplemented. No commit in the full 14-commit history explains what it was supposed to provide.

Decode Algorithm (update loop)

for (t_path : session→declared_types) {
    &t = types.at(t_path);            // safe: declared ⊆ types

    // Lazy create — concurrent clear() may have wiped instances
    it = instances.find(t_path);       // 5b6037aeb43a
    if (it == instances.end())
        it = instances.insert({t_path, t.type}).first;

    decode(val, p);
    if (t.type & PERFCOUNTER_LONGRUNAVG) {
        decode(avgcount, p);
        decode(avgcount2, p);           // consumed but DISCARDED
        it→second.push_avg(now, val, avgcount);
    } else {
        it→second.push(now, val);
    }
}

Invariants

#InvariantEstablished
I-1 session→declared_types ⊆ types — every path in the session set has a valid type entry. Guaranteed because the declare loop inserts into types before inserting the path into session→declared_types. ac30e6cee2b2
I-2 The packed byte stream has exactly one value per path in session→declared_types (plus avgcount/avgcount2 for LONGRUNAVG paths). Breaking this causes DECODE_FINISH to throw. ac30e6cee2b2
I-3 declared_types is NOT owned by this class. clear() must not touch it. dc415f1ae09a
I-4 An instance for t_path may not exist at decode time even if the path is in the session set (concurrent clear()). Always use lazy find-or-insert, never at(). 5b6037aeb43a
I-5 types is never purged. Undeclared type paths are removed from session→declared_types only, leaving the type definition in the global registry. a46690c6230b
I-6 The session pointer is kept alive for the duration of update() by holding the intrusive_ptr priv in a local variable. 72883956c26f

4 — Threat Model & Adversarial Handling

Actor / Scenario What Happens Blast Radius Mitigated?
Daemon sends malformed packed binary (truncated / wrong field count) DECODE_FINISH(p) detects overrun or underrun and throws a C++ exception. The exception propagates up to handle_report(). Single report dropped. Connection may be closed depending on caller error handling. Partial — exception is thrown but the original TODO ("handle badly encoded things without asserting out") was removed without being replaced by graceful recovery.
Daemon floods declare_types with novel paths Every new path inserts unconditionally into the shared types map and the session set. No limit enforced. Shared types map grows without bound across all daemon connections. Memory pressure on manager process. No — no path count limit at this layer.
Daemon re-declares an existing path with different metadata types.insert(make_pair(t.path, t)) is a no-op if the key already exists — first-writer wins. Silent discard of new metadata. No log warning. A rogue daemon cannot overwrite an already-seen type definition. Benign — accidental protection; not a deliberate security gate.
Two RGW daemons share the same name, race on open dc415f1ae09a: declared_types is per-session, so each connection has its own type membership set. One session's types cannot bleed into another's decode loop. Isolation is correct at the session level. Both sessions share the same instances map (same DaemonState object), so their counter values intermix. Partial — type isolation fixed; instance isolation acknowledged as "not prevented yet" in code comment.
Session B calls clear() while session A is mid-update() Session A's decode loop encounters a missing instances entry. The lazy find-or-insert at 5b6037aeb43a recreates it. A few data points may be silently discarded (the just-cleared entries). No crash. Crash fixed — data loss is possible but accepted.
Session pointer get_priv() returns null (daemon disconnects mid-flight) static_cast<MgrSession*>(priv.get()) would be a null pointer dereference. session→declared_types access would crash. Manager crash (SIGSEGV). Not guarded — no null check. Relies on the assumption that the connection always has a valid session when a report arrives.
Daemon sends undeclare for a path it never declared session→declared_types.erase(t) on a non-existent key is a no-op for std::set. None. Harmless

5 — Failure Modes, Edge Cases & Blast Radius

Failure Root Cause Observable Symptom Blast Radius
Decode exception on malformed packed data Wire encoding out of sync with session→declared_types. Can happen if a daemon is restarted mid-session and old schema state persists. Exception thrown from update(). Counter history silently stale until next successful report. Single daemon's counters frozen. Manager remains up.
types.at(t_path) throws out_of_range Path in session→declared_types but not in shared types. Should be impossible by invariant I-1 but could occur if the shared map was externally modified. Uncaught exception from decode loop. Manager crash in pathological cases.
Counter history silently capped at 20 points Ring buffer is hardcoded to 20. High-frequency reporters or slow polling consumers will lose history. Sparklines / rate queries span at most 20 samples. No overflow warning. Silent data loss. Only affects historical queries, not current value.
avgcount2 silently discarded Variable decoded to advance wire pointer but never stored. Intent undocumented. Bug since ac30e6cee2b2, unresolved through 1164ef2f32d8. Any metric that depends on avgcount2 (e.g. stddev of a running average) is unavailable via the manager's perf counter API. Incomplete avg statistics. No crash, no error log.
Shared types map unbounded growth Types are only added, never removed. Even after all reporting daemons exit, stale type definitions accumulate. Manager memory grows proportionally to lifetime unique counter paths. Memory leak on long-lived managers with high daemon churn.
Concurrent clear() drops data silently One session opens for a named daemon, calling clear() and wiping entries a concurrent session just wrote. Counter gaps in time-series. Acknowledged in code comment (5b6037aeb43a). Per-daemon data gap. No crash. Affects all consumers reading that daemon's counters.
Clock skew between ceph_clock_now() calls Timestamp is captured once per update() call at the start (750ad8340c82). All counters in one report share the same timestamp. All counters in a single report appear at an identical timestamp. High-resolution ordering within a report is lost. Acceptable; sub-report ordering is not a stated requirement.

Triage Runbook

Symptom: Counter history is empty / stale for a specific daemon
1. Check manager log for dout(20) lines from that daemon — is update() being called?
2. If called: check whether declare_types.size() == 0 on every report (daemon never re-declared after reconnect).
3. If not called: daemon not sending MMgrReport. Check daemon-side perf dump and its mgr connection state.
4. If called with non-zero declare and still empty: suspect concurrent clear() from a competing session for the same daemon name.
Symptom: Manager crash / exception in update()
1. Stack trace will show DECODE_FINISH or types.at().
2. DECODE_FINISH: packed data length mismatch — daemon protocol version skew or daemon sent wrong counter count for its declared set. Check daemon version.
3. types.at(): invariant I-1 broken — path in session set but not in shared types. Should not happen; implies external map corruption or a code path that inserts to session set without inserting to types.
Symptom: LONGRUNAVG metrics showing wrong averages
avgcount2 is decoded from wire but silently discarded (ac30e6cee2b2, never fixed). Any metric needing avgcount2 (second-moment / stddev of running avg) is incorrect. This is a known gap — no commit in the full 9-year history resolved it.
Symptom: Manager memory growing without bound
Shared types map never shrinks. On clusters with high daemon churn (ephemeral RGW workers, test daemons), type paths accumulate permanently. Mitigation: restart manager (resets DaemonStateIndex).
