§1 · High-Level Architecture & Mental Model

What is this?

MgrOpRequest is the ceph-mgr analogue of OSD's OpRequest. It wraps an inbound MessageRef and registers it with OpTracker, giving the mgr daemon the same op-tracking / slow-op visibility that OSDs have had for years. Introduced as a single large commit (66efcaae) in December 2023.

Lifecycle Flow

Caller (DaemonServer / Dispatcher) │ │ OpTracker::create_request<MgrOpRequest>(msg) │ └─ new MgrOpRequest(req, tracker) │ ├─ TrackedOp(tracker, req->get_recv_stamp()) ← anchors timer at wire-recv time │ ├─ request = req ← MessageRef ref-count +1 │ └─ req_src_inst = req->get_source_inst() ← snapshot; immutable hereafter │ ├─ mark_started() │ ├─ mark_queued_for_module() │ ├─ mark_reached("module-name") ← stores module name in last_event_detail │ ├─ [optional] mark_start_mon_command() │ ├─ [optional] mark_finish_mon_command() ── ⚠ BUG: sets flag_start_mon_command, not flag_finish_mon_command │ │ Processing completes / op deregisters │ ├─ OpTracker calls _unregistered() │ ├─ request->clear_data() │ ├─ request->clear_payload() │ ├─ request->release_message_throttle() │ └─ request->set_connection(nullptr) ← drops connection ref; big memory win │ └─ ~MgrOpRequest() ← MessageRef RAII calls put(); (was double-put before 941c5eda) ───────────────────────────────────────────────────────────────── Parallel observers (dump_ops_in_flight / dump_historic_ops): _dump(Formatter*) ← called by OpTracker; lock held for events iteration _dump_op_descriptor(os) ← one-liner: get_req()->print(stream) filter_out(filters) ← address filter: exact → nonce=0 → nonce+port=0

§2 · Architectural Decisions & Trade-offs

Decision Rationale / Defence Alternative Rejected Evidence
Inherit TrackedOp directly Reuses the entire OpTracker infrastructure (event log, slow-op watcher, dump APIs, address filter contract) without reimplementing it for mgr. Custom standalone tracker with no base class 66efcaae
MessageRef (intrusive_ptr) instead of raw pointer RAII ref-count ensures the Message stays alive for the full tracked lifetime even after the caller drops its reference. No manual lifetime bookkeeping. Raw Message* with manual get()/put() 66efcaae; bug confirmed by 941c5eda
Snapshot req_src_inst at construction _unregistered() clears the connection; after that point request->get_source_inst() may be unusable. Snapshotting at ctor makes _dump() and filter_out() safe to call post-unregister. Re-read from request each time 66efcaae
uint8_t bitmask for flags Five stages fit comfortably in a byte; bitmask accumulation in hit_flag_points allows asking "did this op ever reach module?" independently of current state. Enum, int counter, or string state 66efcaae
_unregistered() clears payload/data/throttle/connection but does NOT deallocate the Message The MgrOpRequest may still be referenced by dump_historic_ops after it leaves the active table. Clearing payload reclaims the memory-intensive parts while keeping metadata (source, tid, type) accessible for dumps. Full delete of Message on unregister 66efcaae
static_cast in get_req<T>() Consistent with OSD's OpRequest; no runtime type check overhead. Callers know the concrete type from the message type field before calling. dynamic_cast with null check 66efcaae (undocumented)
Three-pass address matching in filter_out() Copied from OSD's OpRequest::filter_out: exact → nonce=0 → nonce+port=0. Allows operators to filter by IP only, or IP+port, without needing to know the session nonce. Exact-only match 66efcaae (no comment; U3)
Two mark_flag_point overloads (const char* vs const string&) Avoids unnecessary std::string construction for literal-string callers. The string variant is used when the caller already has a std::string (e.g. from Python module name). Single overload accepting only std::string 66efcaae
LTTng tracepoint opt-in (#ifdef WITH_LTTNG) Zero overhead when LTTng not compiled in; #define tracepoint(...) makes calls compile to nothing. Always-on logging or perf counters only 66efcaae

Algorithm: filter_out() — Three-Pass Address Matching

Pass 1: exact match — full entity_addr_t (IP + port + nonce)
Pass 2: nonce zeroed — matches IP:port regardless of session ID
Pass 3: nonce + port zeroed — matches IP-only

If any filter set is all non-parseable strings → addrs is empty → return true (include all)

Copied from OSD's OpRequest::filter_out. No comment in any commit explains the three-pass approach in the mgr context. (UNGROUNDED U3)

Algorithm: _dump() — Event Duration Calculation

for each event i in events (random-access vector):
    duration = (i == begin) ? 0 : i.stamp - (i-1).stamp
emit { event: i.str, time: i.stamp, duration: duration }

Lock scope: lock (TrackedOp::lock) held only around the events iteration. state_string() (reads latest_flag_point + last_event_detail) is called before the lock. UNGROUNDED U2 — these two reads are not protected.

§4 · Threat Model & Adversarial Handling

Threat / Adversarial Input What Happens Severity Mitigation
Client sends malformed / garbage source address req->get_source_inst() is called unconditionally at construction. A structurally invalid address is snapshotted into req_src_inst. filter_out() compares against it; a garbage addr just won't match any filter. Low No crash. Worst case: op is always visible in dump_ops_in_flight even when a filter is active.
Client sends a null/null-source message (req == nullptr) Constructor dereferences req->get_recv_stamp() without a null guard. Immediate null-dereference crash. Critical Precondition: callers (OpTracker::create_request) must never pass null. No in-class guard exists. Enforced by convention only.
Attacker floods mgr with many inflight ops Each op registers with OpTracker; the table grows. OpTracker enforces osd_op_complaint_time / osd_op_num_ops_threshold (mgr uses analogous config). No per-op size bound on events. Medium OpTracker slow-op threshold will log/alert. Memory: each op holds a MessageRef until _unregistered() — which fires when the tracker deregisters the op. For historic ops, only the cleared message shell remains.
Caller passes all-garbage filter strings to dump_ops_in_flight filter_out() parses each string as entity_addr_t; unparseable strings are silently ignored. If all strings are unparseable, addrs is empty → return true → all ops are shown. Not a security risk, but unpredictable UX. Low Operator issue only; no crash or info leak.
Concurrent mark_* calls from multiple threads mark_event() acquires TrackedOp::lock to append to events. But last_event_detail and latest_flag_point are written outside the lock in mark_flag_point. Concurrent _dump() reads them without the lock too. Medium UNGROUNDED U2 — technically a data race on std::string last_event_detail. In practice the mgr processes ops on a single event thread, making this benign in deployed code but fragile by design.
Wrong T in get_req<T>() static_cast<const T*>(request) will succeed silently at compile time. If T is not the actual dynamic type, reading through the cast pointer is undefined behaviour. Medium Caller contract: must guarantee type before calling. No runtime check. Pattern copied from OSD OpRequest which is also performance-sensitive. UNGROUNDED U4.
Short-lived const char* passed to mark_reached() Pre-16b3343b: stored as raw pointer → dangling pointer → garbage in dump_historic_ops_by_duration. Post-16b3343b: copied into std::string; safe. Fixed Fixed 16b3343b tracker #66268
Explicit request->put() in destructor Pre-941c5eda: double-decrement of ref-count when MessageRef destructor also called put() → use-after-free / crash. Fixed Fixed 941c5eda tracker #70618

Reading a Dump — Quick Reference

{
  "ops": [{
    "flag_point": "queued for module",     ← _get_state_string() via _dump()
    "client_info": {                        ← only present when is_client()
      "client": "client.4308",
      "client_addr": "192.168.1.5:0/12345",
      "tid": 42
    },
    "events": [
      {"event": "started",          "time": "...", "duration": 0},
      {"event": "queued_for_module","time": "...", "duration": 0.0012},
      ...
    ]
  }]
}
⚠ Known dump anomalies to be aware of:
  • Mon-command ops stuck at "start mon command" even after completion → D3 bug. The events array will show "mon_command_finished" as the last event string, but flag_point remains "start mon command". Use the events array, not flag_point, to determine actual mon-command completion.
  • Empty flag_point in dump_historic_ops_by_duration → unknown flag value passed to static get_state_string().
  • Stale/empty module name in flag_point when flag_point shows "reached module" but no module name appears → mark_flag_point_string was used instead of mark_flag_point (D2).
  • Event string vs state string inconsistency: event log says "queued_for_module" (underscore), state says "queued for module" (space). Don't grep for one to find the other.

Triage Decision Tree

Op appears stuck in dump_ops_in_flight? │ ├── flag_point = "no flag points reached" │ → Op never called mark_started(); either just created or DaemonServer bug. │ ├── flag_point = "queued for module" │ → Op is waiting in module dispatch queue. Check module backlog. │ ├── flag_point = "start mon command" │ → EITHER genuinely stuck in mon command, OR mark_finish_mon_command() was │ called (D3 bug). Check events array for "mon_command_finished" entry. │ If present: op completed but tracking is wrong (D3). │ If absent: op genuinely blocked waiting for mon response. │ ├── flag_point = "reached module" with empty/missing module name │ → mark_flag_point_string() was used (D2). Check LTTng trace for actual module. │ └── flag_point = "" (empty) → Unknown flag value. Check state_flag() raw value via LTTng trace.

LTTng Trace Points

When compiled with -DWITH_LTTNG, every mark_flag_point and mark_flag_point_string fires:

tracepoint(mgroprequest, mark_flag_point, flag, s, old_flags, hit_flag_points)

This is the only reliable way to observe old_flags (pre-transition bitmask) and get the raw event string for mark_flag_point_string calls (which don't update last_event_detail).
