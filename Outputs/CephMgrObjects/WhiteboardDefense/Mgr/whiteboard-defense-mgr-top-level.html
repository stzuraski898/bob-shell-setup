1. High-Level Architecture & Mental Model

What is Mgr?
Mgr is the active Ceph Manager daemon instance — the brain that coordinates cluster state monitoring, daemon metadata, cluster map ingestion, KV config synchronisation with monitors, and Python module execution. It is owned and lifecycle-managed by MgrStandby. It implements Dispatcher to receive Ceph messages from the messenger layer.

2. Architectural Decisions & Trade-offs

Decision / "Why X instead of Y?" Rationale Key Commit(s)
Async background init (background_init + Finisher) instead of blocking sync init Prevents blocking the caller (MgrStandby's messenger thread) during lengthy map subscriptions and metadata loads. completion callback fires only after all Python modules are confirmed started, avoiding a premature active beacon. 7845f8d757ad (background init), e0e87da6529d (completion callback), cbd1726fde08 (module-start barrier)
_exit(0) on SIGINT/SIGTERM instead of graceful Python shutdown Python module teardown deadlocked reliably (tracker #42744, #42981). Monitor blocklists the mgr's RADOS clients on failover, so graceful client-side cleanup is unnecessary. Forced exit is the correct tradeoff. 3363a1001c7b
Pacific KV push subscription (kv:mgr/, kv:device/, kv:config/) instead of polling config-key ls + per-key get Polling required O(n) synchronous mon commands at startup. KV subscription delivers incremental push updates. Pre-Pacific monitors fall back to load_store() bulk scan. Pre-init updates staged in pre_init_store until active_start(). edf1ea2f5092
Wait for OSDMap epoch ≥ last_failure_osd_epoch before accepting daemon reports Ensures the OSDMap containing the previous mgr instance's blocklist entry has propagated to the new mgr before it opens DaemonServer. Without this, a zombie prior-mgr could still reach RADOS objects. f2986a4400bb
CRUSH physical hostname override for OSDs, not reported container hostname In Rook/containerised deployments, OSD pods report container hostnames; CRUSH records the real physical host. ceph device ls was showing pod names. Override with CRUSH host in all three metadata paths. Falls back to reported hostname if CRUSH has no mapping. dcd9c5bac5e2 (override), ec5988807024 (fallback)
Clear daemon_health_metrics for down+out OSDs instead of removing from DaemonStateIndex Removing down+out OSDs broke Prometheus exporter and stat output (ceph osd pool stats). Daemon state must persist; only health metrics are stale when an OSD is down and out. 3072b113242e (removed), 282558cf4027 (reverted — clear instead)
Process map internally before notifying Python modules Prior ordering notified modules with stale map data; modules might call back into ClusterState and read the old map before the update was applied. Handler-then-notify is the correct invariant. 190f37978f72
MetadataUpdate::notify_updating(key) in constructor, not at call site Multiple call sites dispatched MetadataUpdate; without constructor-side registration, two concurrent fetches for the same daemon were possible. 3eaf1516ebbf
Resolve CRUSH host outside state->lock crush_hostname_for_osd calls with_osdmap() which acquires Objecter::rwlock. Acquiring that under state->lock would violate the global lock ordering and risk deadlock. dcd9c5bac5e2 (code comment)
Sleep ~3×mgr_tick_period on pre-Pacific startup Pre-Pacific monitors require multiple beacon exchanges before module option overrides propagate. Without the sleep, early active start would race against undelivered config options. b356fd0a8c65
Owned services injected from MgrStandby instead of self-allocated Original design allocated MonClient, Objecter, Messenger in the constructor. Refactored to inject them so standby/active lifecycles could be managed externally and resources shared between standby/active transitions. 7845f8d757ad, 6c10417f7ed3
Explicit shutdown() method instead of relying on destructor order Unit test teardown found that DaemonServer's OpHistory background thread accessed op_tracker members after destruction began (tracker #76334). Explicit ordered shutdown stops the thread before member destructors run. fd4d4ce58b86, 75b6149b294e

3. Data Structures, Algorithms & Invariants

Core Data Structures

MemberTypePurpose & Invariants
lock ceph::mutex Guards all mutable Mgr state. Must be held before accessing initialized, initializing, daemon_state, map handlers. Dropped across blocking mon-command waits and re-acquired. Invariant: never acquire under state->lock + Objecter::rwlock.
daemon_state DaemonStateIndex Hash-index of daemon metadata keyed by DaemonKey{type, name}. Supports: insert, get, exists, cull, notify_updating, is_updating, clear_updating, update_metadata. "updating" set prevents duplicate concurrent metadata fetches.
cluster_state ClusterState Caches current OSDMap, FSMap, MgrMap, ServiceMap. Accessed via scoped callbacks (with_osdmap(), with_monmap()) — never return raw pointers.
pre_init_store std::map<string, string> Staging area for KV push data arriving before active_start(). Pacific: updated by MSG_KV_DATA handler. Pre-Pacific: populated by load_store(). Handed to py_module_registry->active_start() at module launch. Keyed on full config-key path.
initialized / initializing bool State machine flags guarded by lock. Only check_all_modules_started() (or timeout path) transitions initializing→initialized. is_initialized() drives MgrStandby::send_beacon().
initialization_start_time ceph::coarse_mono_clock::time_point Zero until background_init(); set to now(). Used by exceeded_initialization_expiration() to detect hung module startup. Reset to zero when initialization completes (either path).
digest_received bool One-shot flag; set true by first handle_mgr_digest() arrival. Guards digest_cond wait in init(). Once true, never reset.
finisher Finisher Single-threaded queue serialising the init path and completion callbacks. Prevents concurrent execution of init() with message dispatch callbacks without additional locking.
fs_map_cond / digest_cond ceph::condition_variable Condition variables for startup synchronisation. fs_map_cond signaled by handle_fs_map(); digest_cond by handle_mgr_digest(). Both waited under lock in init().
MetadataUpdate Context subclass Completion for async mon-command metadata fetches. Constructor calls daemon_state.notify_updating(key) immediately (dedup guard). finish(r): validates JSON, resolves CRUSH host outside locks, updates DaemonStateIndex. defaults map injects synthetic fields for legacy daemons.

Lock Ordering (Global)

Critical ordering rule: Never acquire Objecter::rwlock while holding DaemonState::lock (or any sub-lock). The CRUSH hostname lookup via with_osdmap() acquires Objecter::rwlock — always resolve CRUSH host before taking state->lock.

Lock hierarchy (outer → inner):
Mgr::lock > DaemonState::lock  |  Objecter::rwlock is acquired independently (not nested under DaemonState::lock)

Key Algorithms

  • OSD join detection: In handle_osd_map(), triggers MetadataUpdate when osd_map.get_up_from(osd_id) == osd_map.get_epoch() (newly joined) or when no existing daemon state exists. (73078cf73c3a)
  • Daemon culling: Collects all currently-known OSD/MDS/Mon names into names_exist set, then calls daemon_state.cull(type, names_exist) to prune stale entries. Called in handle_osd_map, handle_fs_map, handle_mon_map.
  • Pre-init KV staging: Full vs incremental MSG_KV_DATA — full update clears matching prefix range from pre_init_store before inserting; incremental applies deltas (set/delete per key).
  • Metadata defaults injection: MetadataUpdate::set_default(k, v) pre-registers key/value pairs. In finish(), any key absent from the mon response is filled from defaults. Used for legacy MDS addr field. (8ce30bc4cd23)
  • Module-start barrier: check_all_modules_started() spins on pending_modules emptiness before setting initialized=true. Prevents advertising active status when modules are still loading. (cbd1726fde08)

4. Threat Model & Adversarial Handling

Actor / Scenario What Mgr Does Gaps / Residual Risk
Malicious or buggy Python module hangs in serve() exceeded_initialization_expiration() fires after mgr_module_load_expiration ms. Forces initialized=true so the beacon is sent and the cluster unblocks. Module is force-initialized, not killed. The hung module thread continues running. It may consume CPU and may issue broken RPCs. No sandboxing. (bf25a08cc58c)
Python module deadlock on shutdown (SIGTERM/SIGINT) handle_mgr_signal() calls _exit(0) immediately. No Python teardown attempted. Monitor blocklists all RADOS clients. In-flight Python operations are unceremoniously killed. Any non-flushed RADOS writes by modules are lost. Acceptable because blocklisting ensures consistency.
Daemon sends invalid / malformed metadata JSON MetadataUpdate::finish() validates JSON parse success and that root is json_spirit::obj_type. Logs error and returns without updating state. clear_updating() is called unconditionally so the daemon can be retried. A daemon that persistently sends bad JSON will be retried on every OSDMap / FSMap epoch until it sends valid data. No circuit breaker / blackhole for such daemons.
Daemon sends metadata without "hostname" Entry skipped with a log notice. No state update occurs. clear_updating() still called. Daemon is perpetually absent from DaemonStateIndex. All Python module metrics for that daemon will be missing.
Unknown daemon type in MetadataUpdate (key.type not in {mds, osd, mgr, mon}) ceph_abort() — immediate process crash. Hard invariant: any future daemon type must be added to the type list or abort is triggered. This is an intentional tripwire.
Zombie prior-mgr instance still running after failover New mgr waits for OSDMap epoch ≥ last_failure_osd_epoch before opening DaemonServer. That OSDMap contains the prior mgr's blocklist entry, evicting its RADOS/MDS sessions. Race window between blocklist propagation and new mgr accepting work is bounded by OSDMap propagation latency, not eliminated.
Mon returns error on config-key ls during load_store() ceph_assert(cmd.r == 0) — process abort. Individual config-key get failures are tolerated (skip key). A transient mon disconnect during startup crashes the mgr. No retry logic for the listing command.
Admin socket command with unknown admin_command Returns -ENOSYS. Malformed arguments return -EINVAL (via bad_cmd_get exception catch). No privilege elevation risk — admin socket access requires local root/sudo anyway.
DaemonServer.init() fails (bind error) Logs error and calls exit(1) — lets systemd restart the process. No attempt at port retry or alternative port. Single failure mode for the whole mgr process.
Containerised OSD reporting pod hostname instead of physical host CRUSH physical hostname lookup overrides reported hostname in all three metadata paths. Falls back to reported hostname if OSD not in CRUSH or CRUSH map unavailable. Only OSDs are overridden; MDS/Mon container hostnames are NOT corrected. If CRUSH map is incomplete, some OSDs get pod hostnames.
Racing config-key deletion during load_store() Individual config-key get failure tolerated: key is skipped rather than aborting or inserting stale data. (615a6562bc6a) Deleted key silently absent from initial store — modules start without that config value.

5. Failure Modes, Edge Cases & Blast Radius

Startup Failures

FailureBehaviourBlast Radius
server.init() bind failure exit(1) — process terminates, systemd restarts Total mgr loss until restart; standby may promote. Port conflict blocks all restarts.
FSMap or MgrDigest never arrives init() blocks indefinitely in condition variable wait; mgr never signals active beacon Mgr remains non-active indefinitely; cluster operates with degraded mgr. Standby promotion will also block.
Python module hangs in serve() Active beacon delayed until mgr_module_load_expiration. Module commands unavailable during delay. Cluster commands fail with ENOTSUP for that module's command set until timeout or module starts.
sqlite3_open_v2 or cephsqlite_setcct failure (WITH_LIBCEPHSQLITE) ceph_abort() Total mgr process crash. Will restart but same abort if SQLite init conditions persist.
All metadata mon commands fail (r != 0) during load_all_metadata() ceph_assert(r == 0) — process abort Mgr crashes on startup. Will keep crashing if mon is unresponsive.

DeviceStateIndex may be incomplete for MDS-hosted devices. MDS device tracking broken at startup; may recover when MetadataUpdate runs asynchronously on FSMap update.

TODO: FSMap daemon_state population race (line 762) Python modules can read the new FSMap before daemon_state is updated with new MDS metadata. Commented as known. Python modules may see an MDS in FSMap that has no corresponding daemon state entry transiently.

Stale in-flight MetadataUpdate completion will attempt to insert/update state for a destroyed OSD. daemon_state.clear_updating() still called unconditionally so index stays consistent.

Shutdown Ordering

Correct shutdown sequence (established 75b6149b294e):
  1. Unregister admin socket commands (if initialized)
  2. finisher.wait_for_empty() — drain pending init/completion contexts
  3. finisher.stop() — stop finisher thread
  4. server.shutdown() — stop DaemonServer + OpHistory thread
Wrong order risk: If server.shutdown() runs after member destruction begins, the OpHistory background thread accesses freed memory → SEGFAULT / "pure virtual method called".
