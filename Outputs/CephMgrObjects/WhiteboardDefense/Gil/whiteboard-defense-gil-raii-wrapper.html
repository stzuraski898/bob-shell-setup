§1 — High-Level Architecture & Mental Model

What does this module do?

src/mgr/Gil.h / Gil.cc provide RAII wrappers around Python's Global Interpreter Lock (GIL) for Ceph's manager daemon. ceph-mgr embeds CPython and runs multiple sub-interpreters. The standard PyGILState_* API is incompatible with sub-interpreters, so this module replaces it with explicit, thread-state-bound acquire/release primitives.

Root motivation (f36b0d9d Tim Serong, 2017-05-12): "Prep work for loading modules in separate Python sub-interpreters. Mixing the PyGILState_*() API with sub-interpreters is unsupported."

Object Lifecycle Flow

── "Same-thread" path (new_thread=false, default) ────────────────────────────────────

  C++ thread (owns SafeThreadState.thread == pthread_self())
  │
  ├─ { Gil gil(state); }
  │     ctor:  PyEval_RestoreThread(state.ts)   ← GIL acquired, thread state current
  │            ceph_assert(pthread_self() == state.thread)
  │            assert_gil()                     ← ts->thread_id == PyThread_get_thread_ident()
  │     dtor:  PyEval_SaveThread()              ← GIL released
  │

── "New OS thread" path (new_thread=true) ────────────────────────────────────────────

  C++ thread NOT created by Python (new_thread=true required)
  │
  ├─ { Gil gil(state, true); }
  │     ctor:  pNewTS = PyThreadState_New(state.ts->interp)
  │            PyEval_RestoreThread(pNewTS)     ← GIL acquired on fresh state (fb26bcd9)
  │            assert_gil()
  │     dtor:  PyThreadState_Clear(pNewTS)      ← release Python refs in state
  │            PyEval_SaveThread()              ← GIL released
  │            PyThreadState_Delete(pNewTS)     ← free memory
  │

── GIL drop-and-reacquire (without_gil_t / with_gil_t) ──────────────────────────────

  (GIL held)
  ├─ { without_gil_t no_gil;          ← assert_gil() + PyEval_SaveThread() → save=ts
  │      ...non-Python code (locks OK here)...
  │      no_gil.acquire_gil();          ← PyEval_RestoreThread(save) → save=nullptr
  │      ...Python call...
  │   }  ← ~without_gil_t: save==nullptr → no-op   (6469a9a6 optimization)
  │
  │   — OR: use with_gil_t for scoped reacquire —
  │
  ├─ { without_gil_t no_gil;
  │      ...
  │      { with_gil_t wg(no_gil);        ← no_gil.acquire_gil()
  │           ...Python call...
  │        }                              ← ~with_gil_t: no_gil.release_gil() → save=ts
  │   }                                   ← ~without_gil_t: save!=nullptr → acquire_gil()

Locking Policy (codified at 88db7b19)

Rule 1: Do NOT acquire non-GIL locks while holding the GIL — use without_gil_t.
Rule 2: ALWAYS hold the GIL when calling Python functions.

Rationale: Python's GC can release and re-acquire the GIL autonomously. Holding a non-GIL lock while the GIL is held creates a deadlock window if Python triggers GC mid-call.

§2 — Architectural Decisions & Trade-offs

DecisionWhy this approach?Why not the alternative?SHA
Custom Gil class instead of PyGILState_Ensure/Release PyGILState_* is documented incompatible with sub-interpreters. ceph-mgr uses sub-interpreters per module. PyGILState_Check() always returns 1 once any sub-interpreter exists — masking real correctness errors. f36b0d9d
SafeThreadState wraps PyThreadState* + pthread_t Without the pthread_t record, callers could silently call Gil(state) from the wrong POSIX thread — undefined behaviour in CPython. Could auto-detect thread mismatch via pThreadState->thread_id != PyThread_get_thread_ident(), but that violates the C API contract (only public member is interp). Noted in comment since f36b0d9d. 625e1b5c
assert_gil() uses PyThreadState_Get().thread_id instead of PyGILState_Check() PyGILState_Check() always returns 1 if any sub-interpreter has ever existed — useless as an assertion. PyThreadState_Get() aborts if no current state; thread_id equality check is the real guard. PyThreadState_GetUnchecked() would be cleaner but requires Python ≥ 3.13. Migration path is documented in the comment at Gil.cc:44–46. 19a9981e (Fixes: #74220)
new_thread=true path: PyEval_RestoreThread(pNewTS) directly Eliminated a round-trip: old code did RestoreThread(state.ts) then ThreadState_Swap(pNewTS). Same net effect, one fewer call. The old two-step approach was "safe" but redundant; the original state.ts thread state was never the right active state for the new OS thread. fb26bcd9
without_gil_t destructor is idempotent (if (save)) Allows callers to call no_gil.acquire_gil() explicitly to reacquire the GIL, making ~without_gil_t a no-op — avoids an unnecessary unlock/lock cycle at scope exit. Alternative: always reacquire in destructor. This forces an extra unlock/reacquire when with_gil_t is used as the final scope operation. 6469a9a6
release_gil() and acquire_gil() made public at 6469a9a6 Enables the "avoid redundant lock/unlock" pattern from Sage Weil's optimization: call no_gil.acquire_gil() when ready, skip the extra cycle. Leaving them private (as in 88db7b19) forced use of with_gil_t for every GIL reacquire, always paying the extra cycle cost. 6469a9a6
Gil is copy-deleted Two Gil objects for the same thread state would mean two PyEval_SaveThread calls on destruction — double-release, undefined behaviour. No alternative; the prohibition is clearly signalled at the API level since f36b0d9d. f36b0d9d
Implementation in .cc not .h Reduced include blast from Python.h being dragged into every TU that included Gil.h. Original implementation was header-only; moved to .cc in 23c3a075. 23c3a075

§3 — Data Structures, Algorithms & Invariants

SafeThreadState layout

class SafeThreadState {
public:
  PyThreadState *ts;     // raw CPython state
  pthread_t      thread; // POSIX thread that owns ts

  explicit SafeThreadState(PyThreadState *ts_);
  SafeThreadState();     // deferred-init; ts=nullptr
  void set(PyThreadState *ts_);
};
  • Public fields — intentional; Gil::Gil reads them directly.
  • explicit constructor since 39ffec28 — prevents silent PyThreadState*→SafeThreadState coercion.

Gil layout

class Gil {
public:
  Gil(const Gil&) = delete;
  Gil& operator=(const Gil&) = delete;

  Gil(SafeThreadState &ts,
      bool new_thread = false);
  ~Gil();

private:
  SafeThreadState &pThreadState;  // ref, not owned
  PyThreadState *pNewThreadState  // != nullptr iff new_thread
    = nullptr;
};
  • pNewThreadState == nullptr is the sentinel distinguishing paths in ~Gil().
  • pThreadState is a reference — lifetime must exceed Gil object.

without_gil_t layout

struct without_gil_t {
  without_gil_t();
  ~without_gil_t();
  void release_gil();   // public since 6469a9a6
  void acquire_gil();   // public since 6469a9a6
private:
  PyThreadState *save = nullptr; // null = GIL held
  friend struct with_gil_t;
};

save != nullptr → GIL is not held; save == nullptr → GIL is held (or destructor is no-op).

with_gil_t layout

struct with_gil_t {
  with_gil_t(without_gil_t& allow_threads);
  ~with_gil_t();
private:
  without_gil_t& allow_threads; // ref back to scope
};
  • Constructor calls allow_threads.acquire_gil().
  • Destructor calls allow_threads.release_gil() — restores save so the enclosing without_gil_t can reacquire.

Re-entrancy

Do not nest Gil objects on the same thread. PyEval_RestoreThread() when already holding the GIL is documented to deadlock. No runtime guard prevents this. The comment has been present since f36b0d9d.

Edge Cases at the Python Boundary

  • Sub-interpreter context: assert_gil() uses ts->thread_id which is documented "not necessarily stable" — may need updating when Python 3.13+ support is targeted (19a9981e comment).
  • Multiple SafeThreadState objects per interpreter: Nothing prevents two SafeThreadState objects from wrapping the same PyThreadState*. Two Gil objects from different states on the same interpreter would correctly serialize, but the pthread_t check would only cover same-thread misuse.
  • Thread ID reuse: POSIX allows pthread_t values to be reused after thread exit. If a thread exits and a new thread is created with the same ID while a stale SafeThreadState exists, the pthread_self() check passes incorrectly. Not guarded; low-probability in practice.

Triage Scenarios

Symptom: mgr process aborts with ceph_assert(pthread_self() == pThreadState.thread)
→ A C++ thread is calling Gil(state) without new_thread=true. Find the caller and add the flag. Note: GIL was already acquired before the abort — the assert is post-acquisition. If debugging under gdb, the GIL is leaked.
Symptom: mgr deadlock — Python module callbacks block indefinitely
→ Likely locking policy violation: a non-GIL mutex was acquired while holding the GIL. Look for code that constructs Gil while holding a Ceph mutex. Wrap the mutex acquisition in without_gil_t.
Symptom: assert_gil() fires (ceph_assert(ts->thread_id == ...))
→ Thread holds GIL but ts->thread_id doesn't match PyThread_get_thread_ident(). Possible causes: thread ID reuse after pthread exit, or a stale PyThreadState being used from the wrong thread. Check the SafeThreadState that was passed to Gil.
Symptom: assert(save) fires in acquire_gil()
→ without_gil_t::acquire_gil() was called when save == nullptr (GIL already held). Check for double-acquire_gil() or a with_gil_t construction when the GIL is not released. Note: this is plain assert, not ceph_assert — compiled out with NDEBUG.
Future migration path (documented in code)
Once Python < 3.13 support is dropped, replace PyThreadState_Get() in assert_gil() with PyThreadState_GetUnchecked(), removing the dead ceph_assert(ts != nullptr) at Gil.cc:48.
