1. High-Level Architecture & Mental Model

What it is

PyFormatter is a Ceph ceph::Formatter subclass that builds a live Python object graph instead of serializing to bytes. Every dump_* call inserts a native PyObject* into a PyDict or PyList. The result is retrieved via get() as a new reference ready for the Python GIL holder.

Two-class hierarchy (since 403340bcf8)

  • PyFormatter — mutable builder. Root stays a PyDict or PyList. Not copyable (938189e8f2).
  • PyFormatterRO — read-only subclass. On first get() it recursively freezes the entire tree (list→tuple, dict stays dict with frozen values, set→frozenset). Subsequent get() calls reuse the frozen tree until reset().

2. Architectural Decisions & Trade-offs

DecisionWhy this, not Y?Establishing commit
Build a live PyObject* graph, not serialize to bytes ceph-mgr plugins are Python. Returning bytes would require a Python-side json.loads() round-trip on every call. Building native objects eliminates that overhead and preserves Python types (int, float, bool, None). ac30e6cee2b2
Cursor + stack model for sections Mirrors how serializing formatters track nesting depth. A single mutable cursor pointer plus a std::stack is the minimal state to implement open_* / close_section at O(1). ac30e6cee2b2
dump_pyobject steals its argument Follows Python C-API "new reference" ownership convention. Callers that pass borrowed refs (singletons like Py_True, Py_None) must Py_INCREF first — making ownership explicit at the call site. ac30e6cee2b2
GIL held for entire lifetime (not enforced, caller contract) Python objects are not thread-safe. Construction, destruction, and every dump_* call touches the CPython heap. Enforcement via assertion would add overhead; the comment in the constructor documents the invariant (9ea37c223f92). 9ea37c223f92
Copy and assignment deleted Copying the formatter would clone raw PyObject* pointers without incrementing refcounts, causing double-free on destruction. The mutable cursor/stack state would also be aliased. Deletion makes the error compile-time. (938189e8f2) 938189e8f280
flush(), get_len(), write_raw_data() abort on call These methods exist in ceph::Formatter for serializing formatters (JSON, XML). PyFormatter produces objects, not byte streams. Calling them indicates a caller bug; aborting is correct over returning garbage. 61fca96c2910
Namespace sections (_in_ns) abort Ceph namespaces are a JSON-serialization concept with no Python object equivalent. The comment "Obscure, don't care" in ac30e6cee2b2 is explicit; 61fca96c2910 hardened the abort. 61fca96c2910
dump_unsigned uses PyLong_FromUnsignedLong Original code used the signed variant, silently truncating values above INT64_MAX. Bug fix in ac8b016b7237 preserves the full uint64_t domain. ac8b016b7237
All strings are Python 3 Unicode, via PyUnicode_FromStringAndSize Python 2 was dropped (48c4bc445fc). Unicode objects are the universal string type in Python 3. Length-aware construction from string_view (6712393fbc53) avoids NUL-termination requirements. 48c4bc445fc · 6712393fbc53
Deferred stream materialization via PendingStream dump_stream() must return an ostream& synchronously, but the content is written after the call returns. A shared PendingStream object captures the cursor context at call time; finish_pending_streams() resolves all of them before get(). ac30e6cee2b2
PyFormatterRO freezes lazily (on first get()) Freezing is expensive for deep trees. Deferring it to first get() means formatters that are populated but never read pay no conversion cost. Flag prevents repeated conversion. 403340bcf8c2
Fallback to original on conversion failure (readonly path) If PyTuple_New / PyDict_New / child conversion fails, return the original mutable container increffed rather than NULL. Callers receive a valid (mutable) object rather than crashing. 403340bcf8c2
enable_line_break() is a no-op Line-break semantics are text-serializer concepts. Python objects have no textual line structure. Rather than aborting (which would break callers using the generic Formatter* interface), it silently accepts the request. 992829d38cb8
Dict keys decoded as UTF-8 with explicit length Keys arrive as string_view; they may not be NUL-terminated and may be substrings. PyUnicode_DecodeUTF8(name.data(), name.size(), nullptr) is the only safe API for this input. 6712393fbc53

3. Data Structures, Algorithms & Invariants

Core state (protected members, ac30e6cee2b2)

FieldTypeRole
rootPyObject*Owned reference to the top-level dict or list. Never reassigned except in reset() and convert_to_readonly().
cursorPyObject*Non-owning pointer to the currently active container. Starts equal to root; moves inward on open, outward on close.
stackstd::stack<PyObject*>Parent-cursor stack. Each open_* pushes; each close_section() pops. Stack depth == nesting depth.
pending_streamsstd::list<shared_ptr<PendingStream>>Deferred stream objects. Each holds a captured cursor pointer, a key name, and a stringstream. Flushed by finish_pending_streams() before any get().

Invariants

  • Cursor invariant: cursor always points to a live PyList or PyDict owned (directly or transitively) by root. Inserting into any other type → ceph_abort().
  • Section-stack balance: close_section() asserts cursor != root and !stack.empty(). Under-close aborts; over-close impossible by construction.
  • Ownership protocol: dump_pyobject steals its PyObject* argument. Every caller either (a) passes a freshly allocated object (new reference) or (b) Py_INCREFs a borrowed singleton before passing it.
  • get() always returns a new reference: Caller must Py_DECREF the result. Multiple get() calls are safe; each increments the root's refcount.
  • GIL must be held for all operations (constructor, destructor, every dump_*, get()). Not enforced by assertions — caller contract.
  • No serializer interface: flush(), get_len(), write_raw_data() always ceph_abort().
  • PendingStream cursor snapshot: The cursor saved in PendingStream is non-owning. If a section is closed after dump_stream() but before finish_pending_streams(), the stream inserts into the original cursor, not the current one — which is the intended deferred-write semantics.

4. Threat Model & Adversarial Handling

ScenarioWhat happensStatus
Caller invokes dump_* without holding the GIL CPython heap is accessed without the lock. Race condition → refcount corruption → crash or silent heap corruption. No runtime guard; enforced only by caller discipline. CALLER CONTRACT
Caller passes a string with non-UTF-8 bytes (e.g., raw disk data) PyUnicode_FromStringAndSize fails, error is cleared, and the value is silently dropped. No key is inserted into the dict/list. The commit message of 7c68a00cce5b claims a Latin-1 fallback was added — it was not. Silent drop is the actual behavior. DIVERGED / DATA LOSS
Caller passes a string that causes dump_format_va to produce non-UTF-8 bytes (via vsnprintf) Same as above: PyUnicode_FromString on the stack buffer may fail; result passed directly to dump_pyobject which then aborts on null. The pre-check in dump_string is absent here. DIVERGED / ABORT RISK
Format string in dump_format_va produces output > 1024 bytes vsnprintf truncates silently. The caller has no way to detect truncation. Established behavior since 86c851e138ae — the bound is intentional but the truncation policy is undocumented. SILENT TRUNCATION
Caller closes more sections than it opened close_section() asserts cursor != root and !stack.empty(). Triggers ceph_assert → ceph_abort(). Process terminates. ABORT (INTENTIONAL)
Caller calls flush(), get_len(), or write_raw_data() All three call ceph_abort() unconditionally. Intentional: these are serializer-only operations with no Python object equivalent. ABORT (INTENTIONAL)
Caller calls open_array_section_in_ns() or open_object_section_in_ns() ceph_abort(). Namespace sections are XML/JSON concepts; unsupported by design. ABORT (INTENTIONAL)
Caller attempts to copy or assign a PyFormatter Compile error — copy constructor and assignment operator are = delete. Prevents double-free. COMPILE-TIME SAFE
PyDict_New() or PyList_New() returns null (OOM in Python heap) For dict/list sections: null is passed to dump_pyobject which then hits the null guard → ceph_abort_msg. For the root constructor: null root, crash on first use. No graceful OOM path. ABORT ON OOM
dump_null passes Py_None without Py_INCREF dump_pyobject steals its argument and calls Py_DECREF. Passing the borrowed Py_None singleton without incrementing its refcount decrements None's refcount. In CPython None has a very high refcount and this is practically harmless, but it violates the ownership contract established by ac30e6cee2b2. UNGROUNDED / OWNERSHIP GAP
PyUnicode_DecodeUTF8 fails in dump_pyobject (key encoding failure) Returns null key. PyDict_SetItem(cursor, null_key, p) called without checking — undefined behavior, likely Python exception set, value not inserted, no abort. Caller sees a silent data loss. UNGROUNDED / SILENT FAILURE
Malicious plugin triggers reset() while sections are open reset() does not clear stack. Stale parent-cursor pointers remain in the stack pointing into the now-decref'd tree. A subsequent close_section() restores a dangling pointer to cursor. USE-AFTER-FREE RISK

Known divergences (commit message ≠ actual behavior)

Ungrounded paths (error policy not established by any commit)

  • PyUnicode_DecodeUTF8 failure in dump_pyobject — null key silently passed to PyDict_SetItem
  • PyDict_SetItem failure — return value unchecked in both dump_pyobject and convert_dict_to_proxy
  • PyTuple_New null in convert_list_to_tuple — loop proceeds with null tuple, PyTuple_SET_ITEM writes into null
  • PyDict_New null in convert_dict_to_proxy — loop proceeds with null dict
  • PyUnicode_FromString failure in finish_pending_streams — null passed to dump_pyobject → abort
  • reset() while stack is non-empty — stale parent-cursor pointers remain; use-after-free on next close_section()

6. Observability & Triage Playbook

Signals that PyFormatter is involved

  • ceph-mgr crash with ceph_abort_msg("PyFormatter::dump_pyobject received null PyObject") — null object reached the helper. Most likely culprit: non-UTF-8 bytes through dump_format_va.
  • ceph-mgr crash with bare ceph_abort() in the stack near PyFormatter — either a serializer method (flush/get_len/write_raw_data) was called, or cursor was in an unexpected state.
  • Python-side KeyError or missing field in plugin output with no crash — dump_string silently dropped a non-UTF-8 value (7c68a00cce5b divergence).
  • Python SystemError or ValueError referencing dict/tuple operations — unchecked allocation failure in the readonly conversion path.

Triage decision tree

crash in ceph-mgr Python thread?
  ├── abort "received null PyObject"
  │     → check if caller is dump_format_va with non-ASCII data
  │     → look for non-UTF-8 cluster/OSD metadata being formatted
  ├── bare ceph_abort() near PyFormatter
  │     → check call stack: flush/get_len/write_raw_data = caller misuse
  │     → cursor not list/dict = open/close mismatch; check section nesting
  └── Python exception (AttributeError, KeyError, TypeError) on mgr plugin
        → check if field is missing (dump_string silent drop)
        → check if PyFormatterRO fallback returned mutable object (plugin mutated cache)

missing field in mgr module output?
  → reproduce with string containing bytes 0x80-0xFF
  → if field absent: dump_string UTF-8 drop confirmed
  → temporary workaround: sanitize strings to ASCII before passing to formatter
