1. Architecture & Mental Model

One-Line Summary

MgrClient is a Messenger Dispatcher subclass that every Ceph daemon (OSD, MDS, MON, RGW, RBD mirror, plus external service daemons) embeds to maintain a single long-lived TCP session to the active ceph-mgr, report perf counters and daemon status on a timed cycle, and submit/receive management commands.

Roles Handled by One Class

  • Session Manager — owns the single MgrSessionState (connection + declared-counter set); tears down and rebuilds on failover.
  • Periodic Reporter — fires _send_stats() every stats_period seconds via SafeTimer; sends MMgrReport (perf counters + status + health + config delta) and MPGStats (OSD only).
  • Command Bus — queues start_command / start_tell_command in CommandTable<MgrCommand>; sends MMgrCommand (octopus+) or legacy MCommand; routes replies back to callers.
  • Service Daemon Registry — lets non-core services call service_daemon_register() to appear in the mgr's ServiceMap.
  • MON Metadata Updater — update_daemon_metadata() + _send_update() path for MONs that need to push metadata post-session-open.

Concurrency Model

  • Single ceph::mutex lock protects all mutable state. All methods that touch shared state assert ceph_mutex_is_locked_by_me(lock).
  • SafeTimer fires callbacks under lock — timer lambda and _send_stats() require no re-acquisition.
  • ms_dispatch2() is called from the Messenger thread pool — acquires lock at entry.
  • Public API (start_command, send_pgstats, etc.) all acquire lock on entry.
  • reconnect() is lock-must-be-held (private); asserted with ceph_assert(ceph_mutex_is_locked_by_me(lock)). c93dc8849145

2. Architectural Decisions & Trade-offs

DecisionWhat was chosenWhy not Y?Commit(s)
Single session, not connection pool unique_ptr<MgrSessionState>; one active mgr connection at a time Mgr is a HA singleton — only one active mgr exists. A pool would waste resources and complicate failover bookkeeping. 4d1989dc229a
Connect throttling via last_connect_attempt + SafeTimer At most 1 connect per mgr_connect_retry_interval; deferred via connect_retry_callback Un-throttled reconnect after mgr failover would cause a thundering-herd storm (all OSDs hitting simultaneously). SafeTimer is already lock-associated — no extra thread needed. d902e5b76ed5
fsid as tell-command signal in MCommand Tell commands populate monmap->fsid in the message; CLI commands leave it null/zeroed Feature bits couldn't be used: a new client talking to an old mgr doesn't yet know if the mgr supports MMgrCommand. The fsid field was previously unused — repurposing it is backward-compatible. 6f35d2835268
MMgrCommand for octopus+, MCommand for older Dispatch gated on HAVE_FEATURE(map.active_mgr_features, SERVER_OCTOPUS) Dedicated mgr command message type allows the mgr to distinguish CLI vs. tell without the fsid hack. Legacy path kept for rolling upgrades. 0019005e87a0
Command queue instead of immediate failure when no session Commands enqueued in CommandTable; sent on next reconnect() Original code returned -ENOENT immediately. That broke callers that submitted commands during startup before the mgr was known. Queueing provides transparent retry. 6ff0857974ea 6ff0857974ea
mgr_optional mode / -EACCES on epoch==0 If mgr_optional && map.epoch == 0: return -EACCES immediately Pre-luminous clusters may never have a mgr. Blocking or queueing forever would deadlock. The gate is only active when mgr_optional is explicitly set. bae47183c262
MMgrClose handshake on service daemon shutdown Shutdown sends MMgrClose, waits up to mgr_client_service_daemon_unregister_timeout for mgr ack Without the handshake, the daemon's entry in ServiceMap would linger until the mgr's health-check kicked it out, causing stale health warnings. 082a700ac80a
Abandon in-flight commands on premature shutdown command_table.clear() without invoking callbacks Originally asserted command_table.empty() — triggered on Ctrl-C. Silent drop is correct: the process is exiting. Callers must not depend on callbacks being invoked during shutdown. 8ca982f403b0
Perf counter undeclare on session reconnect / disappearance / threshold drop session->declared set; diff against PerfCountersCollection each cycle; undeclare removed/below-threshold counters Accumulating stale declarations on the mgr side would bloat its state. Undeclare messages allow the mgr to clean up without a full session reset. a46690c6230b, 88163749b572
Config: full snapshot on open, delta on each report _send_open() calls get_config_bl(0, ...); _send_report() calls get_config_bl(last_config_bl_version, ...) The mgr needs a complete config view when a new session starts. Sending the full config on every report would be wasteful for large configs — deltas keep the wire format small. d8450574cf48, 8e2a30068acc
dead flag to guard post-shutdown dispatches bool dead = false; set at top of shutdown(); checked first in ms_dispatch2() The Messenger may deliver messages after shutdown() (e.g., a queued MMgrMap) before the Messenger itself stops. Without the flag, this would trigger a new session on a shutting-down daemon. 7fd618c28895
Late-register path for CEPH_ENTITY_TYPE_CLIENT only service_daemon_register(): if mytype == CLIENT && session → call _send_open() immediately Non-CLIENT types (OSD, MDS) already send MMgrOpen unconditionally in reconnect(). The late-register path only applies to pure-client messengers (e.g., RBD mirror) that need to register as service daemons after connection. An earlier commit inverted the condition and was fixed within a week. fc60989bf7a7 → 13198b133fad 13198b133fad
update_daemon_metadata does NOT set service_daemon=true Only sets identity fields and calls _send_update() (MON path). Service daemon registration remains separate. MONs need to push metadata to the mgr but are NOT service daemons in the ServiceMap sense. Mixing the two paths caused a tracker issue (ceph#55322). 6540937a6d18 explicitly removed the service_daemon=true assignment. 6540937a6d18

Perf Counter Report Algorithm (per cycle)

_send_report() — called under lock:

1. Snapshot PerfCountersCollection via with_counters(cb)
2. For each counter path in snapshot:
   include_counter = adjusted_priority ≥ stats_threshold
3. Undeclare pass:
   a. Paths in session->declared NOT in snapshot → undeclare
   b. Paths in snapshot failing include_counter → undeclare
4. Declare pass:
   Paths passing include_counter NOT in declared → declare + add header
5. Encode counter VALUES into report->packed (ENCODE_START(1,1,...))
6. Append daemon_status if daemon_dirty_status
7. Append task_status if task_dirty_status
8. std::move(daemon_health_metrics) — always sent
9. Config delta: get_config_bl(last_config_bl_version, ...)
10. MetricReportMessage (OSD/MDS perf queries) if callback set

Key Invariants

  • Lock before state: all paths touching session, command_table, map, dirty flags require lock.
  • reconnect() requires lock held: asserted via ceph_assert(ceph_mutex_is_locked_by_me(lock)). c93dc8849145
  • stats_period = 0 on teardown: prevents orphaned timer reschedule after session destroyed. e3104862b84e
  • report_callback cancelled before session reset: prevents double-send on reconnect. 1643a7fc6074
  • dead set before any other shutdown action: ensures concurrent ms_dispatch2 sees it under lock. 7fd618c28895
  • session->con->mark_down() before session.reset(): drains in-flight messages before releasing state. eb5c02df634b
  • Callbacks abandoned on shutdown: command_table.clear() does NOT invoke on_finish. Callers must tolerate silent drop. 8ca982f403b0
  • Wire encoding version frozen at 1: ENCODE_START(1, 1, report->packed) — never updated since initial commit. 88442d2391ad

handle_mgr_close does not tear down local session MGR sends MMgrClose (ack); client sets service_daemon=false and signals shutdown_cond but does NOT reset session Stale connection object persists. If MGR does not subsequently send a new MMgrMap, client may attempt to send reports on a dead connection. Next MMgrMap triggers reconnect() and fixes state. UNGROUNDED — asymmetry not documented
Unbounded CommandTable growth Caller submits many commands while no mgr session exists; CommandTable grows without bound Each entry holds bufferlist inbl + vector<string> cmd. Large uploads will consume memory. No limit enforced. Mitigation: callers should timeout their own command submissions. No commit addresses this.
Known Regression (f82ab1cbf242, 2025-08-12): In start_tell_command(), name is moved into op.name before the dispatch check. The check name.size() == 0 || ... always evaluates true (moved-from string is empty), so tell commands targeting a non-active mgr are immediately sent to the wrong connection. The -ENXIO cancel fires on the next reconnect, not at send time.

Triage Scenarios

Scenario A: Daemon shows no metrics in ceph dashboard

  • Check stats_period — was MMgrConfigure received? If 0, the mgr has disabled reporting for this daemon.
  • Check for a live session: look for Starting new session with at level 4.
  • Check if stats_threshold is too high — counters below priority threshold are silently undeclared.
  • Verify initialized == true (MDS only) — init() must have been called.

Scenario B: Commands to mgr hang indefinitely

  • Check map.epoch in daemon state — if 0 and !mgr_optional, commands queue forever (no session will ever be created without a map).
  • If mgr_optional = true, map.epoch == 0 returns -EACCES immediately — caller may be suppressing errors.
  • Check connect_retry_callback presence — daemon may be in throttle backoff.
  • Check if dead = true — shutdown() was called; command_table.clear() silently dropped the command.

Scenario C: Service daemon persists in ceph status after process exit

  • Process exited without a live mgr session — MMgrClose not sent, ServiceMap entry lingers.
  • MGR will eventually expire the entry via health-check timeout.
  • Force-remove via ceph service rm <service> <daemon>.

Scenario D: Tell command returns -ENXIO unexpectedly

  • Likely: target mgr name ≠ active mgr at time of reconnect. The command was queued; on reconnect, the target was deemed wrong and cancelled.
  • Also possible (regression f82ab1cbf242): tell was sent immediately to the wrong mgr; mgr rejected it; on next reconnect the stale entry is erased with -ENXIO.

Scenario E: OSD crash with ceph_abort() in handle_config_payload

  • Mgr sent a MetricConfigMessage with an UnknownConfigPayload variant — indicates version skew between daemon and mgr.
  • Only occurs when metric_config_message branch is taken in handle_mgr_configure().
  • Fix: ensure mgr and OSD are on compatible versions.

Quick mental model for on-call: MgrClient is a stateful, lock-protected proxy to the active mgr. When in doubt, the answer is "it queues and retries on reconnect." The only permanent failures are: shutdown (dead=true), mgr_optional with epoch=0 (-EACCES), and the tell-command regression (f82ab1cbf242) which sends to the wrong mgr.
