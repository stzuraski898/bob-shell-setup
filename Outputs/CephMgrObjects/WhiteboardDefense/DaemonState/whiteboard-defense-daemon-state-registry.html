1 · High-Level Architecture & Mental Model

What it is: DaemonStateIndex is the ceph-mgr's in-process registry of all cluster daemon instances. It maps every live daemon (OSD, MDS, MON, RGW, plus third-party services) to a DaemonState object containing its metadata, config, perf counters, and device attachments. A parallel devices index inverts that relationship: physical storage devices → which daemons reference them.

┌─────────────────────────────────────────────────────────────────────────┐ │ ceph-mgr process │ │ │ │ Daemon A ──MMgrReport──▶ ┌────────────────────────────────────────┐ │ │ Daemon B ──MMgrReport──▶ │ DaemonStateIndex │ │ │ Daemon C ──MMgrReport──▶ │ │ │ │ │ all: map<DaemonKey, DaemonStatePtr> │ │ │ │ ├─ {osd, "0"} ──▶ DaemonState ─┐ │ │ │ │ ├─ {osd, "1"} ──▶ DaemonState │ │ │ │ │ ├─ {mds, "a"} ──▶ DaemonState │ │ │ │ │ └─ {rgw, "x"} ──▶ DaemonState │ │ │ │ │ │ │ │ │ │ by_server: map<host, map<...>> │ │ │ │ │ │ │ │ │ │ devices: map<devid, DeviceRef> │ │ │ │ │ └─ "wwn-xyz" ──▶ DeviceState ◀──┘ │ │ │ │ daemons: {osd/0, osd/1} │ │ │ │ attachments: {(host,dev,path)} │ │ │ └────────────────────────────────────────┘ │ │ │ │ │ Python modules ─┘ (ActivePyModules) │ │ Dashboard / REST API / CLI │ └─────────────────────────────────────────────────────────────────────────┘

Lock Architecture — Two-Level Model

DaemonStateIndex::lock (ceph::shared_mutex) ├── Protects: all, by_server, devices index maps ├── Writers: insert, rm, _insert, _erase, _rm, update_metadata, cull, cull_services └── Readers: exists, get, get_by_service, get_by_server, with_* family, is_updating ↓ acquired AFTER index lock (never before — lock ordering) DaemonState::lock (ceph::mutex) ├── Protects: metadata, config_defaults, devices (per-daemon), hostname, perf_counters └── Writers: update_metadata (via set_metadata), _get_config_defaults callers

2 · Architectural Decisions & Trade-offs

Decision What was chosen Why not the alternative? Ground truth
Two-level locking
index-wide + per-entry mutex		 Global shared_mutex guards structure; per-DaemonState ceph::mutex guards fields Single global lock would serialize all perf-counter updates from all daemons — too coarse. Per-entry-only lock can't protect the index maps themselves during insert/erase. f236b5e7 (2017-07-19) — added per-DaemonState lock; 806f10847c (2017-08-24) — upgraded index to RWLock
Return by value, not reference
get_by_service, get_by_server, with_daemons_by_server		 Callers receive a copy; no obligation to hold the index lock during use Returning a reference forces callers to hold the lock for an indefinite duration (incl. Python callbacks) causing priority inversion and GIL deadlocks 806f10847c comment: "returns by value to avoid callers holding lock"; GIL deadlock fix b4304d521f (tracker#72337)
Atomic remove-update-reinsert in update_metadata _rm → set_metadata → _insert under single exclusive lock acquisition Separate lock acquisitions would create a window where the daemon disappears from all indexes — Python modules polling between those windows would see phantom absences 8a2f4429b1: "Do the whole thing under the DaemonState lock so there isn't a window where the osd metadata isn't present at all"
Lazy decode of config_defaults_bl Bufferlist stored encoded; decoded into config_defaults map on first access (_get_config_defaults) Eager decode on every session open would pay ~50 kB decode cost unconditionally; most sessions never query config defaults 86cf85e0a2 (2018-01-05) — deferred decode; 1c2bc53df7 (2018-10-17) — renamed to _get_config_defaults to signal lock requirement (tracker#36590)
DeviceState::empty() as prune sentinel Device pruned from index only when both daemons.empty() AND metadata.empty() Pruning on daemons.empty() alone would discard persistent device metadata (life expectancy, wear level) loaded from config-key store even when no daemons currently reference the device 45d4dfed1d (2018-06-05)
Private constructor + FRIEND_MAKE_REF on DeviceState Only ceph::make_ref<DeviceState>() can construct; constructor private Public constructor allowed incorrect initial refcount, causing premature deallocation crashes 0b14f926ec (2018-11-08) — initial refcount bug; 517bdca529 (2019-02-06) — private constructor enforcement
DaemonKey as named struct struct DaemonKey { string type; string name; } pair<string,string> required .first/.second at all use sites — opaque and error-prone; struct provides named fields, natural ordering, and a stream operator 5aac7eba36 (2019-09-29)
with_daemons_by_server copies map before callback Snapshot under shared lock; callback runs on snapshot without lock Earlier: callback ran under lock — if callback entered Python interpreter, held the index lock while the GIL was needed, producing deadlock under high mgr load b4304d521f (2025-07-31, tracker#72337)
devices and devices_bypath cleared at top of set_metadata Both maps cleared before re-parsing every metadata update Without the clear, stale device entries would persist when a daemon's disk set changes (e.g., disk replacement); callers would see phantom devices c52fc7b5d3 (2018-10-18)
Life-expectancy stored in both typed fields and metadata map Both life_expectancy pair (in-memory fast path) and metadata["life_expectancy_min/max/stamp"] (persistence path) updated atomically in set_life_expectancy Earlier, only typed fields were updated — predictions were forgotten on mgr restart because the config-key store read back empty strings 78b72b0be7 (2021-02-08, tracker#49215)

Critical Invariants

#InvariantEstablished
I-1 Lock ordering: always DaemonStateIndex::lock → DaemonState::lock. Never reversed. 8a2f4429b1 / 675606bf71
I-2 No stale devices on metadata refresh: devices and devices_bypath cleared before re-parse in set_metadata(). c52fc7b5d3
I-3 Index consistency: if all contains a key, by_server and devices are consistent with it. Enforced by _insert/_erase always updating all three atomically under exclusive lock. 38afbae026
I-4 No phantom absence: update_metadata() holds exclusive lock across _rm→set_metadata→_insert; daemon is never absent from index during update. 8a2f4429b1
I-5 Device pruned only when truly empty: empty() = daemons.empty() && metadata.empty(). Device survives if it has persistent metadata even with no daemon references. 45d4dfed1d
I-6 Life-expectancy persistence: both in-memory typed fields and metadata map updated atomically in set_life_expectancy(). Serialised as stringify(t) (non-zero) or "" (zero) — not "0.000000". 78b72b0be7
I-7 _get_config_defaults lock discipline: leading underscore = caller must hold DaemonState::lock. Same convention as _insert, _rm, _erase. 1c2bc53df7 (tracker#36590)
I-8 DeviceState construction via factory only: constructor private, FRIEND_MAKE_REF enforces correct initial refcount. 517bdca529
I-9 Blank device IDs are skipped during set_metadata() parsing. 7add8da7b0

Algorithm Notes

  • cull(svc, names_exist): O(k + v·log n) — lower_bound({svc,""}) scans only the service prefix, collects victims into vector<string>, then reconstructs DaemonKey for erase. Optimised by 0e7137aa6a.
  • get_by_service(svc): O(n) full linear scan of all — inconsistency vs. cull() which uses lower_bound on the same sorted map. Never optimised.
  • _get_or_create_device: single try_emplace call (517bdca529) — one map operation vs. the original find+insert two-step.
  • get_by_server: single find after f9a11737ea — was count()+at() (two lookups) before.

4 · Threat Model & Adversarial Handling

The ceph-mgr assumes authenticated daemons (messenger v2 auth). The threat model is primarily misbehaving or buggy daemons, not external attackers. The registry's attack surface is the MMgrReport message path and the Python module interface.

Actor / Scenario Attack Vector What happens Status
Malicious / buggy daemon sends metadata["hostname"] = "" update_metadata() → set_metadata() → _insert() by_server[""] bucket accumulates entries. All queries for server "" return these contaminated results. No assertion guards this. Silent corruption of by_server index. UNGROUNDED no empty-hostname guard in _insert()
Daemon sends corrupt config_defaults_bl Blob stored; decoded on first access by _get_config_defaults() buffer::error caught and silently swallowed (62382040ee). config_defaults remains empty. No log line. Caller sees empty config defaults with no indication of corruption. UNGROUNDED silent failure
Daemon sends metadata with device_ids containing spaces set_metadata() for_each_pair with delimiter ",; " Space is treated as field delimiter — device ID is silently truncated at the space. Device with space in WWN/serial would be split into two bogus entries. UNGROUNDED undocumented wire contract
Python module sends inverted life expectancy (from > to) set_life_expectancy(from, to, now) No assertion. Stored as-is. get_life_expectancy_str() would compute negative duration. Output would be nonsensical but not crash. OVERCAUTIOUS no from≤to guard
Python module sets wear_level = 999.0 with_device_write(id, cb) → set_wear_level(999.0) Only wear >= 0 checked; arbitrary float stored and persisted to config-key store. Dashboard would display 999.0. UNGROUNDED no upper-bound check
Daemon re-registers with same key after being culled insert(dm) when all.count(dm->key) > 0 _erase(key) called first, then _insert(dm). Idempotent; old entry fully replaced. No crash. OK
Two daemons register with the same key simultaneously Concurrent insert() calls Both acquire exclusive write lock sequentially. Second insert calls _erase on the first entry then inserts its own. Last writer wins. No data corruption. OK — 5b6037aeb4 fixed crash from multiple sessions with same name
Python callback blocks indefinitely in with_devices2(cbi, cb) Callback into Python while holding index shared lock GIL-vs-index-lock inversion identical to the one fixed in with_daemons_by_server (b4304d521f, tracker#72337). with_devices2 was not fixed. Extended shared lock hold blocks all writers. UNGROUNDED potential GIL deadlock
exists() + get() double-check pattern in callers Daemon removed between exists() (shared lock released) and get() (new shared lock) get() returns nullptr on miss (f9a4ca07ac). Callers that don't null-check after get() would dereference null. get() itself is safe; calling pattern is TOCTOU. OVERCAUTIOUS at API level — caller responsibility

5 · Failure Modes, Edge Cases & Blast Radius

Failure Trigger Blast Radius Recovery
get_all() data race Caller invokes get_all() while insert() or cull() is running get_all() copies all without holding lock — the copy is unprotected during a concurrent structural write. UB if the map is being modified. DIVERGED from 806f10847c intent. Only callers that take the shared lock themselves avoid this. Fix: add std::shared_lock to get_all().
Stale empty DeviceState after with_device_create Callback leaves device empty (no metadata set, no daemon attached) Device never pruned from devices index until next _erase of a daemon that references it. Memory leak of DeviceState proportional to number of such calls. Minor; no correctness impact. Fix: add empty() check post-callback in with_device_create.
Silent corrupt config defaults Corrupt config_defaults_bl from daemon _get_config_defaults() returns empty map. Python modules querying config defaults get silently empty results. Modules that enforce config rules see no defaults, potentially accepting invalid config values. No automatic recovery. Requires daemon reconnect with valid bufferlist. Add dout on catch to make visible.
Re-decode loop on empty-but-valid config defaults Daemon with zero config-default entries connects config_defaults.empty() stays true even after decode; every subsequent call to _get_config_defaults() re-decodes the bufferlist. CPU waste proportional to call frequency; no correctness impact. Pathological but possible. Fix: use a separate config_defaults_decoded bool flag.
GIL deadlock in with_devices2 Python module calls get('devices') while another thread holds the GIL and waits for index shared lock mgr ActivePyModules thread and the mgr main thread deadlock. mgr becomes unresponsive. Same root cause as tracker#72337 (fixed for with_daemons_by_server in b4304d521f). mgr restart required. Fix: copy devices map before releasing lock in with_devices2 (same pattern as b4304d521f).
Long exclusive lock in cull / cull_services Cluster map update with many stale daemons, or many service-daemon removals All readers (get, get_by_service, Python callbacks) block for duration of full scan + N×_erase under exclusive lock. Dashboard and REST APIs stall. Operational: keep service daemon counts low. Engineering fix: incremental cull or collect-then-release pattern.
by_server[""] contamination Daemon connects before metadata is set (hostname is "") by_server[""] accumulates entries. Queries for server "" return wrong results. list_devids_by_server("") returns all devices on all daemons with no hostname. Dashboard host view corrupted. Subsequent update_metadata() with correct hostname will _rm + _insert correctly. Self-heals on metadata arrival. Guard: assert non-empty hostname in _insert.
DaemonState outlives DaemonStateIndex Caller holds DaemonStatePtr past mgr shutdown perf_counters holds a reference to DaemonStateIndex::types. If DaemonStateIndex is destroyed first, the reference dangles. Use-after-free on any perf counter access. Enforced only by convention (all DaemonStatePtr owned by index). No RAII guarantee. Shutdown order must be correct.
Life-expectancy persistence forgotten on mgr restart Pre-78b72b0be7 behaviour (Historical, fixed) life_expectancy in-memory only; mgr restart cleared all predictions. Disk failure warnings silently disappeared after mgr failover. Fixed: 78b72b0be7 (tracker#49215) — both typed fields and metadata map updated atomically.
