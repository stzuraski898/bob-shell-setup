1 · High-Level Architecture & Mental Model

A per-counter, per-daemon ring-buffer of timestamped samples. The Ceph mgr daemon reads perf counters from OSDs/MONs/MDSs and holds recent history for Python plugin queries and the DaemonServer REST surface.

Ceph daemon (OSD / MON / MDS) mgr process ┌─────────────────────────┐ ┌──────────────────────────────────────────┐ │ PerfCounters (in-proc) │ │ DaemonState │ │ │ MSG/ │ ┌────────────────────────────────────┐ │ │ counter[N] │─ reports ─▶│ │ map<name, PerfCounterInstance> │ │ │ type: SCALAR │ │ │ │ │ │ type: LONGRUNAVG │ │ │ ┌──────────────────────────────┐ │ │ └─────────────────────────┘ │ │ │ PerfCounterInstance │ │ │ │ │ │ │ │ │ │ │ │ SCALAR path: │ │ │ │ │ │ buffer[20] ← push(t,v) │ │ │ │ │ │ avg_buffer capacity=0 │ │ │ │ │ │ │ │ │ │ │ │ LONGRUNAVG path: │ │ │ │ │ │ buffer capacity=0 │ │ │ │ │ │ avg_buffer[20]←push_avg(t,s,c)│ │ │ │ │ └──────────────────────────────┘ │ │ │ └────────────────────────────────────┘ │ │ │ │ │ Python plugins / REST │ └──────────────────────────────────────────┘ avg = s / c (c==0 is storable; caller must guard division) get_latest_*() → buffer.back() — UB if buffer is empty (D-2, D-3)

Lifecycle

  • Construct — PerfCounterInstance(type) sizes exactly one buffer to 20; the other stays at capacity 0.
  • Write — caller invokes push(t, v) (scalar) or push_avg(t, s, c) (avg). Oldest entry is silently evicted when full.
  • Read — consumers call get_data() / get_data_avg() for full history, or get_latest_data() / get_latest_data_avg() for the most-recent sample.
  • No destruction logic — RAII via boost::circular_buffer; no explicit destructor.

Provenance — "two lives" of this code

Logic was authored in src/mgr/DaemonState.h/.cc (2016–2018) and extracted verbatim into its own TU by 35f6dd06 (Max Kellermann, 2025-08-14) solely to reduce header-inclusion chains. Zero logic was changed during extraction.

2 · Architectural Decisions & Trade-offs

DecisionWhy this?Why not Y?Grounding
Single class, two mutually exclusive buffers
(one always capacity=0)		 One abstraction handles both SCALAR and LONGRUNAVG counter types; callers pass the type flag and get the right buffer. Two subclasses would require virtual dispatch or a variant; the codebase chose simplicity over type-safety. 1164ef2f (Boris Ranto, 2018-05-15) — added AvgDataPoint and branched the constructor.
boost::circular_buffer with hard-coded capacity=20 Fixed-size ring; O(1) push, O(1) eviction; no dynamic allocation on every update. Bounded memory per counter instance. A std::deque with manual trimming works but is not bounded by design. A ring-buffer makes overflow policy explicit. 9501bfdd (John Spray, 2016-07-26). Magic constant 20 has no documented rationale.
Silent eviction on overflow (oldest sample dropped) mgr needs recent data for dashboards; stale history is worthless. Dropping oldest preserves freshest view. Blocking / rejecting pushes would stall reporters. An error path adds complexity with no user-visible benefit. 9501bfdd — circular_buffer::push_back semantics; no overflow handler ever added.
Const-reference returns from all accessors Zero-copy read path. Python plugin and REST code iterate large sets; copying 20 DataPoints per counter per call would be expensive. Returning by value would be safe but wastes heap/stack with no benefit. 9501bfdd — original get_data() design; extended uniformly in 1164ef2f and b421142b.
No default constructor Forces the caller to provide a type flag. A zero-initialized instance with two capacity-0 buffers would be useless and silently discard all pushes. A default constructor + setter pattern would require a two-phase init hazard. 35f6dd06 — extraction preserved this; no default ctor was ever added.
Extraction to separate TU (35f6dd06) Breaks DaemonState.h's transitive pull of boost/circular_buffer.hpp and common/perf_counters.h into every includer. Compile-time dependency reduction. Keeping it in DaemonState.h was simpler but bloated downstream compilation. 35f6dd06 commit message: "To reduce header dependencies."
AvgDataPoint stores raw (s, c) rather than a float average Preserves exact integer precision; deferred division means callers control rounding. Avoids FP non-determinism in storage. Storing a double average would lose precision and make sum-of-averages aggregation incorrect. 1164ef2f — fields named s (sum) and c (count); underdocumented but intentional.

Buffer Invariants

InvariantSHAStatement
INV-1 Mutual exclusivity 1164ef2f Exactly one buffer has capacity=20. The other has capacity=0. Determined at construction; never changed after.
INV-2 Scalar buffer 9501bfdd buffer: boost::circular_buffer<DataPoint>, capacity=20. On overflow, oldest entry is silently evicted.
INV-3 Avg buffer 1164ef2f avg_buffer: boost::circular_buffer<AvgDataPoint>, capacity=20. Same eviction semantics. count==0 storable.
INV-4 Zero-copy reads 9501bfdd All accessors return const&. No copies made.
INV-5 back() precondition (unenforced) b421142b get_latest_data() / get_latest_data_avg() are only safe when the respective buffer is non-empty. No assertion exists.
INV-6 No default construction 35f6dd06 Type-branching constructor is the only construction path. Every instance is type-committed at birth.

4 · Threat Model & Adversarial Handling

Scope: PerfCounterInstance lives entirely inside the mgr process and is written only by the mgr daemon's own internal message-handling path. It is not directly reachable from network input. Threats come from incorrect internal callers.
Actor / ScenarioAttack VectorWhat HappensSeverity
Call push() on a LONGRUNAVG instance Caller passes wrong PerfCounterInstance to push() buffer has capacity=0; circular_buffer::push_back on a zero-cap buffer is a no-op silent discard. Data is lost; no crash, no assert. DATA LOSS
Call push_avg() on a SCALAR instance Symmetric to above Same silent discard. avg_buffer capacity=0 → push is no-op. DATA LOSS
Call get_latest_data() before any push() Race or ordering bug in caller; new instance queried before first sample arrives buffer.back() on empty circular_buffer → undefined behaviour (likely heap read of garbage). UB / CRASH (D-2)
Call get_latest_data_avg() on empty or SCALAR instance Same ordering bug, or calling on wrong type avg_buffer.back() on empty/zero-cap buffer → undefined behaviour. UB / CRASH (D-3)
Call get_current() Any caller; private but accessible to the class itself and friends Linker error at link-time (undefined reference). No body exists in .cc or anywhere in the TU. (D-1) LINK ERROR (D-1)
Push c=0 into avg_buffer Daemon reports a LONGRUNAVG counter with zero events Stored faithfully. Caller who computes s/c must guard for division-by-zero; no protection in this class. CALLER RISK
Overflow s or c (uint64_t wraparound) Extremely high-throughput counter running for years Silent unsigned wraparound. Each push_avg receives a snapshot; whether sum wraps is a daemon-side concern, not mgr's. LOW
Concurrent read+write Python plugin reads while mgr dispatch thread writes No mutex in this class. Thread-safety is the caller's responsibility (coordinated by DaemonState locking). CALLER MUST LOCK

UNGROUNDED Paths (undocumented design choices)

IDLocationRisk
U-1 Constructor — capacity 20 Magic constant; no documented rationale. A very fast counter could exhaust history in <1s at the poll rate. No mechanism to tune per counter type.
U-2 push() on wrong type No assertion; silent discard when buffer.capacity()==0. Data loss is invisible in logs.
U-3 push_avg() on wrong type Same as U-2 for avg_buffer.
U-4 get_data_avg() on SCALAR Returns a zero-capacity empty buffer. Callers iterating it are safe, but callers calling .back() on the returned ref trigger UB.
U-5 AvgDataPoint::s, ::c Field names terse and undocumented. "s" = sum, "c" = count only inferrable from context.

6 · Observability & Triage Playbook

Triage: "mgr crashed / corrupted state"

Suspect D-2 / D-3 first. If the crash is inside boost::circular_buffer::back(), the buffer was empty when get_latest_data() or get_latest_data_avg() was called. Check whether the counter received any push() calls before the read, and whether the instance type matches the accessor used.
SymptomLikely CauseCheck
mgr crash in circular_buffer::back() D-2 or D-3 — get_latest_data[_avg]() called on empty buffer Stack trace: is caller checking !buffer.empty()? Is the counter type correct for the accessor?
Counter metric shows all zeros / never updates U-2 / U-3 — push() called on wrong-type instance (silent discard) Verify instance was constructed with the right perfcounter_type_d flag. Instrument: add assert on buffer.capacity() > 0 before push.
Link error: undefined reference to PerfCounterInstance::get_current() D-1 — body was never implemented Remove the declaration from .h:52 or provide an implementation in .cc. Currently dead code; safe to remove.
Counter history looks stale / only last sample available U-1 — capacity=20 may be too small for the poll frequency Check polling interval vs. 20-sample window. History window = 20 × poll_interval_seconds.
Python plugin crashes computing average U-5 — caller computes s/c without guarding c==0 Inspect plugin code for division guard. Class stores c==0 without error.

Safe-Call Checklist (for callers)

  • Before get_latest_data(): assert / check !get_data().empty()
  • Before get_latest_data_avg(): assert / check !get_data_avg().empty()
  • Before iterating get_data_avg(): verify the instance was constructed with PERFCOUNTER_LONGRUNAVG
  • When computing average: guard against c == 0
  • Concurrent access: DaemonState-level lock must be held; this class has no internal synchronisation
