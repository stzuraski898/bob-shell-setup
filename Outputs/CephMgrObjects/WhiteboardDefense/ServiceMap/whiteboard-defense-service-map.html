1. High-Level Architecture & Mental Model

ServiceMap is Ceph's centralized, cluster-wide, wire-serializable metadata catalog for auxiliary service daemons (e.g., rgw, iscsi, cephfs-mirror, rbd-mirror) and non-standard reporting tasks across Ceph components.

Core Responsibility: Provides a two-level hierarchical dictionary (service_type → daemon_id → Daemon) tracked under a monotonic epoch. It exposes serialization primitives for Paxos persistence across Monitors/Managers and deterministic, aggregated status formatting for CLI/REST consumers (ceph -s, ceph versions).

2. Architectural Decisions & Trade-Offs ("Why X Instead of Y?")

Decision / Choice Alternative Considered Rationale & Grounding (Commit Citations)
Plain uint64_t gid = 0 boost::optional<uint64_t> Wire & API Stability: Commit 3e65551d deliberately reverted boost::optional from commit 5c25a018. An uninitialized or null optional crashed formatters dereferencing *gid and broke backward compatibility. A default 0 preserves value semantics and predictable encoding across cluster versions.
Aggregated Host/Zone Summaries Raw Daemon ID Enumeration (e.g. [gw1, gw2, ...]) CLI Scalability: Commit ab0d8f2 replaced individual daemon listing (from 394baa0) with aggregated host and zone sets (groupings). Large clusters with 100+ RGW or iSCSI gateways would blow out ceph -s terminal height.
std::pair<Daemon*, bool> try_emplace operator[] Lookup / Direct Insertion Mutation Awareness: Commit 3e65551d altered get_daemon() to return an insertion flag. DaemonServer needs to know whether an epoch increment and Paxos proposal are strictly required (new daemon arrival) or if it is updating an existing entry in-place.
Auto-Pruning Parent Services on Daemon Removal Retaining empty Service containers Zero-Leak Memory & Output Hygeine: Established in 7fce6382. When the last daemon in a service is unregistered (rm_daemon), the service key is erased immediately from services map. Prevents stale empty service headers from cluttering ceph -s and consuming manager heap.
Value Return for Test Fixtures Heap Pointers (std::list<T*>) ASan Leak Elimination: Commit ed6b7124 and f6387fd8 eliminated pointer-based test generators across Ceph. Prevents heap leaks in ceph-dencoder and CI unit test harnesses.
Legacy Format String for Addresses Full entity_addr_t protocol prefixes (v1:/v2:) Client Agnostic Presentation: Commit 671641df forced addr.get_legacy_str() in dump() because protocol versions are transport details; external scripts and dashboards expect standard host:port tuples.

3. Data Structures, Algorithms & Invariants

Container Types & Complexity

  • std::map<std::string, Service> services: O(log S) ordered lookup of services. Guarantees deterministic serialization and JSON output across Paxos runs.
  • std::map<std::string, Daemon> daemons: O(log D) per-service daemon mapping keyed by daemon identifier string.
  • std::map<std::string, std::string> metadata: Arbitrary string key-value attributes (e.g. hostname, ceph_version, daemon_type, zone_id).
  • std::map<std::string, std::string> task_status: Running task descriptors (e.g. scrub state) encoded under version ≥ 2.

Core Invariants

  • Strict Pruning Invariant: If services[svc].daemons.empty() is true after rm_daemon(), services.erase(svc) MUST be executed before return.
  • Encoding Layout Invariant: ServiceMap: epoch (u32) → modified (utime) → services (map).
    Daemon: gid → addr → start_epoch → start_stamp → metadata [→ task_status if v ≥ 2].
  • Entity Classification Invariant: is_normal_ceph_entity() returns true strictly for osd, client, mon, mds, mgr (79503fc).

4. Threat Model & Adversarial Handling

Adversarial Input / Behavior Failure Vector Mitigation / Defense in ServiceMap
High-frequency Daemon Churn (Flapping Registration) Map expansion and Paxos proposal flood get_daemon() uses try_emplace returning added boolean. If a daemon already exists, in-place updates avoid reallocating map nodes. (Epoch increments controlled upstream by DaemonServer).
Corrupted / Truncated Mon Wire Buffer Crash during cluster map decode Framed with DECODE_START(2, p) and DECODE_FINISH(p). Buffer overrun or missing version envelope throws ceph::buffer::malformed_input cleanly caught by Mon/Mgr dispatcher.
Oversized Daemon Metadata Injection Memory bloat in Mgr and Mon Paxos store Map storage is constrained to std::string key/value pairs. Upstream message decoders enforce maximum payload bounds; ServiceMap strictly iterates existing keys.
Missing Metadata Keys (e.g. absent version / host) Null pointer dereference or crash in status commands count_metadata() explicitly handles missing fields by incrementing the "unknown" bucket (80a42122). get_summary() defaults fallback daemon type to "daemon" (ab0d8f2).

5. Failure Modes, Edge Cases & Blast Radius

  • Mixed-Version Cluster Rolling Upgrades: Version 1 daemons/monitors decoding Version 2 payloads will ignore task_status without error because of DECODE_START(2) backward compatibility rule (compat version 1).
  • Empty Service Map: get_summary() returns "no daemons active" without string-stream allocation overhead (ee5835df). has_running_tasks() safely returns false via std::any_of empty check.
  • Missing Custom Summary: If Service.summary is empty, dynamically falls back to synthesized host/zone breakdown (ab0d8f2).
  • Memory Blast Radius: Pure in-memory dictionary. Memory consumption is directly proportional to O(S * D * (M + T)) where S = services, D = daemons, M = metadata entries, T = task entries.

6. Observability & Triage Playbook

Operator Commands & Inspection

  • ceph -s / ceph status: Invokes ServiceMap::Service::get_summary() and get_task_summary() for active daemon and scrub status.
  • ceph mgr dump / ceph service dump: Invokes ServiceMap::dump(Formatter *f) exporting full JSON representation with epoch, timestamps, legacy addrs, and metadata.
  • ceph versions: Invokes count_metadata("ceph_version", &out) across all service types.

Triage Diagnostics

# Dump full JSON ServiceMap state:
$ ceph service dump

# Verify daemon task status:
$ ceph tell mgr service status

# Check version distribution across daemons:
$ ceph versions

If a service disappears unexpectedly, verify whether rm_daemon() erased the final active daemon, triggering automatic container cleanup.
