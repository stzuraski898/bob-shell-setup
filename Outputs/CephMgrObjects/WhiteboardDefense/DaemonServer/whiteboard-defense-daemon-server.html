1. High-Level Architecture & Mental Model

DaemonServer is the active Ceph Manager's network endpoint, protocol front-door, and cluster aggregation engine. It hosts the Messenger interface for incoming Ceph daemon heartbeats, telemetry reports, PG statistics, client commands (ceph tell mgr ...), and admin socket diagnostics.

Core Responsibilities
  • Telemetry Ingestion: Ingests high-frequency MSG_PGSTATS and MSG_MGR_REPORT from all OSDs and MDSs without global head-of-line blocking.
  • Daemon State & Connection Index: Maps live daemons to connections (osd_cons, daemon_connections, DaemonState).
  • Admin & CLI Gateway: Validates capability strings via MgrCap, authorizes, and routes commands (JSON/Plain) to Python modules or native handlers.
  • Cluster Autoscaling & Sync: Runs the periodic adjust_pgs() engine and sends cluster summaries (send_report()) to MONs.
Key Boundary Protocols
  • MSG_MGR_OPEN / MSG_MGR_CLOSE: Daemon session establishment and lifecycle teardown.
  • MSG_PGSTATS: Per-PG placement group statistics updates.
  • MSG_MGR_REPORT: Metric reports, daemon performance counters, and health metrics.
  • MSG_COMMAND / MSG_MGR_COMMAND: Operator/client management requests.
  • MMgrConfigure: Downstream metric collection configurations pushed to OSDs/MDSs.

3. Data Structures, Algorithms & Invariants

Lock Ordering & Hierarchy Rules
  1. Messenger Connection Lock (Internal): Managed by Simple/AsyncMessenger. Never acquire DaemonServer::lock inside fast messenger callbacks (ms_handle_fast_authentication).
  2. DaemonServer::lock (Global Mutex): Protects osd_cons, daemon_connections, pending_service_map, and safe timer scheduling.
  3. daemon->lock (Per-Daemon Mutex): Nested strictly inside DaemonServer::lock. Protects individual daemon metadata and metrics.
  4. Finisher Queue Decoupling: Metric updates (OSD/MDS perf queries) dispatch via Finisher threads to break collector vs server lock cycles.
Core In-Memory Data Structures
  • std::map<int, std::set<ConnectionRef>> osd_cons: Direct OSD ID to active Messenger connection map.
  • std::set<ConnectionRef> daemon_connections: Broadcast set for config pushes (MMgrConfigure).
  • std::set<int> reported_osds: Ephemeral set tracking bootstrap OSD reports before pgmap_ready.
  • StatsAutotuner stats_autotuner: PI-style rate regulator monitoring dispatch queue backlog.
  • OpTracker op_tracker: Live telemetry tracker for in-flight/slow mgr commands.

6. Observability & Triage Playbook

Live Admin Socket Diagnostics (asok)

Admin socket commands registered in DaemonServer::init() (66efcaae7a05):

  • ceph daemon mgr.<id> dump_ops_in_flight: Inspect hung commands/reports.
  • ceph daemon mgr.<id> dump_blocked_ops: Identify lock contention points.
  • ceph daemon mgr.<id> dump_historic_slow_ops: Analyze trailing slow telemetry.
  • ceph daemon mgr.<id> dump_pg_ready: Check boolean bootstrap status.
Key Log Patterns for Triage (ceph-mgr.log)
  • "unauthorized command name=... caps=..." → Auth capability rejection (4085eb475328).
  • "rejecting report from non-daemon..." → Malicious/misconfigured client (612747e97bdd).
  • "auto-tuning stats period from X to Y" → Dispatch queue under load (027a609a8274).
  • "adjust_pgs: pool X pg_num Y -> Z" → Active autoscaling decisions.
