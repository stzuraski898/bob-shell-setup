1 · High-Level Architecture & Mental Model

One-Line Contract

PyModule is the plugin descriptor and lifecycle manager for a single Ceph Manager Python plugin. It loads the module into an interpreter context, interrogates its static metadata (commands, options, notify subscriptions), evaluates runnability, and exposes that metadata to the registry — without executing any plugin logic itself.

Two-Class System

PyModule

  • Owns the interpreter thread state (SafeThreadState pMyThreadState)
  • Holds pClass, pStandbyClass, pPickleModule
  • Stores extracted metadata: commands, options, notify_types
  • Tracks five boolean flags: enabled, always_on, loaded, can_run, failed
  • Owns per-module perf counters (PerfCounters* perfcounter)

PyModuleConfig

  • Holds in-memory cache of module KV configuration (std::map<string,string> config)
  • Writes changes through to monitor via MonClient
  • Updates local cache only after monitor confirms success
  • Protected by its own ceph::mutex lock

Algorithms

walk_dict_list (6c8fba975831)

  • Linear scan of a PyList attribute on pClass
  • Type-checks each element as PyDict
  • Invokes callback; short-circuits on first non-zero return
  • Guaranteed Py_DECREF(command_list) on all paths

load_subclass_of

  • Imports mgr_module → extracts base class by attribute name
  • Imports plugin module by module_name
  • Iterates module __dict__ values, filtering: PyType_Check AND PyObject_IsSubclass AND not identical to base
  • Keeps first match; logs error if multiple found
  • Memory fix: c1614fe7b893 decref'd mgr_module_type on all paths

py_bytes_{as,from}_{span,vec} (f69069e114ea)

  • Zero-copy span view (py_bytes_as_span) vs. owning vector copy (py_bytes_as_vec)
  • Used to marshal pickle-serialized objects across subinterpreter boundaries

Module State Machine

UNLOADED │ load() called ├── error in subclass/cmds/opts → loaded=false, error_string set └── success → loaded=true │ ├── can_run()=false → can_run=false (module won't be activated) └── can_run()=true → can_run=true │ ├── set_enabled(true) / always_on → enabled └── fail(reason) called → failed=true

Config Key Format

global_key = "mgr/" + module_name + "/" + key    ← e.g. "mgr/dashboard/ssl_port"

Persisted via: {"prefix": "config set/rm", "who": "mgr", "name": global_key}

4 · Threat Model & Adversarial Handling

Actor / Scenario Attack Vector Mitigation Residual Risk
Malicious plugin module Python plugin raises arbitrary exception during load(), can_run(), COMMANDS inspection handle_pyerror() catches and formats all Python exceptions. Failure sets error_string + returns error code. Module descriptor survives with loaded=false. No crash isolation — an exception during load() can corrupt interpreter state if not normalized. PyErr_NormalizeException added in dee598087a37 mitigates unnormalized exceptions.
Plugin with infinite loop in module body Top-level module code blocks during PyImport_ImportModule() None — load() holds the GIL and will block indefinitely. Switched from PyImport_ImportModuleNoBlock to PyImport_ImportModule (a89074c6bee9) as former was deprecated with no safety guarantee. HIGH. A hung plugin blocks the entire manager load path.
Plugin with malformed COMMANDS list Non-list, non-dict, or missing cmd/perm keys in COMMANDS walk_dict_list validates list type and dict type per element; returns -EINVAL on type mismatch, causing load() to fail and module to stay unloaded. Missing individual keys within a valid dict are not validated — they return empty string silently.
Plugin with multiple MgrModule subclasses Ambiguous class resolution in load_subclass_of Logs an error, keeps only the first encountered subclass. Does not abort. Wrong class may be selected — behavior undefined by plugin author intent.
Cross-subinterpreter object leak PyObject* from one subinterpreter referenced in another All cross-interpreter data serialized via pickle to std::vector<std::byte> and re-deserialized. Span/vec conversion utilities enforce this path. Introduced f69069e114ea. Depends on plugins calling dispatch_remote correctly; not enforced in plugin Python code.
Config injection via monitor Attacker modifies monitor config store for mgr/<module>/<key> Config values come from monitor — trust boundary is at the monitor, not here. PyModule trusts the monitor unconditionally. No validation of config values — a malicious monitor can inject arbitrary strings to module config.
Race on fail() vs is_failed() Concurrent read/write of failed and error_string Both paths acquire std::lock_guard l(lock). Thread-safe. None.
Race on set_enabled() Concurrent write to enabled without lock Callers in PyModuleRegistry use external synchronization. Documented as UNGROUNDED — design relies on callers. Medium: if external synchronization breaks, enabled write races with is_enabled() lock-guarded read.
NotImplementedError crash dumps Remote dispatch raises NotImplementedError (expected in standby mode) handle_pyerror(crash_dump=false) skips crash dump generation for this case. Added 18c4e08ccddd. None.

Python GIL Protocol

  • All Python object operations require GIL. PyModule::~PyModule() acquires it via SafeThreadState before decref'ing pClass, pStandbyClass, pPickleModule.
  • get_typed_option_value() documented as requiring GIL on entry — enforced by contract (c4e2965a4b83), not by code assertion.
  • init_ceph_module(): PyType_Ready failures abort the process — no partial type state can be recovered.

5 · Failure Modes, Edge Cases & Blast Radius

⚠ CONFIRMED BUG (DIVERGED) — ~PyModule() destructor
Line PyModule.cc:816: if (use_main_interpreter) { Py_EndInterpreter(pMyThreadState.ts); }
Intent (from 239b0dc8a9c4): call Py_EndInterpreter only for subinterpreters (if (!use_main_interpreter)).
Actual behavior: calls Py_EndInterpreter on the main interpreter thread state — which terminates the shared interpreter, crashing the process — while leaking memory for subinterpreter thread states.
Blast radius: Process crash on destruction of any main-interpreter module. Memory leak on destruction of subinterpreter modules.
⚠ UNGROUNDED — PyModuleConfig copy constructor
PyModuleConfig(PyModuleConfig&) at line 237 copies mconfig.config without locking mconfig.lock.
Relies on caller ensuring exclusive access before copy. No assertion enforces this.

Bottlenecks

  • GIL contention at load time: load() holds the GIL through all Python import and inspection calls. With many modules, load is serialized.
  • Monitor round-trip on config write: set_config() blocks waiting for monitor confirmation — synchronous on the calling thread.
  • Pickle serialization overhead: Every cross-subinterpreter remote call serializes/deserializes through pickle — linear in object graph size.

1. Is module loaded?          ceph mgr module ls  →  check 'available' / 'enabled' columns
