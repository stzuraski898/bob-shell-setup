§1 High-Level Architecture & Mental Model

What it is

MDSPerfMetricCollector is the MDS-specific concrete implementation of the MetricCollector<Q,L,K,M> CRTP-like template. It sits inside ceph-mgr and bridges the MDS daemon world (raw MDSMetricPayload messages) to the Python plugin world (ceph fs perf stats). Two things are MDS-specific that the base does not handle: (a) delayed-rank tracking — which MDS ranks are lagging their metric delivery; and (b) last-update timestamp — monotonic clock snapshot used by ceph fs perf stats to detect rank-0 failover (c2470f27 / tracker #50033).

§2 Architectural Decisions & Trade-offs

Counter replacement algorithm (lambda)

// stateless, called per (query, key, counter-index) triple by process_reports_generic
[](PerformanceCounter *counter, const PerformanceCounter &update) {
    counter->first  = update.first;   // absolute value (e.g. avg latency numerator)
    counter->second = update.second;  // absolute count / denominator
}

Why not deltas? MDS sends its current internal counter snapshot; the mgr stores the most recent values so queries always return the latest sample. OSD-style delta accumulation would require subtraction state and is not the MDS reporting contract.

§5 Failure Modes, Edge Cases & Blast Radius

DIV-1/DIV-2 — Uninitialized last_updated_mono Before the first process_reports() call, any path that calls get_last_updated() reads uninitialized POD memory. Blast radius: Python ceph fs perf stats receives a garbage utime_t and may erroneously flag MDS as offline or stale immediately after mgr startup. Fix: add last_updated_mono{} to the constructor MIL.
UG-5 — Error path leaves collector partially initialized On get_counters() failure (r≠0), c→delayed_ranks and c→last_updated_mono are not cleared or documented. A caller that doesn't check the return value will use stale or garbage data silently.
UG-4 — Unchecked static_cast If a wrong PerfCollector subtype is passed to get_counters(), the static_cast silently produces an invalid pointer. Downstream writes corrupt memory. No assert or null-check exists.

Bottleneck

  • Single mutex for all operations. Both process_reports() (writer) and get_counters() (reader) serialize on the same inherited lock. With many active queries or high MDS report rates, this becomes a contention point. No reader-writer lock upgrade has ever been attempted.
  • Full delayed_ranks copy on every get_counters(). The set is copied by value. For filesystems with many MDS ranks, this copy runs under lock.
