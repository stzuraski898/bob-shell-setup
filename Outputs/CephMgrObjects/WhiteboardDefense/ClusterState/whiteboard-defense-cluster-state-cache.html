ClusterState — Whiteboard Defense

Central cluster-wide state aggregator & in-memory synchronized map cache for ceph-mgr

Source: src/mgr/ClusterState.cc / .h Scope: ceph-mgr Core Concurrency: Single Mutex + External RWLock Corpus Span: 71 Non-Merge Commits

1. High-Level Architecture & Mental Model

ClusterState acts as the single source of cluster-wide truth inside the active ceph-mgr daemon. It ingests asynchronous updates across multiple control planes (Mon digests, OSD stats, OSDMap epochs) and provides thread-safe accessors (via callback templates) to Python plugins, internal telemetry, and CLI services.

Key Ingestion Pathways

  • load_digest(MMgrDigest*): Replaces health and mon status JSON bufferlists under lock.
  • ingest_pgstats(ref_t<MPGStats>): Accumulates PG stats, pool statfs, and OSD heartbeats into pending_inc (O(1) buffer push, no full apply).
  • update_delta_stats() & notify_osdmap(): Batched execution point where pending_inc is applied to pg_map and reset.

Read & Consumption Interface

  • Synchronized Callback Model: with_pgmap(), with_fsmap(), with_mgrmap(), with_servicemap(), with_health() execute callbacks while holding lock.
  • Delegated Reader: with_osdmap() bypasses ClusterState::lock to avoid lock inversion with Objecter.
  • Composite Reader: with_osdmap_and_pgmap() strictly locks ClusterState::lock first, then Objecter's lock.

3. Data Structures, Algorithms & Invariants

Core Member Layout

  • ceph::mutex lock: Single recursive-free mutex named "ClusterState" guarding all maps except OSDMap.
  • PGMap pg_map: Full authoritative snapshot of all Placement Groups, pool utilization, and per-OSD stats.
  • PGMap::Incremental pending_inc: Ephemeral delta buffer accumulating updates between tick() cycles.
  • std::map<int64_t, unsigned> existing_pools: Fast lookup cache mapping pool_id -> pg_num.
  • FSMap fsmap & MgrMap mgr_map & ServiceMap servicemap: Cached cluster service topologies.
  • bufferlist health_json, mon_status_json: Raw JSON buffers received from Monitor digests.

Locking Order & Concurrency Hierarchy

  1. ClusterState::lock Alone: Acquired by load_digest, ingest_pgstats, set_*, and simple with_* readers.
  2. Composite Lock Ordering: with_osdmap_and_pgmap mandates: 
    1. std::lock_guard l(lock);      // ClusterState
2. objecter->with_osdmap(cb...); // Objecter rwlock
    Never acquire in reverse order anywhere in Ceph codebase.
  3. OSDMap Delegation: with_osdmap acquires only Objecter::rwlock.

Critical Structural Invariants

  • [INV-1] Monotonic PG Stat Versioning: In ingest_pgstats, an incoming stat for pgid is discarded if pg_map.pg_stat[pgid].get_version_pair() > pg_stats.get_version_pair(). Lookup MUST use .find() (Commit ae688fc4d72c) to avoid default insertion.
  • [INV-2] Pool Boundary & Orphan Truncation: PG updates where pgid.pool() ∉ existing_pools or pgid.ps() >= existing_pools[pool] are silently discarded (Commit 9e906733fe07), preventing ghost PGs after pool shrinkage or deletion.
  • [INV-3] Delta Epoch Sequencing: Before calling pg_map.apply_incremental(), pending_inc.version MUST be explicitly stamped to pg_map.version + 1 (Commit d6d1db62edeb).
  • [INV-4] Incremental Evacuation: Immediately following pg_map.apply_incremental(), pending_inc MUST be assigned a fresh PGMap::Incremental() to guarantee idempotency across clock ticks (Commit aad1afcb96de).

4. Threat Model & Adversarial Handling ("What If an Actor Behaves Maliciously?")

Adversarial Vector / Fault Trigger Scenario System Defense & Containment Blast Radius Limit
Rogue / Desynchronized OSD OSD flooded with old or fabricated PG reports for deleted pools or invalid PG numbers (e.g. after pool deletion or split/merge). ingest_pgstats filters all reports against existing_pools map. Any PG with ps() >= pg_num or unknown pool ID is dropped and logged at dout(15). Zero state corruption; bad records discarded at ingestion boundary before reaching pg_map.
Out-of-Order UDP/TCP Messages Network re-ordering delivers an older MPGStats packet after a newer one was already processed. Version comparison checks (reported_epoch, reported_seq) pair against existing pg_map.pg_stat. Stale versions are ignored. Zero regression; authoritative PG state monotonically advances.
Dead / Stale Heartbeat Flood OSD daemon hangs or network partitions, leaving old heartbeat ping records in memory indefinitely. asok_command("dump_osd_network") validates timestamps against osd_mon_heartbeat_stat_stale (default 1h) and skips last_update == 0 entries. Admin telemetry filters stale nodes; output reflects verified active mesh only.
Out OSD Stat Metric Distortion OSD is marked OUT by monitor but continues sending storage utilization metrics. ingest_pgstats queries with_osdmap(osdmap.is_in(from)). If false, it substitutes an empty_stat while keeping only seq. Cluster capacity calculations remain accurate; out disk space is excluded from allocation calculations.
Admin Socket Injection / Fuzzing Malformed arguments or negative values passed to dump_osd_network CLI. Wrapped in try ... catch (bad_cmd_get) returning -EINVAL; negative values clamped to 0; unrecognized commands abort safely via registration validation. Manager daemon protected from unhandled exceptions; error string returned to admin socket.

5. Failure Modes, Edge Cases & Blast Radius ("Where Does This Fail?")

Critical Lock Inconsistency (DIVERGED Finding):
notify_osdmap() contains assert(ceph_mutex_is_locked(lock)) (Commit 03a761c980a1), but update_delta_stats() lacks this assertion despite mutating identical structures (pg_map, pending_inc). Any external caller invoking update_delta_stats() without acquiring ClusterState::lock will cause undetected data corruption in production builds.
Mutable Escape Hatch Risk (UNGROUNDED Finding):
with_mutable_pgmap() (Commit 86f0b811882d) exposes a direct non-const reference to pg_map. Callers that mutate internal PG collections directly bypass pending_inc tracking, making delta accounting desynchronized until the next full sync.
Failure Point / Bottleneck Root Cause & Mechanism Blast Radius & Mitigation
Lock Contention on ClusterState::lock Heavy active Python plugins (e.g. Dashboard + Prometheus polling with_pgmap() every second) competing with high-frequency ingest_pgstats from 5000+ OSDs. High lock hold times cause latency in mgr message dispatch loop. Mitigation: Keep callbacks short; never perform I/O or sleep inside with_* callbacks.
Double Call to final_init() asok_hook allocated via raw new ClusterSocketHook(this) with no null-check or guard. Leaks the first hook object; second registration assertion fails with ceph_assert(r == 0), terminating the mgr. Mitigation: Invoke only once during mgr startup sequence.
Return Code Divergence in Socket Hook ClusterSocketHook::call() returns asok_command(...) which returns boolean true (cast to int 1). Standard conventions treat 0 as success. AdminSocket dispatcher interprets non-negative return as success, so CLI does not break, but error code propagation is technically non-standard.
Memory Spike on Debug Logging Historically, setting debug level to 30 caused JSON serialization of pg_map on every tick. Resolved in 0bac6af3c18a by guarding JSON serialization with if (!pending_inc.empty()).

6. Observability & Triage Playbook

Diagnostic Logging & Subsystems

  • Subsystem: ceph_subsys_mgr (configured via debug_mgr).
  • Level 10 (dout(10)): Tracks incremental version increments: 
    mgr update_delta_stats v48291
  • Level 15 (dout(15)): Discarded / filtered PG stat telemetry: 
    mgr ingest_pgstats got 2.14 reported at 120:4 but pool not in existing_pools
mgr ingest_pgstats got 3.8 reported at 120:4 but > pg_num 4
  • Level 20 (dout(20)): Timed-out heartbeat ping removals.
  • Level 30 (dout(30)): Full JSON formatted pending_inc dump (only when active).

Runtime Inspection Commands

  • Dump Network Ping Times (Microseconds/Milliseconds): 
    ceph daemon mgr.<id> dump_osd_network [min_threshold_ms]
    Outputs sorted bidirectional 1m, 5m, 15m heartbeat ping metrics between all OSD pairs.
  • Verify Pool & PG Map Cache State: 
    ceph daemon mgr.<id> perf dump mgr
  • Detect Daemon Liveliness / Stuck Locks: 
    ceph daemon mgr.<id> status
    If commands hang, attach with GDB to inspect thread backtraces on ClusterState::lock.
