1. High-Level Architecture & Mental Model

OSDPerfMetricCollector is the specialized, thread-safe aggregator in ceph-mgr that arbitrates dynamic client I/O workload and performance metric queries sent to OSD daemons. It bridges high-level consumers (mgr modules like stats, Prometheus exporter, CLI/REST) and hundreds/thousands of low-level OSDs pushing periodic binary report bufferlists via MMgrReport.

Core Operational Flow:

  • Query Registration: Consumer registers a query (e.g. per-client or per-pool IOPS/bandwidth) via add_query(). If the query is new or limited, the collector notifies DaemonServer via MetricListener::handle_query_updated() to broadcast active queries to OSDs via MMgrConfigure.
  • Daemon Reporting: OSDs execute the query locally on live I/O paths, pack performance counters into raw binary bufferlists, and push them upstream in periodic MMgrReport messages.
  • Ingestion & Aggregation: process_reports() unpacks raw bufferlists and performs multi-OSD additive delta accumulation (+=) across all reporting OSDs for the matching (query_id, entity_key) slot.
  • Consumer Retrieval: Consumer calls get_counters(), which executes a thread-safe drain-and-reset operation (moves collected metrics into caller space and resets internal accumulator to zero).

2. Architectural Decisions & Trade-offs ("Why X instead of Y?")

Decision Choice (X) Alternative Rejected (Y) Defense & Rationale
Class Hierarchy & Code Reuse Thin subclass inheriting from parameterized template MetricCollector<Query, Limit, Key, Report> [efcebe1e] Standalone, duplicated query management implementation per daemon subsystem (MDS/OSD/RGW). Eliminated ~197 lines of duplicated query tracking, limit calculation, and thread synchronization across OSD and MDS collectors. Concentrates lock management and memory layouts into a single verifiable base template.
OSD Aggregation Arithmetic Additive delta accumulation (+=) in report update lambda [efcebe1e], [438a3f7b] Absolute value overwrite (=) as used in MDSPerfMetricCollector [f6ba1eea]. OSDs partition object data (PGs). A single client/pool workload is striped across hundreds of OSDs. The mgr receives individual per-OSD delta reports and must sum them across all OSDs to compute the total cluster-wide metric. In contrast, MDS rank metrics are authoritative per rank.
Counter Ingestion Lifetime Contract Drain-and-Reset (move semantics + clear()) during get_counters() [438a3f7b], [7523aef6] Cumulative monotonically increasing counter registers that are never cleared. Avoids unbounded memory growth in mgr when transient client keys disconnect. Prevents 64-bit integer rollover issues for high-throughput rate counters over long periods. Offloads rate calculation to consumers (Prometheus/Python).
Descriptor Matching Strictness Full equality matching via PerformanceCounterDescriptor::operator!= [b1f12671] Type-only matching (desc->type == query->type) [438a3f7b]. Protects against mixed-version daemon clusters or schema upgrades where two counter descriptors share a metric type code but differ in internal representation, units, or packing schema. Prevents binary bufferlist corruption.
Dynamic Variant Dispatch std::get<OSDMetricPayload> on MetricPayload variant [d8141f43] Virtual method polymorphism on payload structs or C-style void pointers. Value-semantic variant avoids heap allocation/indirection on high-frequency MMgrReport message dispatch paths. Migrated from boost::variant to std::variant in [d8141f43] to eliminate third-party dependencies.
Notification Outside Critical Section Drop lock before invoking listener.handle_query_updated() [efcebe1e] Hold lock across the MetricListener callback. Prevents ABBA deadlocks between OSDPerfMetricCollector::lock and DaemonServer::lock or ClusterState::lock when DaemonServer pushes new configs or acquires downstream subsystem locks.

3. Data Structures, Algorithms & Invariants

Key Data Structures

  • Queries (std::map<OSDPerfMetricQuery, std::map<MetricQueryID, std::optional<OSDPerfMetricLimit>>>): Multi-tenant query registry. Maps canonical query configurations to all active consumer subscriptions and their individual limits.
  • Counters (std::map<MetricQueryID, std::map<OSDPerfMetricKey, PerformanceCounters>>): Aggregated metrics matrix. Primary index is consumer MetricQueryID; secondary index is entity OSDPerfMetricKey (e.g., client IP/ID, pool ID); value is a std::vector<std::pair<uint64_t, uint64_t>> representing raw counter pairs (count, sum/latency).
  • ceph::mutex lock: Mutual exclusion primitive initialized via ceph::make_mutex("OSDPerfMetricCollector::lock") [c93dc884] guarding all mutations to queries and counters.

INV-GC-3 438a3f7b, efcebe1e Atomic Drain-and-Reset: On successful get_counters(), the entire sub-map counters[query_id] is transferred out via std::move() and immediately clear()ed under lock. Consecutive calls return empty data until new reports arrive.

4. Threat Model & Adversarial Handling ("What if an actor behaves maliciously?")

Attack Vector / Misbehavior Threat Impact Mitigation / Code Defense Residual Risk & Invariant
Corrupted or Truncated Report Bufferlist (Malicious or Buggy OSD) Memory corruption or manager daemon crash during bufferlist unpacking. desc_it->unpack_counter(bl_it, &c) uses Ceph buffer::list::iterator bounds checks. Base template checks descriptor vector boundaries (desc_it != end) and validates exact descriptor equality before decoding. Corrupted bufferlists throw buffer::error exceptions, terminating daemon report parsing if uncaught at the outer network layer.
Key Cardinality Explosion / DoS (Attacker spawning millions of unique client keys) Unbounded growth of counters[query_id][key], leading to Mgr OOM. Queries support OSDPerfMetricLimit (e.g. top-N keys by IOPS/bandwidth). OSDs enforce limits locally prior to transmission, pruning low-volume keys before sending upstream. If an unlimited query is registered by an authorized admin/module, rogue clients creating random entity IDs can inflate map memory until the next consumer drain.
Mismatched Subsystem Payload Injection (DaemonServer routes MDS report to OSD collector) Undefined behavior or memory corruption. std::get<OSDMetricPayload>(payload) throws std::bad_variant_access immediately, aborting the invalid operation before locks are acquired or state corrupted. UG-3: Uncaught exception will crash ceph-mgr if DaemonServer fails to isolate message types. Requires strict routing in DaemonServer.
Rapid Query Churn / Flooding (Spamming add_query / remove_query) Lock contention on lock and notification broadcast storms to cluster OSDs. Base class is_limited() short-circuits redundant notifications: listener.handle_query_updated() is triggered only when the canonical query set or limit presence actually changes. High-frequency additions with unique keys will trigger OSD config broadcasts via MMgrConfigure.

5. Failure Modes, Edge Cases & Blast Radius ("Where does this fail?")

Ungrounded Contracts Identified (Historical Audit):
  • UG-3 (Payload Type Guard): std::get<OSDMetricPayload> is unguarded against invalid variant alternatives. Safe only because DaemonServer routes messages based on daemon type.
  • UG-4 (Unchecked static_cast): get_counters() performs an unchecked static_cast<OSDPerfCollector*>(collector). Passing a null or foreign PerfCollector subtype results in instant segfault.
  • UG-6 (Silent Metric Loss on Missed Poll): The drain-and-reset pattern destroys accumulated deltas upon get_counters(). If a scraping consumer drops the returned map or fails to persist it, the aggregated cluster delta for that window is permanently lost.
Failure Scenario Root Cause & System Behavior Blast Radius & Containment
Stale / Offline OSD Daemons OSDs fail to send MMgrReport due to network partitioning or crashes. Contained: OSDPerfMetricCollector simply accumulates whatever reports arrive. Returned counters for that period reflect partial cluster totals without failing the query.
Consumer Missing Polling Cycles Mgr module sleeps or hangs longer than the scrape interval. Silent Metric Coarsening: Counters continue to accumulate in memory (+=). When consumer finally polls, it receives a single large burst delta spanning multiple report intervals. No data is lost unless the daemon restarts.
Unregistered Query Counter Access Consumer requests counters for a query_id that was removed or never registered. Graceful Failure: get_counters_generic returns -ENOENT. Internal state remains completely unmodified; output container is untouched (UG-5).
Descriptor Schema Mismatch during Rolling Upgrade OSD runs newer/older version with different counter descriptors. Safe Drop: process_reports_generic compares descriptors with operator!=. Non-matching descriptors are skipped via continue, preventing deserialization errors.

Whiteboard Summary (30-Second Elevator Pitch):

"OSDPerfMetricCollector is the specialized OSD metrics aggregator in ceph-mgr. It subclasses the generalized MetricCollector template, configuring it with OSD-specific keys and reports. Its defining architectural trait is additive delta accumulation (+=) across all OSD reports under a single mutex, coupled with a drain-and-reset retrieval model that transfers data to Python modules/Prometheus via move semantics. It ensures lockless listener notification, strict descriptor equality validation across cluster versions, and localized memory management."
