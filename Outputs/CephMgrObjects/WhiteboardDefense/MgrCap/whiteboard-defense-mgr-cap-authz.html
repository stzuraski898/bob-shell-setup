1 · High-Level Architecture & Mental Model

What it is

MgrCap is the standalone authorization engine for Ceph's Manager daemon. It was carved out of MonCap in 6350bee because the MGR's five distinct grant types — blanket, service, module, profile, command — are semantically different from MON grants and warranted a dedicated parser + evaluator.

Request Lifecycle

Caller ──parse_cap_string──► MgrCap::parse()
│ ├──[Boost.Spirit Qi grammar]──► grants[] (MgrCapGrant) │ ├── parse_network() per grant │ └── expand_profile() per profile grant ◄──validates at parse time (9193d87) │ └──[encode/decode]──► text only (v4/compat4); decode re-parses text
AuthZ check ──is_capable(service,module,command,args,op_r/w/x,addr)──► │ ├─ for each grant: │ ├── network check (skip grant if addr outside range / invalid CIDR) │ ├── is_allow_all? ──► return true (fast-path) │ └── get_allowed() OR bits → check if all needed bits satisfied → return true └── all grants exhausted → return false

2 · Architectural Decisions & Trade-offs

Decision Why X (chosen) Why not Y (alternative)
Split MgrCap from MonCap MGR has module grants + profile grants with their own semantics. Reusing MonCap added accidental complexity and mismatched semantics. (6350bee) Keeping MonCap would have required adding MGR-specific branches everywhere inside a MON-centric type, violating single-responsibility.
Text-only serialisation (encode/decode) Only text is encoded (v4/compat4); grants are reconstructed by re-parsing on decode. Format is the cap string itself — simple, human-readable, unambiguous. (6350bee) Encoding the struct directly would require a versioned schema per field and would break when new grant types are added.
Profile validation at parse time Unknown profile = parse() returns false immediately. Fail fast; invalid caps never enter the grants vector. (9193d87) Deferring to auth time would silently grant nothing (confusing) or require error propagation through is_capable().
Profile expansion memoised (profile_grants) expand_profile() is called once; result cached in mutable profile_grants. Free after first authorisation check. (6350bee) Re-expanding on every get_allowed() call would be safe but wastes allocations for long-lived cap objects.
Boost.Spirit Qi grammar Type-safe parser that maps directly to BOOST_FUSION_ADAPT_STRUCT fields. Error position is recoverable. Used consistently with MonCap. (6350bee) Hand-written recursive descent would be simpler to understand but harder to keep in sync with the struct layout when fields are added.
Command grants return MGR_CAP_ANY Command access is all-or-nothing by design. The grammar injects qi::attr(0) for the allow field; returning MGR_CAP_ANY is the semantic choice. (6350bee) Returning allow (which is 0) would silently deny all command grants — a catastrophic bug.
Invalid network → silent skip, not deny-all Only the affected grant is skipped; other grants still apply. Fail-safe: bad CIDR cannot escalate access. (6350bee) Denying the entire cap on one invalid network CIDR would be too aggressive; the intent is to restrict that grant, not revoke all caps.
Module arg bypass when command is given When c ≠ "", module argument constraints are skipped — command-level checking handles the arguments independently. (cb534e0) Enforcing module constraints even during command checks would double-count constraints and could incorrectly deny a command the module explicitly permits. UNGROUNDED — design intent underdocumented
Partial parse = failure (full-input consumption required) r && iter == end — the grammar must consume the entire string. Trailing garbage is caught. (6350bee) Accepting a partial parse would silently ignore trailing grant clauses, resulting in over-permissive or under-permissive caps.
Grants OR-ed across the list A principal may hold multiple grants from different services; ORing allows allow service mds r, allow service osd w to compose naturally. (6350bee) AND-ing would be too restrictive for composable multi-service caps.

Grammar (BNF summary)

mgrcap      := grant ((',' | ';') grant)*
grant       := rwxa_match | profile_match | service_match | module_match | command_match

rwxa_match  := 'allow' spaces rwxa [network_clause]
service_match := 'allow' 'service' ['='] str rwxa [network_clause]
module_match  := 'allow' 'module'  ['='] str ['with' kv_map] spaces rwxa [network_clause]
profile_match := ['allow'] 'profile' ['='] str [kv_map] [network_clause]
command_match := 'allow' 'command' ['='] str ['with' kv_map] [network_clause]

rwxa        := '*' | 'all' | [r][w][x]          # qi:: || (optional parallel)
kv_map      := kv_pair (spaces kv_pair)*
kv_pair     := str ('=' str | ' prefix ' str | ' regex ' str)
network_clause := 'network' network_str

str         := quoted_string | unquoted_word
unquoted_word := +[a-zA-Z0-9_./-]
quoted_string := '"' + chars + '"' | "'" + chars + "'"
Asymmetry: unquoted_word allows . and /, but maybe_quote_string() wraps strings containing those chars in double-quotes. Round-trip is still sound (both forms accepted by parser), but the grammar accepts more than it emits. Single-quote quoting in the grammar has no corresponding emission path. UNGROUNDED

4 · Threat Model & Adversarial Handling

Attack / Adversarial Input What happens Verdict & gaps
Malformed cap string (garbage, truncated, extra trailing text) parse() returns false; grants.clear() called → zero access. SAFE Fail-closed. Error message propagated if err != nullptr.
Unknown profile name e.g. profile evil expand_profile(&profile_err) sets error string; parse() returns false. SAFE at auth time. DIVERGED D2: grants vector not cleared on this code path — cap object left in partial state if caller ignores return value.
Profile with unrecognised key e.g. profile rbd evil_key=x Same as above: expand_profile writes error, returns without populating profile_grants. SAFE — grants nothing. DIVERGED D1: memoisation guard broken; get_allowed() will re-call expand_profile(nullptr) on every check. Silent no-op per call.
Malicious regex in constraint e.g. k regex "(a+)+" std::regex_match with std::regex::extended. std::regex_error caught → return false (deny). PARTIAL ReDoS possible — std::regex has no execution timeout. A crafted regex + matching input string can cause catastrophic backtracking.
Invalid network CIDR e.g. network 999.999.999.0/24 parse_network() returns false → network_valid=false. Grant silently skipped in is_capable(). SAFE Fail-closed: invalid network = no access from that grant.
Stored cap with obsolete profile decoded at runtime decode() calls parse(s, NULL); NULL silences all errors. Profile failure → empty grants. SAFE (deny direction). DIVERGED D4: error is silently swallowed, making silent access loss impossible to diagnose.
Crafted cap string that partially parses r && iter == end check — partial parse = failure. No partial grants. SAFE
Attacker injects semicolons to split grants Grammar accepts ; as grant separator. This is valid and intended. Multiple grants are OR-ed. SAFE Semicolons are not privileged; they behave identically to commas.
Module cap with arguments + specific command check c.empty() guard in get_allowed(): module argument constraints are skipped when a command string is provided. REVIEW A caller that provides both module name and command name bypasses the module's argument constraints. Intent is that command-level constraints take over. Underdocumented. UNGROUNDED U4
Programmatic grant construction (bypass parser) MgrCap(vector ctor) sets empty text. Grant with network="" and network_valid=true (default) is treated as unrestricted. GAP Programmatic caps have no text, so get_str() returns "". UNGROUNDED U8
Service grant with injected arguments (struct only, not from parser) Parser never produces arguments for service grants. If programmatically constructed with arguments, operator<< would emit " with ..." but service_match grammar does not accept a with block. LATENT Round-trip would break for such a cap, but the path is unreachable from the parser. UNGROUNDED U3

5 · Failure Modes, Edge Cases & Blast Radius

D1 — Memoisation broken for invalid profiles

DIVERGED 9193d87 vs get_allowed() line 238
What happens: If a profile expansion fails (invalid key), profile_grants stays empty. The memoisation guard if (!profile_grants.empty()) return never fires. get_allowed() re-invokes expand_profile(nullptr) on every auth check — no error logging, no grants.
Blast radius: CPU waste (re-runs expand on every auth for that grant). Security direction correct (zero grants). In practice blocked by parse-time validation, but reachable if cap is deserialized without validation.

D2 — grants not cleared on profile-error path

DIVERGED (highest severity) 6350bee invariant violated by 9193d87
What happens: parse() returns false on profile error but does not call grants.clear(). The grammar-parsed grants remain. Explicit comment at line 565: "Make sure no grants are kept after parsing failed!"
Blast radius: Caller that ignores parse() return value (e.g., calls is_capable() after a failed parse) would operate on stale grants. The grants themselves have empty profile_grants, so profile-typed grants grant nothing. Other grant types in the same cap string would evaluate normally. This is a latent correctness exposure, not a guaranteed exploit.

D3 — Parameter name inconsistency

DIVERGED cb534e0
is_capable() parameter still named command_args (line 312), not renamed to arguments. Pure naming inconsistency — no functional impact. Causes confusion when reading the function.

D4 — decode silences profile errors

DIVERGED 9193d87 vs decode() line 376
decode() calls parse(s, NULL). If a stored cap string contains an unrecognised profile (e.g., after a rollback), parse returns false but no error is emitted. The cap silently becomes zero-access.
Blast radius: Silent access loss after rolling back to a Ceph version before a new profile was introduced. Operator sees permission denied with no diagnostic.

Regex ReDoS

validate_arguments() compiles a fresh std::regex on every call and invokes std::regex_match. No regex caching, no execution timeout. A crafted cap with a pathological regex constraint (e.g., k regex "(a+)+") against a long matching value can cause catastrophic backtracking and spin the auth thread. Only reachable if an attacker can inject a cap string (requires write access to the auth database).
