1 · High-Level Architecture & Mental Model

What is it?

ActivePyModule is the active-side adapter between the Ceph Manager daemon and a single running Python plugin. It extends PyModuleRunner (added df879732) and owns:

  • The Python class instance (pClassInstance) — created by load(), destroyed by the runner
  • A per-module Finisher thread — command execution queue (added 46de6431)
  • A per-module health_check_map_t — last set of health checks published by the plugin
  • A per-module uri — optional service endpoint string
  • Transient command-dispatch state: m_session / m_command_perms — live only during handle_command()

2 · Architectural Decisions & Trade-offs

DecisionWhy this over the alternativeGrounding commit
Inherit PyModuleRunner instead of owning Python state directly Active and standby modules originally duplicated interpreter lifetime, GIL management, and serve()/shutdown(). Extracting to PyModuleRunner removed the duplication and made both paths identical for Python lifecycle management. df879732 — "cut down duplication between active+standby"
Pickle-serialized cross-interpreter dispatch instead of passing raw PyObject* The original code passed CPython objects directly between subinterpreters. A comment in the code acknowledged this relied on a shared GIL/allocator and explicitly noted a TODO for PEP 554. f69069e1 replaced it with pickle.loads/pickle.dumps to properly cross interpreter boundaries. f69069e1 — "serialize python objects sent between subinterpreters via remote"
Per-module Finisher thread instead of shared finisher A single shared finisher serialized command execution across all modules. A slow or blocked module command would starve all other modules. Per-module finisher gives each plugin its own bounded-15-char thread (m-fin-{module}), providing isolation and independently observable queues. 46de6431 — "Add one finisher thread per module" (Fixes tracker #51177)
Transient m_session/m_command_perms instead of passing session into is_authorized() Python cannot hold a C++ pointer across frames; capability check must be callable from Python without crossing the C/Python boundary again. Installing session state before the call and clearing it after creates a narrow, deterministic window accessible via is_authorized(). 282c31c3 — "python modules can now perform authorization tests"
Rename hook to _config_notify (private) instead of config_notify Configuration updates replaced explicit per-module logging CLI commands. Renaming to the underscore-prefixed form signals that this is an internal infrastructure hook, not a user-overridable public method. 25b99dde — "remove CLI commands to manage modules' logging"
set_health_checks returns bool (changed?) instead of void Health reports were only sent on periodic beacon. By detecting change at the setter, the manager can trigger an immediate monitor report, eliminating the beacon-delay window during which a fresh health failure would be invisible. 3068c429 — "report health check changes immediately"
Do not call Py_EndInterpreter() on shutdown If a module (e.g. CherryPy) leaves a background Python thread sleeping, Py_EndInterpreter() aborts with "not the last thread". The comment at df879732 explicitly documents this decision: rely on Py_Finalize() at process exit instead. df879732 — destructor comment block
NotImplementedError ≠ crash dump Optional-interface probing via dispatch_remote() produces NotImplementedError for methods a module simply hasn't implemented. Original behavior generated a crash dump and error-level log for every probe, pinning RECENT_MGR_MODULE_CRASH permanently. Now: fill err, set crash_dump=false, log at debug. 18c4e08c + 42c4dfb4 — Fixes tracker #79106
get_uri() returns std::string_view The URI is set once by the module during serve() and read frequently for status reporting. Returning a view avoids an allocation on every read. The caller must not outlive the ActivePyModule. 9d47b164 — "return std::string_view instead of std::string copy"

Triage Steps for Common Issues

Issue: mgr module appears loaded but commands return -EINVAL / "Module not instantiated"
1. Check ceph mgr module ls — is module in "on" list?
2. Search mgr log for "Failed to construct class in '<name>'" — Python import/constructor failure.
3. Look for crash dump under crash ls — crash generated by handle_pyerror(true, ...).
Issue: Health checks from module not visible / stale
1. Check alive perf counter — if 0, module has exited.
2. If is_dead() is true, get_health_checks() silently returns without merging.
3. Verify module is calling set_health_checks() — if map is unchanged, set_health_checks() returns false and no monitor report is triggered.
Issue: Inter-module remote() calls failing with crash dumps
1. Check if the exception is NotImplementedError — after 18c4e08c/42c4dfb4 this must NOT generate a crash dump.
2. If crash dumps are still generated on NotImplementedError, check mgr version is ≥ 18c4e08c.
3. For real exceptions, the traceback is in *err returned to the calling module.
Issue: Command handler runs slowly / queues backing up
1. ceph daemon mgr.<id> perf dump | jq '.mgr_module_<name>.cmd_avg_usec'
2. Thread name m-fin-<module> in stack traces is the per-module finisher — check if it's stuck.
3. Module's Python command handler is the bottleneck — no C++ fix available; must fix Python code.
Issue: Authorization check always returns false for a valid session
1. is_authorized() was called outside a handle_command() dispatch — m_session == nullptr → always false.
2. Verify the Python module is calling self.is_authorized() from within handle_command(), not from a background thread or serve().
