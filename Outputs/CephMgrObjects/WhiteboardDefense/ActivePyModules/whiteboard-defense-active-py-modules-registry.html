1 High-Level Architecture & Mental Model

ActivePyModules is the active runtime bridge inside ceph-mgr that connects Ceph C++ daemon infrastructure (monitors, daemons, OSD maps, perf counters, KV stores) to dynamic Python subinterpreters (e.g. dashboard, restful, orchestrator, progress).

+---------------------------------------------------------------------------------------------------------+ | DAEMON SUBSYSTEM | | [ ClusterState / DaemonStateIndex ] [ MonClient / Objecter ] [ DaemonServer ] | +------------------------------------+-----------------------+-------------------------------+------------+ | | | v v v +------------------------------------+-----------------------+-------------------------------+------------+ | ActivePyModules | | | | Mutex: `ceph::mutex lock` Config: `module_config.lock` Store: `store_cache` (KV) | | Cache: `MgrMapCache` Async Dispatch: `cmd_finisher` Read-Only: `PyFormatterRO` | | | | +---------------------------------------------------------------------------------------------------+ | | | Modules Map: std::map> modules | | | +---------------------------------------------------------------------------------------------------+ | +-----------------------------------+----------------------------------------------------+----------------+ | | Per-Module Finisher Task | Remote Dispatch (Pickle) | (Cluster/Log/Config Notify) (Inter-module call) | v v +-----------------------------------+------------+ +--------------------------------+------------+ | ActivePyModule ("dashboard") | | ActivePyModule ("orchestrator") | | GIL Release: `without_gil_t` | | Subinterpreter isolation | | Finisher: `modules[name]->finisher` | | Finisher: `modules[name]->finisher` | | Serve Thread: `pthread_t` + `ThreadMonitor` | | Serve Thread: `pthread_t` + `ThreadMonitor`| +------------------------------------------------+ +---------------------------------------------+

Core Responsibilities:

  • Cluster State Query Dispatch: Handles get_python() and cacheable_get_python() for maps, health checks, daemon metadata, and rocksdb stats.
  • Configuration & KV Bridge: Coordinates cluster ConfigMap, module-specific options, and store_cache persistence to monitors.
  • Per-Module Concurrency & Isolation: Manages lifecycle (start_one()), individual finisher queues, thread monitoring, and pickled inter-module calls (dispatch_remote()).
  • Notification Routing: Delivers cluster state updates, cluster logs, and config mutations to modules registered via should_notify filters.

2 Architectural Decisions & Trade-offs ("Why X instead of Y?")

Decision (X vs Y) Defensive Rationale (Why X) Trade-offs / Alternatives Rejected Key Commit
Per-Module Finishers
vs. Single Global Finisher		 Prevents one slow, blocked, or misbehaving Python module (e.g. hung HTTP handler in dashboard) from stalling notification dispatch across the entire cluster. Higher thread footprint (~1 thread per loaded module), but bounds the blast radius of any single module. 46de6431
Strict GIL-Release Locking Contract
vs. Direct C++ Lock Acquisition		 Enforces without_gil_t before taking any C++ mutex (lock, module_config.lock, DaemonState::lock). Python GC can relinquish and re-acquire GIL at any point; holding GIL while awaiting C++ locks guarantees AB-BA deadlocks. Requires explicit RAII wrappers and careful scoping; formatting must re-acquire GIL before generating Python dicts/lists. 0601b31a
9c652fb3
MgrMapCache (LFU) + PyFormatterRO
vs. TTLCache / Mutable Returns		 Provides memory-bounded LFU caching of expensive maps while returning frozen read-only proxies (PyFormatterRO). Avoids race conditions where a Python module mutates shared cached data. Python modules requesting mutable state must explicitly pass get_mutable=true to receive a deep copy. 403340bcf8
Pickled Argument Serialization
vs. Direct PyObject* Sharing		 Safely passes arguments across Python subinterpreters in dispatch_remote() without violating subinterpreter memory bounds or leaking reference counts. Serialization CPU overhead (pickle.dumps/loads), but guarantees process stability across interpreters. f69069e1
Filter-Gated Notifications
vs. Broadcast-to-All Dispatch		 Checks py_module_registry.should_notify() before enqueuing to per-module finishers. Eliminates needless context switches and GIL contention for disinterested modules. Modules must declare required notify hooks at registration time. ee4e3ecd
Startup Completion Deferred Beacon
vs. Immediate Active Beacon		 Holds the active beacon via recheck_modules_start context until pending_modules is empty. Prevents standby mgr takeovers and partial-service discovery while modules boot. Slightly increases startup latency; requires test hooks (cbd1726f) for verification. cbd1726f

3 Data Structures, Algorithms & Invariants

Field / Data Structure Type Invariants & Concurrency Guards
modules std::map<string, shared_ptr<ActivePyModule>> Contains fully-initialized, running modules. Protected by lock. Insertions during start_one() assert unique emplace (40c4b9ac). Lookups in dispatch_remote() assert existence.
pending_modules std::set<string, std::less<>> Tracks modules in the process of starting up. Inserted before queuing load lambda; erased upon completion under lock.
api_cache MgrMapCache<PyObject*> LFU-eviction cache for structured map queries. Invalidated on notify_all() and config_notify() before queuing finisher notifications. Hits return borrowed refs (no Py_INCREF).
store_cache std::map<string, string> Optimistic in-memory mirror of KV config-keys. Protected by lock. Updated locally before firing async set_cmd to mon, ensuring immediate read-your-writes consistency.
config_map mon::ConfigMap Derived from store_cache keys starting with "config/" (excluding "config/mgr/"). Populated only if have_local_config_map == true.
cmd_finisher Finisher Dedicated finisher thread for asynchronous monitor commands (set_store, set_device_wear_level, foreign config). Started at construction, stopped at destruction.
progress_events std::map<string, ProgressEvent> Tracks in-flight background operations (e.g. pg balancing, osd recovery). Guarded by lock.
Global Locking Invariant: Never hold the Python GIL while attempting to acquire lock, module_config.lock, or any DaemonState::lock. Use without_gil_t / without_gil() prior to C++ lock acquisition, then re-acquire GIL via no_gil.acquire_gil() or with_gil before touching any PyFormatter or returning PyObject*.

4 Threat Model & Adversarial Handling

Threat / Adversarial Scenario Impact & Blast Radius System Defense & Mitigation
Malicious / Crashing Python Module in dispatch_remote Target module throws unhandled exceptions or NotImplementedError when remote procedures are invoked. Pickled transport prevents corrupting caller memory. 42c4dfb4 suppresses noise for NotImplementedError, allowing graceful degradation without spamming error logs.
Non-Printable / Binary Characters in KV Store Keys Malformed UTF-8 string encoding could cause Python C API string construction to segfault the manager daemon. 7c68a00c replaces unchecked f.dump_string with PyUnicode_FromStringAndSize, detecting encoding failure, clearing error via PyErr_Clear(), and skipping bad keys safely.
Slow / Blocking Module Event Handlers A single module blocking inside its notify() hook could starve other modules of OSDMap/cluster updates. Isolated per-module Finisher threads (46de6431). A stalled module blocks only its own queue without slowing any other module.
Unauthorized / Mutation of Shared Cached Maps A Python module modifying an in-memory dictionary returned by get_python() could corrupt data for other modules. 403340bcf8 uses PyFormatterRO to generate immutable proxy objects for cached queries, preventing modification unless explicit mutable copy requested.
Leaked / Rogue Thread Execution Unruly Python module threads spawning or hanging without daemon supervision. ThreadMonitor integration (95a90f7d) tracks module threads by native TID; stopped cleanly during ActivePyModules::~ActivePyModules().

5 Failure Modes, Edge Cases & Blast Radius ("Where does this fail?")

Failure Scenario Severity & Category Mechanics & Root Cause Blast Radius
Deadlock in get_config DIVERGED Concurrency get_config acquires module_config.lock directly without releasing GIL (violates 0601b31a). When called directly from Python, lock is acquired with GIL held. Mgr hang if another thread holds module_config.lock while waiting on GIL.
Unchecked Return in get_foreign_config DIVERGED Logic Error When !have_local_config_map, mon command return code cmd.r != 0 is not checked. Error strings in cmd.outbl are parsed as typed values. Incorrect config values fed into module logic; silent misconfiguration.
Stale Declaration: update_cache_metrics DIVERGED Linker Hazard .h:272 retains declaration after 403340bcf8 excised the .cc implementation. Linker failure if invoked by external translation unit.
Use-After-Check Race in dispatch_remote UNGROUNDED Race / Abort modules.find(other_module) asserts existence (ceph_assert). If a module stops concurrently after module_exists() check, daemon aborts. Manager daemon crash (fatal assertion).
Silent Mon Write Failure in set_store UNGROUNDED Error Handling If set_cmd.r != 0, error is logged but not propagated back to Python caller. In-memory store_cache remains out of sync with mon KV store. State desynchronization between mgr cache and persistent monitor store.
Unchecked modules.at() in set_uri & get_module_finisher UNGROUNDED Exception modules.at(name) throws uncaught std::out_of_range if the target module was terminated. Unhandled C++ exception crashes the mgr process.
Double-Call Context Leak in check_all_modules_started UNGROUNDED Leak Does not verify recheck_modules_start == nullptr prior to assignment. Concurrent init calls leak previous context. Minor heap memory leak during initialization.

6 Observability & Triage Playbook

Primary CLI Commands for Triage:

  • ceph mgr module ls — List enabled, active, and available Python modules.
  • ceph mgr dump — Inspect active mgr metadata, services, and URI advertisements.
  • ceph mgr cli cache flush <map-name> — Invalidate a stale LFU cache entry (e.g. osd_map, mon_map) without daemon restart.
  • ceph tell mgr.<id> pending_modules — Check modules currently blocked in startup phase (68221661).
  • ceph health detail — Inspect aggregated module health checks emitted via set_health_checks().

Key Log Patterns (dout / derr):

Log Signature Subsystem / Level Diagnosis & Immediate Action
mgr get_python Unknown key [<what>] dout(0) / derr Module requested an unhandled state key. Check for version mismatch between Python module and Ceph mgr daemon.
Failed to run module in ActivePyModules::start_one dout(0) / derr Module failed to load or throw an exception during startup. Check Python dependency imports or syntax errors.
api_cache hit: [<what>] / miss: [<what>] dout(20) Cache hit/miss diagnostics. Low hit ratio indicates frequent map invalidation or cache thrashing.
send_report: DaemonServer::lock → PyModuleRegistry::lock Locking Audit Health check update deadlock. Ensure ActivePyModules::lock is released before server.schedule_tick(0).
