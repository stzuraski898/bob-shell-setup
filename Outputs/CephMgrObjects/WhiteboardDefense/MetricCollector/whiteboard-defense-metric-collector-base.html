1 · High-Level Architecture & Mental Model

What it is

MetricCollector<Query, Limit, Key, Report> is an abstract template base class in the Ceph Manager daemon. It centralizes the bookkeeping for all client performance-metric subscriptions and the aggregation of counter data coming back from daemons (OSDs, MDS). Concrete subclasses (OSDPerfMetricCollector, MDSPerfMetricCollector) only need to implement two pure-virtual hooks: process_reports() and get_counters().

Introduced in efcebe1e (2019-09-10, Venky Shankar) by extracting and generalizing the OSD-specific OSDPerfMetricCollector. Extended to MDS metrics in f6ba1eea the same day.

Key relationships

  • MetricListener& — callback interface; called outside the lock (lock-order safety). The only notification is handle_query_updated().
  • queries map — two-level: outer key is Query descriptor; inner map is QueryID → optional<Limit>. Multiple callers can register the same logical query with different limits.
  • counters map — flat: QueryID → Key → PerformanceCounters. Lifetime exactly matches queries inner entries.
  • ceph::mutex lock — named "mgr::metric::collector::lock"; guards both maps and next_query_id. Must be held by callers of process_reports_generic and get_counters_generic (enforced by ceph_assert).

2 · Architectural Decisions & Trade-offs

Decision Why this instead of… Trade-off / Risk Commit
Template class, not runtime polymorphism for Query/Report types Zero-cost abstraction at the boundary between query-type logic and shared bookkeeping. Avoids type erasure, virtual dispatch per counter, or std::any wrapping. Explicit template instantiations required in .cc — adding a new subsystem means updating that translation unit. efcebe1e
Two-level queries map: Query → map<QueryID, OptionalLimit> Multiple clients can subscribe to the same logical query with different limit budgets. A flat QueryID → Query map would require duplicate daemon-side subscriptions for each client. Reverse lookup from QueryID → Query is O(N) in remove_query (full linear scan of all query buckets). Acceptable because query counts are small (O(10s)). efcebe1e (origin: a6c33908)
Listener notified outside the lock Prevents deadlock if MetricListener::handle_query_updated() re-enters the same mutex (e.g., to call get_queries()). Lock is scoped to map mutation only. TOCTOU: state may change between lock release and listener invocation. Acceptable because listener re-reads state under its own locking. efcebe1e
get_counters_generic requires lock held by caller (ceph_assert) MDS collector needs to atomically call get_counters_generic for multiple query IDs within a single lock hold (tracker #36253). Inlining lock acquisition would serialize each call separately. Caller contract violation aborts the process (assert). Requires disciplined derived-class authors. 7523aef6
remove_all_queries() does NOT clear counters Historical behavior preserved from OSDPerfMetricCollector. Counters for removed query IDs are orphaned but harmless as they are never referenced once the query is gone. Minor memory leak if bulk-removal is called frequently with large counter maps. Not considered a realistic scenario. efcebe1e
reregister_queries() calls listener unconditionally, without holding lock Post-failover recovery: after rank-0 MDS failover, the daemon has no knowledge of prior subscriptions. Triggering handle_query_updated() causes the listener to re-push all currently registered queries, which it reads via get_queries() under its own lock. If called when no queries are registered, it fires a no-op notification. Benign. c2470f27 (tracker #50033)
get_queries() guards if (limit.second) before dereference Mixed registrations (some limited, some unlimited) for the same query descriptor. is_limited() returning true only means at least one sub-registration has a limit — others may have nullopt. Without the guard, a mixed registration caused a crash (tracker #52801). The guard was added as a targeted fix. 9a05872f (tracker #52801)
Counter dispatch via UpdateCallback function object Derived classes supply a lambda / function that decides how to accumulate a new counter into the running total (e.g., sum, avg, max). Keeps accumulation policy out of the base class. Slight overhead for std::function wrapping; negligible versus I/O. efcebe1e

Invariants (must hold at all times)

  1. Every QueryID in queries[q][qid] has a corresponding entry in counters[qid] (allocated in add_query, erased in remove_query). atomicity enforced by lock
  2. next_query_id is strictly monotonic; IDs are never reused. established: efcebe1e
  3. The lock is never held when listener.handle_query_updated() is called. lock-order safety
  4. process_reports_generic and get_counters_generic require the caller to hold lock (asserted at entry). caller contract
  5. get_counters_generic moves (not copies) data from counters[qid] and then clears the slot — ensuring data is delivered exactly once per poll cycle.

process_reports_generic — descriptor matching algorithm

for each [query, report] in reports:
  for each [key, packed_bl] in report.group_packed_performance_counters:
    bl_it = packed_bl.cbegin()

    // Phase 1 — resize counter vectors for all registered QueryIDs
    for each registered qid p in queries[query]:
      counters[p.first][key].resize(query.descriptors.size(), {0,0}) if empty

    // Phase 2 — walk report descriptors vs query descriptors
    desc_it = report.performance_counter_descriptors.begin()
    for i in [0 .. query.descriptors.size()):
      if desc_it == end → break          // report truncated
      if *desc_it != query.descriptors[i] → continue   // skip mismatched position
      c = desc_it.unpack_counter(bl_it)
      for each qid in queries[query]:
        callback(&counters[qid][key][i], c)
      desc_it++
Key property: Descriptor mismatch is silently skipped (continue), not an error. The counter slot at index i is simply not updated for that cycle. This tolerates version skew between mgr and daemon without crashing.

is_limited predicate

bool is_limited(const map<MetricQueryID, OptionalLimit> &limits) const {
    return std::any_of(begin(limits), end(limits),
                       [](auto &l) { return l.second.has_value(); });
}

Returns true if any registration for a query bucket has a defined limit. Used to decide whether removing or adding a registration changes the effective limit envelope and therefore requires a daemon notification.

4 · Threat Model & Adversarial Handling

Scenario What happens Verdict Evidence
Daemon sends a malformed / truncated packed bufferlist process_reports_generic walks descriptors; if desc_it reaches end() it breaks. Mismatch triggers continue. No bounds violation — unpack is bounded by the descriptor loop. Tolerated efcebe1e cc:168–173
Daemon sends reports for queries that were never registered queries[query] on an unknown key returns an empty inner map. The inner loop over queries[query] iterates zero times — report is silently dropped. Note: operator[] will default-insert an empty entry into queries. Silent map growth — benign but leaks an empty entry efcebe1e cc:158, 178
Client calls remove_query with a non-existent QueryID Returns -ENOENT. No map mutation, no listener notification. Safe efcebe1e cc:106–109
Client registers identical queries thousands of times (flooding) Each call allocates a new monotonic QueryID, grows both queries inner map and counters. Each call may trigger handle_query_updated() (if registrations are limited). No rate-limiting inside this class. Unbounded memory + notification spam — no guard here; caller is trusted efcebe1e
Mixed limited + unlimited registrations for same query is_limited() returns true. get_queries() only inserts limits where limit.second has a value (guard added in 9a05872f). Unlimited registrations produce an empty Limits set entry. Fixed (tracker #52801) 9a05872f h:19
MDS rank-0 failover — daemon loses all subscriptions reregister_queries() is called by the failover handler. Unconditionally fires handle_query_updated() which causes the listener to re-push all current queries from get_queries(). Handled (tracker #50033) c2470f27
Derived class calls get_counters_generic without holding lock ceph_assert(ceph_mutex_is_locked(lock)) fires → process abort. This is deliberate; the assert is the enforcement mechanism. Hard crash (by design) 7523aef6 cc:127
MetricListener reference becomes a dangling pointer No protection. Class stores a raw reference. Caller is responsible for lifetime management. All uses are within ceph-mgr where the listener is a long-lived singleton. UB on dangling ref — mitigated by architecture, not by code efcebe1e
next_query_id wraps around at UINT64_MAX Wrap would cause a collision with a still-active QueryID. In practice (one registration per ceph fs perf stats session), this is a non-issue over any realistic uptime. Theoretical only efcebe1e
