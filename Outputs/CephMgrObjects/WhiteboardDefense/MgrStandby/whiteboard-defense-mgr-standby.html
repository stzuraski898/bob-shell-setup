1. High-Level Architecture & Mental Model

What is MgrStandby?

  • Process harness for ceph-mgr. Every mgr daemon runs as MgrStandby first. One will be elected active; the rest stay in standby.
  • Owns all long-lived infrastructure: messenger, MonClient, Objecter, timer, ASIO pool, PyModuleRegistry, finisher, admin socket.
  • When elected active, allocates a Mgr instance on the heap and background-inits it. On demotion — respawns via execv().

2. Architectural Decisions & Trade-offs

DecisionWhy This, Not ThatCommit(s)Trade-off / Risk
Demotion → execv() respawn, not in-process teardown Unwinding the CPython interpreter is unreliable. Module threads, global state, and GIL interactions make in-place teardown non-deterministic. execv() gives a clean address space. 2fd49a1a Re-exec latency (~1s). No graceful drain of in-flight ops. Process state logged but not flushed on respawn path.
Respawn via /proc/self/exe, fallback to orig_argv[0] Binary upgrade: if the binary is replaced on disk, /proc/self/exe still resolves to the running binary's inode, not the new file. 2fd49a1a On non-Linux (FreeBSD, PROCPREFIX set), logged path vs. exec path can diverge. Not a bug on Linux.
Random nonce via Messenger::get_random_nonce(), not getpid() PID is reused across rapid restarts (e.g., cephadm rolling restart). Reused nonce → connection identity collision with monitors. e27f6c6a Nonce is now opaque; ps-based debugging loses easy correlation. Acceptable trade.
SIGTERM/SIGINT → _exit(0), not exit(0) exit() runs atexit handlers and Python finalizers — known broken/hang-prone. _exit(0) exits immediately. 6146c85b, b925be726, a3dad559 No subsystem cleanup on signal; file descriptors not flushed. Intentional — systemd will clean up the cgroup.
Standby SIGTERM registered as oneshot Prevents re-entrant signal delivery into _exit(). Avoids the signal-in-signal problem. a3dad559 After promotion to active, the oneshot has already fired (or not). Mgr::init() registers its own handlers — interaction undocumented.
Config-driven module list change → respawn (not hot-reload) Same rationale as demotion: Python interpreter teardown is unsafe. mgr_standby_modules change triggers respawn only if we are not currently active. efc29fb3 Brief standby downtime on config change. Guard: !active_mgr && value differs from have_standby_modules().
Command descriptions sent only on first "available" transition Avoids redundant large payloads on every beacon tick. Monitor confirms receipt by setting our gid as active in the mgrmap → available_in_map = true. 5c3846306 Until available_in_map flips, command descs are re-sent every tick (implicit retry). Benign but not commented as intentional retry.
Expiration override for module-load deadlock (exceeded_initialization_expiration()) If a Python module hangs at load time, PG availability reporting stalls indefinitely. After mgr_module_load_expiration ms, beacon declares available=true anyway, unblocking the cluster. bf25a08c WARN Creates state_str() vs. beacon availability mismatch — state_str returns "active (starting)" while beacon says available. bf25a08c updated send_beacon but not state_str. DIVERGED.
available_in_map initialised false Must guarantee command descriptions are sent at first availability declaration, not on every beacon. If initialised true, the transition beacon would skip command descs and the CLI would have no commands. 5c3846306 Zero: this is correct. The initial value is load-bearing.
Config callback registered before monc.init() The first config message from the monitor arrives during init(). If the callback is registered after, that initial config is missed. 3193d40d Callback fires on the MonClient thread; py_module_registry.handle_config() must be thread-safe.
set_passthrough_monmap() after auth Calling it before auth would cause ms_dispatch2 to try to acquire lock while authenticate() holds it — deadlock, since init() already holds lock. 430ba5e2 The ordering is invisible in the code; a future refactor that reorders these calls would reintroduce the deadlock.
Asok status returns {} Rook operator health check needed a 200-OK response from the admin socket to detect a live mgr process. Content was deferred ("TBD"). 4a7976a5 (tracker #70571) Cannot distinguish a fully-functional mgr from one that just started. No follow-up commit adds content.

3. Data Structures, Algorithms & Invariants

Core Members & Their Roles

MemberTypeRoleKey Invariant
lock ceph::mutex Global reentrance guard for all state mutations Must be held by send_beacon (assert at cc:300), tick, handle_mgr_map, ms_dispatch2. NOT held by handle_conf_change (inconsistency — see §5).
active_mgr std::unique_ptr<Mgr> Non-null iff this daemon is active Allocation under lock in handle_mgr_map. In ms_dispatch2, copied to a local shared_ptr before dropping lock to prevent use-after-free (890f48256).
available_in_map bool Whether monitor has acknowledged our availability Init: false (5c3846306). Set true in handle_mgr_map when map confirms our gid as active. Governs whether command descs are included in beacon.
timer SafeTimer Periodic tick → beacon loop SafeTimer holds lock when invoking callbacks — this is the contract that satisfies send_beacon's mutex assert. Period read dynamically from g_conf() on every tick (80ee71ab5).
py_module_registry PyModuleRegistry Manages Python module lifecycle (standby + active) Inited in MgrStandby::init() (810369b0). handle_mgr_map() called on every map; returns true if respawn needed.
orig_argc / orig_argv int / const char** Saved for respawn() Stored in constructor (2fd49a1a). respawn() copies argv into a new null-terminated array and passes to execv().
asok_hook std::unique_ptr<MgrHook> Admin socket proxy to asok_command() Unregistered before reset in destructor (4a7976a5) to prevent dispatch-into-freed-hook.
poolctx boost::asio::io_context ASIO thread pool for MonClient + Objecter Started with 2 threads (306eebe0). Must be started before objecter.init().

Beacon Algorithm

send_beacon() — what goes in the beacon
  • Always: gid, addrs, metadata (addr legacy + addrs), module list with {name, error_string, can_run, module_options}, RADOS client list (blocklist support), CEPH_FEATURES_ALL
  • available flag: active_mgr != nullptr && (is_initialized() || exceeded_initialization_expiration()) — bf25a08c
  • First availability only (!available_in_map): full command descriptions; pre-quincy compat strips positional=false — 218f4cef
  • If available: active_mgr->get_services() and get_server_addrs()
  • Trigger: periodic tick (mgr_tick_period seconds) + immediate call on background_init completion — e0e87da6

4. Threat Model & Adversarial Handling

Actor / ScenarioWhat They Can DoSystem ResponseResidual Risk
Malicious / stale mgrmap from monitor Flood fake mgrmap messages to force rapid respawn cycles ms_dispatch2 calls handle_mgr_map() under lock. Respawn calls execv() — process is replaced, flood cannot escalate within a single process. Monitor auth (CephX) required. Rapid execv() cycles = temporary service disruption. No crash, no data corruption.
Attacker sends malformed MSG_MGR_MAP Craft a message with bad module list, bad addrs, etc. MMgrMap decode follows protobuf/Ceph wire format; bad decode → message dropped at messenger layer before reaching handle_mgr_map(). CephX prevents unauthenticated injection. Low. Wire-format integrity protected by HMAC in CephX session.
Attacker with admin socket access Send heap command to profile/manipulate memory heap guarded by ceph_using_tcmalloc() — returns -EOPNOTSUPP if tcmalloc not loaded. Admin socket is a Unix domain socket; permissions controlled by OS. GAP asok_command holds no lock during ceph_heap_profiler_handle_command. Race with concurrent state mutation is theoretically possible but unexploited in corpus.
Python module hangs at load time Hang Mgr::init() indefinitely, blocking PG availability reporting After mgr_module_load_expiration ms, exceeded_initialization_expiration() returns true → beacon sends available=true + health error. Cluster unblocked. Module is still hung; health error surfaced. state_str() still returns "active (starting)" despite beacon saying available (DIVERGED — bf25a08c vs. cc:552).
Active mgr crashes mid-dispatch active_mgr is reset concurrently while ms_dispatch2 is dispatching Local shared_ptr copy of active_mgr in ms_dispatch2 keeps the object alive for the duration of the call. Reset of active_mgr under lock is safe. Correct. 890f48256 was specifically a use-after-free fix.
Binary replaced on disk during run Admin replaces ceph-mgr binary mid-session respawn() tries /proc/self/exe (resolves via open inode — old binary) first, then falls back to orig_argv[0] (new binary on PATH). On rolling upgrade, respawn may exec the new binary depending on filesystem inode state. Intentional upgrade path.
SIGTERM before initialization completes OS kills process during init() handle_standby_mgr_signal fires _exit(0). Registered as oneshot before lock is acquired. Registered handlers before lock; signal fires at any point during init. Subsystems may be partially initialized — _exit(0) bypasses destructors. Intentional.
Monitor authentication fails (missing keyring) Misconfiguration or keyring theft monc.init() and monc.authenticate() return values are checked (10bf5123). On failure, client_messenger->shutdown() is called and init() returns error. WARN On build_initial_monmap() failure path: asok hook, finisher, and timer are NOT cleaned up. Admin socket remains registered pointing to a partially-initialized object.
Config change to mgr_standby_modules while active Attempt to force active mgr to respawn and yield active role handle_conf_change: !active_mgr guard prevents respawn when active. Only standby daemons respawn on this config key change. Low. Active mgr is immune to this trigger.
respawn() fails (execv returns) /proc/self/exe and orig_argv[0] both fail ceph_abort() — process dies with a fatal log. No recovery path. mgr daemon absent until cephadm/systemd restarts it. Cluster continues with remaining mgr standbys.

Failure Blast Radius

FailureScopeRecovery
Active mgr crashes / respawns Mgr commands unavailable for election timeout + init time (~5–30s). Cluster data path (OSDs, RADOS) unaffected. Standby mgr elected, respawns, re-inits. cephadm detects and restarts on persistent failure.
Python module hangs at load PG availability health reporting delayed until mgr_module_load_expiration. HEALTH_WARN after expiration. Expiration override unblocks cluster. Admin must fix the module or disable it via mgr_standby_modules.
monc.authenticate() fails (bad keyring) This mgr instance exits. Other standbys unaffected. Fix keyring, cephadm restarts daemon.
respawn() fails (execv error) ceph_abort() — this mgr process terminates. cephadm/systemd restarts. Other standbys elect a new active.
Timer stops firing (bug in SafeTimer) Beacon stops → monitor marks mgr unavailable after beacon timeout → election. New standby takes over. No data loss.

Triage Decision Tree

Symptom: mgr unavailable / commands failing
│
├── Is `ceph mgr stat` showing no active mgr?
│   ├── YES → Check mgr daemon logs for "respawning" or "authenticate failed"
│   │         Check cephadm: `cephadm ls` and `journalctl -u ceph-mgr@X`
│   └── NO  → Commands failing but mgr listed as active
│             → Check if mgr is in "active (starting)" state
│             → Check if expiration fired (HEALTH_WARN in `ceph health detail`)
│
├── Rapid respawn loop?
│   ├── Check if mgr_standby_modules config key is oscillating
│   ├── Check if mgrmap is flip-flopping (mon election in progress?)
│   └── Check /proc/self/exe resolution and orig_argv[0] validity
│
├── Beacon not reaching monitor (tick loop dead)?
│   ├── Set log level 10 and check for tick() messages
│   ├── Verify SafeTimer is not deadlocked under `lock`
│   └── Check if `monc` is connected: `ceph daemon mgr.X mon_status`
│
└── Python modules not loading?
    ├── Check `ceph mgr module ls` for error_string in module list
    ├── Wait for or reduce mgr_module_load_expiration
    └── Disable problem module: `ceph config set mgr mgr_standby_modules false`

Critical Config Knobs

KeyEffectDefault Guidance
mgr_tick_period Beacon interval (read dynamically per tick — 80ee71ab5) Too large: monitor declares mgr unavailable. Too small: beacon storm.
mgr_module_load_expiration Timeout before expiration-availability override fires (bf25a08c) Tune for slow Python import environments. Too short triggers false-available state.
mgr_standby_modules Enables Python modules on standby daemons. Change triggers respawn (efc29fb3). Set false to disable standby Python load (reduces RAM/startup on standbys).
